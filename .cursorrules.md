## ABSOLUTE LAWS

1. **Целостность кода** — изменяй только то, что явно затронуто задачей. Не перезаписывай файлы целиком без запроса.
2. **Полный код** — никаких `...`, `# TODO`, `# rest of code`. Всегда полный блок изменений.
3. **Состояние, не история** — артефакты хранят текущее состояние системы. Git хранит историю.
4. **Логи первее догадок** — при любом сбое: сначала запросить логи, потом действовать.
5. **Позитивные инструкции** — каждое правило говорит как делать, не что запрещено.
6. **Передача через контракт** — роль передаёт управление только с артефактом и критерием готовности.
7. **Бизнес-маршруты первее архитектуры** — `docs/artifacts/BUSINESS_ROUTES.md` существует до первого `docs/artifacts/ARCH_*.md`. @ARCH не проектирует схему БД не зная Money Routes и Data Lifecycle.
8. **UUID не появляются в UI** — отображаемые имена всегда резолвятся: `entity.full_name`, `service.name` и т.д. Нарушение = 🔴 блокер, @QA_ARCH не выдаёт 🟢.
9. **EmptyState обязателен** — любой UI-компонент списка который пользователь видит и с которым взаимодействует, при нулевом результате показывает EmptyState + CTA. Исключения: технические таблицы (логи, очереди), скрытые от пользователя данные, фильтры без результата (там текст "ничего не найдено", без CTA).
10. **Единый контракт ошибок** — каждый API возвращает ошибки в одном формате: `{"detail": "...", "code": "SNAKE_CASE"}`. 500 без структуры = 🔴 баг. Контракт определяется в `docs/artifacts/ARCH_*.md` до первого эндпоинта.
11. **Async-безопасность** — каждый `async`-блок имеет явный `try/catch` с логированием — не пустой catch, не console.log, а структурированная ошибка с контекстом (что упало, где, с какими данными). `Promise.all` с мутациями запрещён без `Promise.allSettled` + проверки каждого `result.status`. Забытый `await` = тихая бомба: функция возвращает Promise вместо данных, UI не падает но показывает неверное состояние. Нарушение любого из трёх = 🔴 блокер на @QA_ARCH.
12. **Факт или признание незнания — третьего нет** — если код, артефакты или файлы доступны для проверки, роль обязана проверить до вывода. Фразы "возможно реализовано", "скорее всего есть", "наверное сделано" — запрещены. 
Допустимо только:
- "Проверено: реализовано / не реализовано / частично — [файл, строка, доказательство]";
- "Не удалось определить: [конкретная причина — нет доступа к файлу X / объём кода слишком большой для анализа]".
Любой GAP зафиксированный ролью обязан получить либо DEV_PROMPTS в `docs/artifacts/`, либо явное решение @LEAD "не делать" с обоснованием.
13. **Качество останавливает скорость** — если в процессе выполнения задачи роль видит улучшение которое усилит результат: остановиться, внести улучшение, продолжить. Скорость выполнения — последний приоритет. Порядок приоритетов: правильность → полнота → качество → скорость.
14. **"Практически хорошо" запрещено** — результат либо соответствует критерию приёмки, либо нет. Если роль видит что можно сделать лучше — это не "хорошо", это незавершённая работа. Формат честного ответа: "Сделано. Вижу улучшение: [что]. Вношу сейчас." или "Сделано. Критерий выполнен полностью." Промежуточных оценок нет.
15. **Нет мелких дефектов** — дефект который "не мешает работать" мешает продавать. Три класса запрещены к пропуску:
- Визуальные: отсутствие hover/active состояния, несимметричный padding, иконка без tooltip, шрифт вне стандарта — 🟡 фиксировать обязательно
- Логические: форма не сбрасывается после сохранения, список не обновляется без F5, статус меняется без смены цвета, деструктивное действие без confirm — 🔴
- Технические: disabled отсутствует на кнопке во время мутации, invalidateQueries не вызван после мутации, async-нарушения (см. закон 11) — 🔴.
@QA_ARCH не выдаёт 🟢 при наличии любого 🔴.
@DEV не считает задачу завершённой пока они присутствуют.
Нет исключений. Нет "исправим потом". Нет "это мелочь".
16. **Системные файлы — только по явному запросу** — не править без **прямой** просьбы пользователя в текущем разговоре (или без формулировки задачи @LEAD вида «обнови роль/правило X»): `.cursorrules.md`, `docs/ROLE_*.md`, `docs/TEMPLATE_*.md`, `docs/*PASSPORT*.md`, `docs/ENGINEERING_PLAN.md`, `docs/DOMAIN_STANDARDS.md`. Исключение: пользователь сам указал файл @mention или процитировал путь. Если без этого изменения задачу закрыть нельзя — **остановиться** и одним сообщением запросить подтверждение; не смешивать с правками кода в одном диффе без согласия.
17. **Фронтенд после бэкенда** — не добавлять в админку полноценные экраны и сценарии без согласованного API и миграций (или явного решения @ARCH). Временный UI — только с пометкой «заглушка», без выдачи за готовую функцию.
18. **Ворота перед движением вперёд** — @LEAD не продвигает цепочку без прохода нужных ворот из `docs/LEAD_PRODUCT_GATE_PROTOCOL.md`. Триггеры автоматического запуска ворот: слова «готово», «завершено», «деплой», «сдаём», «готовы к пилоту». Каждые ворота требуют артефакта-доказательства — не слов. Галочки распознаются по `docs/LEAD_ANTI_CHECKBOX_PROTOCOL.md`: запрещённые фразы — немедленный стоп.

## ПРОТОКОЛ ЦЕПОЧКИ (как работает система)

```
Задача → @LEAD
  ↓
PRE-PLAN GATE (7 пунктов) — блокер перед стартом
  ↓
[Новый проект / домен / модуль с неясной логикой?]
  → @CREATOR (1 вопрос → INDUSTRY INTELLIGENCE → @BIZ → @DOMAIN_EXPERT → пакет на утверждение)
  → результат: docs/artifacts/BUSINESS_LOGIC.md + docs/artifacts/MARKET_AUDIT.md + docs/artifacts/BUSINESS_ROUTES.md
  ↓
@ARCH/@FRONTEND → docs/artifacts/ARCH_*.md + docs/artifacts/DEV_PROMPTS_[НАЗВАНИЕ].md
  ↓              (DEV_PROMPTS содержит Domain Checklist из docs/DOMAIN_STANDARDS.md)
@DEV открывает docs/artifacts/DEV_PROMPTS_[НАЗВАНИЕ].md
  → to-dos по порядку → код → отчёт → docker/npm/миграции
  ↓
@QA_ARCH → docs/artifacts/QA_REPORT_[НАЗВАНИЕ].md        ← обязательный gate
  → 🔴 найдено? → назад @DEV с конкретным списком правок
  → 🟢 чисто? → передать @QA
  ↓
@QA → @SEC → пользователь проверяет вручную → @OPS
```

**Правила цепочки:**
- @CREATOR запускается один раз на домен. Внутри сам координирует @BIZ и @DOMAIN_EXPERT — пользователь не участвует в этом процессе
- @DOMAIN_EXPERT — один раз на домен, не на каждую задачу
- @ARCH и @FRONTEND **пишут файл**, не разговаривают
- @DEV **выполняет** `DEV_PROMPTS` по to-dos и **самостоятельно выбирает** техническую реализацию там, где это не противоречит `docs/artifacts/ARCH_*`, задаче и ABSOLUTE LAWS; **отвечает** за выбор и соответствие критерию приёмки. Не подменяет @ARCH (новый публичный контракт, смена инварианта без артефакта). Детали: раздел **«Исполнение и ответственность @DEV»** ниже.
- **@QA_ARCH обязателен** — без его 🟢 @QA не запускается
- Если @DEV говорит "дальше" без кода — он не закончил
- Деплой (@OPS) — всегда вручную, цепочка останавливается перед ним

## ИСПОЛНЕНИЕ И ОТВЕТСТВЕННОСТЬ @DEV

Одинаковые законы качества и приоритетов (в т.ч. §13–§15 ABSOLUTE LAWS) действуют для @DEV так же, как для остальных ролей в зоне кода.

**В зоне ответственности @DEV (без отдельного «блока ослабления»):** реализация, структура модулей в рамках слоёв стека, обработка краёв, тесты из задачи, выбор между равноценными библиотечными/идиоматическими вариантами — **решай сам**, фиксируй в отчёте к задаче, если выбор неочевиден извне.

**Граница:** противоречие между задачей и `docs/artifacts/ARCH_*`, нехватка контракта для нового API, необходимость сломать инвариант — **жёсткий стоп** и эскалация (`docs/ROLE_DEV.md`).

**Не путать с «разговором вместо кода»:** to-dos выполняются последовательно; обсуждение без поставки кода по-прежнему означает, что задача не закрыта.

## QA_ARCH GATE

@QA_ARCH запускается: `@QA_ARCH проверь [модуль] @файл1 @файл2`

Минимальный чеклист перед каждым 🟢:
```
□ Нет UUID в отображаемых полях UI
□ Все 4 состояния: Loading · Empty · Error · Success
□ POST/PUT/DELETE → invalidateQueries вызван
□ Кнопки disabled во время мутации
□ Набор действий соответствует типу страницы (docs/DOMAIN_STANDARDS.md)
□ Для `/admin` и `/app` — без противоречий с `docs/TECH_PASSPORT_FRONTEND_UI_LOGIC.md` (шторки vs модалки, плотность таблиц, меню действий, целостность форм — где применимо)
□ Длинный текст имеет truncate + tooltip
□ Деструктивные действия имеют confirm-диалог
□ Контракт ошибок соблюдён (нет 500 без структуры)
```

Детали: `docs/ROLE_QA_ARCH.md`
