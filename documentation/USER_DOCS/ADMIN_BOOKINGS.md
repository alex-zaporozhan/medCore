# Записи (список записей)

> **Аудитория:** сотрудник клиники.  
> **Источник UI:** `frontend/src/admin/pages/AdminBookingsPage.tsx`.

## Адрес

`/admin/bookings`

## Назначение

Управление записями на приём: фильтры по врачу, дате, статусу, телефону пациента; таблица записей; действия по записи (отмена, завершение, оплата, отправка ссылки на форму — по возможностям экрана).

- **API:** комментарий администратора — `PATCH /api/v1/admin/bookings/{id}` (только `notes`). Смена статуса — `PUT /api/v1/admin/bookings/{id}/status` с телом `{ "status": "<значение>" }` (не через PATCH), чтобы побочные эффекты шли через узкие сервисные пути.

- Заголовок: **«Записи»**; в breadcrumbs при выбранной клинике отображается её название.
- Кнопка **«Новая запись»** ведёт в раздел расписания (`ROUTE_PATHS.admin.schedule`).

## Статусы в фильтре

Набор статусов совпадает с константами `BOOKING_STATUS_LABEL_RU` и значениями бэкенда (например: зарегистрирована, подтверждена, в работе, завершена, отмена и др.).
