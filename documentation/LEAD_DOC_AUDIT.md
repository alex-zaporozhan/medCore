# Аудит документации (@LEAD) — честные границы «канона из кода»

> **Дата:** 2026-04-02  
> **Контекст:** запрос на документацию «на 1000%» только из кода. Каталога **`/documents`** в репозитории **нет**; публичный канон — **`documentation/`** (см. `DOCUMENTATION_POLICY.md`).

## Вердикт по работе @SCRIBE

- **Сильные стороны:** выровнены политика и код (без ссылок на закрытый `/docs`), расширен **PRODUCT_KNOWLEDGE_BASE** §5–6, появились **USER_DOCS** и техстраницы (E2E, observability, UI theme). Это **не пустой** объём.
- **Слабая сторона:** **USER_DOCS** в основном каркас (URL + заголовок + отсылка к файлу), без сценариев ошибок и без покрытия всех сегментов админки — ощущение «галочки» **справедливо для end-user слоя**, но не для всего пакета.

## Что невозможно сделать «абсолютно полным» без изменения определения готово

Полная точность **только текстом в markdown** для всего продукта = дублирование OpenAPI + всех экранов + всех веток RBAC. Это:

1. **Раздувает** канон и расходится с кодом при первом же PR.  
2. **Дублирует** машинно генерируемые артефакты (`/docs` Swagger, тесты).

**Рабочая модель канона:**  
- **Инварианты и карты** (маршруты фронта, список роутеров, политика) — в `documentation/*.md` и держать в синхроне с CI.  
- **Каждый HTTP-путь** — источник OpenAPI или grep по репозиторию, не ручной перечень в KB (кроме обзорных таблиц).

## Что сделано в ответ на аудит (инкремент)

1. **`documentation/API_V1_ROUTER_MANIFEST.md`** — порядок и префиксы всех 78 подключений из `router.py` (проверяемый слой для интеграторов).  
2. **`documentation/USER_DOCS/ADMIN_DASHBOARD.md`** — переписан по фактическому `AdminDashboardPage.tsx` (метрики + staff feed + права), а не одной фразой «лента».  
3. **`PRODUCT_KNOWLEDGE_BASE.md`** — уточнение строки дашборда и ссылка на манифест API.
