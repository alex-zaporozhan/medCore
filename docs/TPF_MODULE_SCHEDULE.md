# TPF_MODULE_SCHEDULE — Расписание (Smart Calendar)

> **Префикс TPF_** — Tech Passport Frontend. Модульный техпаспорт.  
> **Связь:** `TPF_MASTER.md` (разд. 4.2), `REV_RAG_MAP_INNOVATIONS.md` (раздел 10).

---

## 1. Назначение

Сетка расписания с возможностью перетаскивания записей между врачами и слотами; при создании записи — подсветка «идеальных» окон (Ghost Slots); лист ожидания в боковой панели с перетаскиванием в слот.

---

## 2. Структура экрана

### 2.1. Основная сетка

- Ось X: врачи (или кабинеты). Ось Y: время (день/неделя по настройке).
- Ячейки — слоты. Запись отображается карточкой с пациентом, услугой, временем.
- **Drag-and-Drop:** перетаскивание карточки на другой слот или другого врача. Мгновенное обновление UI (Optimistic UI), затем `PUT/PATCH` брони (doctor_id, slot). При ошибке — откат и уведомление.

### 2.2. Создание записи

- Кнопка «Новая запись» или клик по пустому слоту открывает Drawer (или модал в рамках правил — лучше Drawer) с формой: пациент (с быстрым созданием нового), врач, услуга, дата, время.
- **Ghost Slots (опционально):** при выборе даты/врача система бледно-зелёным подсвечивает «идеальные» окна (чтобы не создавать дыры по 15 минут). Алгоритм может быть на бэкенде (`GET schedule/suggest-slots`) или на фронте по данным занятости.

### 2.3. Боковая панель — Лист ожидания (Waitlist)

- Список пациентов в листе ожидания (имя, телефон, желаемая услуга/время).
- Действие: перетащить карточку пациента из панели в пустой слот в сетке → создаётся запись и при необходимости запись в листе помечается как «занято» или удаляется. API: создание booking с привязкой к waitlist_entry.

### 2.4. Клик по записи

- Открывает Drawer карточки записи по TPF_MASTER (вкладки: Детали, Услуги и чек, Расходники, Задачи).

---

## 3. Эндпойнты

| Данные | Метод/путь | Примечание |
|--------|------------|------------|
| Сетка расписания | `GET /api/v1/admin/clinics/{id}/schedule` (date, period) | Врачи, слоты, брони. |
| Обновление слота/врача | `PUT /api/v1/admin/bookings/{id}` или reschedule | Поля: doctor_id, appointment_date, appointment_time. |
| Создание записи | `POST /api/v1/admin/bookings` | С patient_id или быстрый создание пациента. |
| Подсказка слотов | `GET /api/v1/admin/schedule/suggest-slots` (опционально) | Параметры: clinic, doctor, date; возврат «идеальных» окон. |
| Лист ожидания | `GET /api/v1/admin/waitlist`, `POST .../bookings` (from waitlist) | Список + создание брони из записи листа. |

---

## 4. Правила UI

- Загрузка: Skeleton по форме сетки (строки времени, колонки врачей).
- EmptyState при пустом дне: «Нет записей на эту дату» с кнопкой «Новая запись» или «Добавить из листа ожидания».
- Drag использует @dnd-kit или аналог; визуальная обратная связь при перетаскивании.
- Escape закрывает Drawer записи/создания.
