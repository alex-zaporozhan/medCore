# Защита от копирования и передача третьим лицам

> Что делать до передачи пакета клиенту. Для каждого проекта после деплоя.

---

## 1. Честный ответ: технической защиты в пакете нет

Если вы отдаёте клиенту папку (например `booking_deploy`) с кодом, Docker-образами и инструкцией — **технически** он может скопировать её и передать другому лицу. Приложение не «звонит домой» и не проверяет лицензию. Это нормально для модели «разовая поставка + свой сервер клиента».

**Вывод:** основная защита — **договор и формулировки лицензии**, а не код внутри папки.

---

## 2. Что сделать до передачи

### 2.1 Договор или оферта

Перед передачей архива/доступа к папке клиент должен принять условия. Минимум:

- **Право использования** — только для одного инстанса (одна организация / один бот / один сайт, как оговорено).
- **Запрет передачи** — клиент не вправе передавать, копировать или перепродавать папку, архив или доступ третьим лицам.
- **Ответственность** — при нарушении (передача «другу») вы вправе считать договор нарушенным и требовать компенсацию по договору.

Формулировки лучше закрепить в **договоре оказания услуг** или **лицензионном соглашении** (оферта + акт приёма-передачи). Юридическую форму (ИП/ООО, оферта на сайте) согласуйте с юристом под вашу юрисдикцию.

### 2.2 Файл LICENSE в папке деплоя (опционально)

В корне папки, которую отдаёте клиенту, можно положить короткий файл **LICENSE.txt** (или **LICENSE**), например:

```
Лицензия на использование

Вам предоставлено право использовать данное программное обеспечение
только для одного инстанса (один бот / одна организация) в соответствии
с договором от [дата] № [номер].

Запрещается передача, копирование или распространение материалов
третьим лицам без письменного согласия правообладателя.

© [Год] [Ваше имя/компания]. Все права защищены.
```

Это не заменяет договор, но фиксирует вашу позицию и напоминает клиенту об ограничениях.

## 3. Опционально: техническая защита в будущем

Если продукт станет дороже или клиентов станет много, можно добавить **активацию по ключу**:

- При первом запуске приложение запрашивает у вашего сервера проверку ключа (домен/ID клиента + ключ).
- Ключ привязывается к домену или к одному инстансу (например, к ID при первом запуске).
- Без валидного ключа бот/админка не работают или работают в ограниченном режиме.

Такой механизм требует доработки кода и небольшого сервиса проверки ключей (ваш бэкенд). Для разовых поставок до ~₽30–50k часто достаточно договора + LICENSE в папке.

---

## 4. Чек-лист перед передачей клиенту

- [ ] Подписан договор или принята оферта (право использования, запрет передачи).
- [ ] В папке деплоя лежит LICENSE.txt (или аналог) с запретом передачи третьим лицам.
- [ ] В переписке/договоре явно указано: «материалы передаются в единственном экземпляре для использования только заказчиком».
