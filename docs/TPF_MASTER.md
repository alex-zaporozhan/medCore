# TPF_MASTER — Техпаспорт фронтенд-функциональности Business OS (мастер-документ)

> **Префикс TPF_** — Tech Passport Frontend: техпаспорта по функционалу и UI.  
> **Назначение:** Единый источник правил UI/UX для админ-панели Business OS. Каждая страница и каждый значимый эндпойнт учтены в рамках модулей. ИИ-разработчики обязаны сверяться с этим документом и с TPF_MODULE_*.

**Источники:** `TECH_PASSPORT_FRONTEND_UI_LOGIC.md`, `REV_RAG_MAP_INNOVATIONS.md`, `REV_CRITERIA_IMPLEMENTATION.md`, `BUSINESS_LOGIC_V2.md`, `ARCH_FRONTEND_BUSINESS_OS_UX.md`.

**Связь:** Детали по модулям — в `TPF_MODULE_DASHBOARD.md`, `TPF_MODULE_OMNICHAT.md`, `TPF_MODULE_CRM.md`, `TPF_MODULE_SCHEDULE.md`, `TPF_MODULE_TASKS.md`, `TPF_MODULE_FINANCE.md`, `TPF_MODULE_LOYALTY.md`, `TPF_MODULE_FORMS.md`, `TPF_MODULE_ENTITIES.md`, `TPF_MODULE_PWA.md`, `TPF_MODULE_SHELL.md`.

## Часть I. Универсальные законы (Universal Laws)

### 1.1. Целостность данных (Relational Integrity)

- **Задача (Task):** Форма создания обязательно содержит: `assignee_id` (Кому), `due_date` (Когда), опционально `linked_entity` (Пациент, Лид, Запись). Без этого задача не создаётся.
- **Финансовая транзакция:** Форма обязательно содержит: `cashbox_id`, `amount`, `type` (Приход/Расход), `category`. Иначе транзакция не создаётся.
- **Общее правило:** Никакая форма не создаёт «подвисших» сущностей без минимально необходимых связей. Валидация на фронте и на бэкенде.

### 1.2. Drawers вместо Modals

- **Modal** допускается только для быстрых подтверждений: «Вы уверены, что хотите удалить?», «Сохранить изменения?».
- **Создание и редактирование** любых сущностей (Услуга, Врач, Задача, Запись, Пациент, Лид, Касса, Шаблон формы) — только в `<Drawer position="right" size="lg">`. Это сохраняет контекст таблицы/календаря.
- Конкретные размеры: `size="md"` для простых форм, `size="lg"` для карточек с вкладками.

### 1.3. Плотность данных (Data Density)

- Таблицы: компактные (`Table` с `verticalSpacing="sm"`), без лишних отступов.
- В каждой строке таблицы справа — кнопка `ActionMenu` (три точки) с быстрыми действиями: Редактировать, Скопировать, Удалить + контекстные (Отправить ссылку, Перевести в отказ, Отправить форму и т.д.).

### 1.4. Состояния пустоты (Empty States)

- Если данных нет (`length === 0`), не показывать пустой белый экран. Всегда показывать компонент `<EmptyState>`: иконка (например size=64, stroke=1), заголовок, краткое описание пользы раздела, главная кнопка CTA (например «Создать первую задачу»).

### 1.5. Контекст без кликов (Zero-Click Context)

- Использовать `HoverCard` и `Tooltip` (Mantine). При наведении на имя пациента или врача в любом месте системы показывать мини-карточку: телефон, LTV, дата следующего визита (если API отдаёт эти данные).

### 1.6. Горячие клавиши (Keyboard First)

- `useHotkeys` (Mantine): `Cmd+K` / `Ctrl+K` — глобальный поиск (Spotlight); `Cmd+Enter` — отправить сообщение (в чате); `Escape` — закрыть открытую шторку или сбросить фокус.
- В чате: `Cmd+J` / `Ctrl+J` — фокус на поиске чатов.

### 1.7. Оптимистичные обновления (Optimistic UI)

- Везде, где есть мутации через React Query (drag в календаре, смена статуса лида, отметка задачи выполненной), использовать оптимистичные обновления: UI меняется мгновенно до ответа API; при ошибке — откат и уведомление.

### 1.8. Загрузка без спиннеров

- Запрещены полноэкранные `<Loader />`. Вместо них — `<Skeleton>`, повторяющий контур будущего контента (таблица, карточки, блок текста). Это создаёт иллюзию скорости и снижает когнитивную нагрузку.

## Часть II. Каркас приложения (App Shell)

*Детали: `TPF_MODULE_SHELL.md`.*

- **Архитектура:** Двудольная структура: контрастный Sidebar (навигация) + светлое Main (рабочая зона). Глобального Header нет.
- **Sidebar:** Тёмный фон (`dark.8`), текст/иконки светлые. Кнопка Collapse: ширина 260px ↔ 80px (только иконки). Группы: OPERATIONS (Дашборд, Расписание, Чат), BUSINESS (CRM, Финансы, Лояльность), SYSTEM (Настройки, Команда).
- **Рабочая зона:** Фон `gray.0`. Контент в `Paper` с тонкой рамкой и радиусом `xl`.
- **Context Bar:** В каждой странице вверху — заголовок страницы и главные кнопки действий (например «Новая запись», «Создать задачу»). Хлебные крошки при необходимости.
- **Spotlight (Cmd+K):** Глобальный поиск: переход по разделам, поиск пациентов и записей. Опционально: вкладка «Спросить AI» (AI Command Line) — текстовый запрос к AI-агенту.

## Часть III. Матрица обогащённых сущностей (Entity Tabs)

*Детали: `TPF_MODULE_ENTITIES.md`.*

Любая карточка сущности в Drawer строится на вкладках (`Tabs`). Три поля в одной форме — недопустимо для уровня Business OS.

### 3.1. Карточка пациента (Patient 360°)

- **Header:** Аватар, ФИО, телефон, email, теги (VIP, Склонен к отменам), LTV, баланс бонусов/кэшбэка.
- **Вкладки:** [Основное] (ДР, пол, категория, согласия, UTM); [Записи] (таблица визитов: дата, врач, услуга, статус, сумма, NPS); [Финансы] (платежи, возвраты, абонементы); [Абонементы] (купленные пакеты, Family Sharing — «+ Добавить члена семьи»); [Медкарта/Заметки] (протоколы, файлы); [Коммуникации] (история уведомлений, доступ к чату).

### 3.2. Карточка записи (Booking)

- **Вкладки:** [Детали] (пациент, врач, кабинет, время, статус); [Услуги и чек] (несколько услуг, скидка, бонусы, касса); [Расходники] (по техкарте + ручная корректировка); [Задачи] (задачи, привязанные к визиту).

### 3.3. Карточка сотрудника/врача (Employee/Doctor)

- **Вкладки:** [Профиль] (ФИО, специализация, контакты, цвет в календаре, роль); [Расписание] (график 2/2, чет/нечет, индивидуальные часы); [Зарплата] (ставка, % от услуг, % от кросс-сейла); [Услуги] (чекбоксы — какие услуги может оказывать).

### 3.4. Карточка услуги (Service)

- **Вкладки:** [Описание] (название, категория, цена, длительность, цвет); [Исполнители] (Many-to-Many с врачами); [Техкарта] (продукты и количество); [Онлайн-запись] (доступна ли, описание, обязательна ли предоплата).

## Часть IV. Модули (краткая сводка по страницам и эндпойнтам)

Каждый модуль раскрыт в отдельном TPF_MODULE_*. Здесь — только сводка и привязка к маршрутам/API.

### 4.1. Dashboard (Action Center)

**Страница:** `/admin` (или главная после входа).  
**Документ:** `TPF_MODULE_DASHBOARD.md`.

- Верхний ряд: 4 метрики (Записи сегодня, Выручка, Новые лиды, NPS/Отмены) с динамикой (% к вчера/неделе) и при необходимости Sparkline.
- Левая колонка (~60%): Attention Feed — просроченные задачи, непрочитанные чаты, отмены, алерты склада/AI; на каждой карточке — кнопки действий («Предложить листу ожидания», «Открыть чекаут» и т.д.).
- Правая колонка (~40%): таймлайн расписания на сегодня (карточки записей).

**Ключевые эндпойнты:** агрегаты для метрик, `GET attention-feed` (или аналог), `GET schedule` на сегодня.

### 4.2. Расписание (Smart Calendar)

**Страница:** `/admin/schedule`.  
**Документ:** `TPF_MODULE_SCHEDULE.md`.

- Сетка по врачам и дням. Drag-and-Drop записей между слотами/врачами (оптимистичное обновление).
- При создании записи: опционально «Ghost Slots» (AI-подсветка идеальных окон).
- Боковая панель: лист ожидания; перетаскивание из листа в слот создаёт запись.

**Ключевые эндпойнты:** `GET admin/clinics/{id}/schedule`, `PUT/POST admin/bookings`, waitlist list + create booking from waitlist.

### 4.3. OmniChat (Smart Hub)

**Страница:** `/admin/chat` (или аналог).  
**Документ:** `TPF_MODULE_OMNICHAT.md`.

- Три колонки: список чатов (Smart Inbox с бейджами и фильтрами), окно переписки (AI Suggestions над полем ввода, Rich Bubbles для платежей, Action Bar: Запись, Счёт, Анкета, AI вкл/выкл), справа — контекст клиента (профиль, этап воронки, след. визит, внутренние заметки). Кнопка «Создать запись» открывает Drawer с предзаполненным телефоном.

**Ключевые эндпойнты:** чаты, сообщения, suggest-replies (AI), платежи (статус), пациент, lead stage, next booking.

### 4.4. CRM & Sales (Kanban)

**Страница:** `/admin/crm`.  
**Документ:** `TPF_MODULE_CRM.md`.

- Горизонтальный скролл со столбцами (LeadStage). Карточки лидов: имя, бюджет, источник, дата контакта, тег «AI Активен». Drag-and-Drop между колонками. В шапке колонки — сумма (например «Думают (5) — 150 000 ₽»). Lead Rotting: карточка подсвечивается, если долго в одном этапе. Клик по карточке — Drawer с чатом и кнопкой «Сгенерировать ссылку на предоплату».

**Ключевые эндпойнты:** lead_stages, lead_cards (CRUD + PATCH stage), агрегаты по stage.

### 4.5. Задачи (Task Manager)

**Страница:** `/admin/tasks`.  
**Документ:** `TPF_MODULE_TASKS.md`.

- Режимы: Таблица и Канбан. Карточка: заголовок, приоритет (бейдж), аватар исполнителя, дата (красная при просрочке). Блок «Задачи от AI» с кнопкой «Принять в работу». В карточке — микро-действия (позвонить, отправить ссылку). На экране Mission Control: Attention Feed + My Focus (личные задачи по SLA, Time-Bomb при долгом ожидании).

**Ключевые эндпойнты:** tasks (list, CRUD, filter by source=ai, assignee), claim from feed.

### 4.6. Финансы и склад (ERP)

**Страница:** `/admin/finance` (и подразделы).  
**Документ:** `TPF_MODULE_FINANCE.md`.

- Кассы: таблица (название, баланс), кнопки Внести/Изъять/Перевод. Форма транзакции — обязательные поля (касса, сумма, тип, категория). В карточке услуги — вкладка «Расходники» (техкарта). При завершении визита — Checkout Hub: чек, выбор кассы, списание материалов (accordion с возможностью корректировки).
- **Отчёты по периодам (выручка, ЗП, материалы, ROI):** тяжёлые сводки на бэкенде могут читаться из **витрин** (предагрегаты ERP, Engine L2 и эпик **026**). Поведение UI — см. `docs/TECH_PASSPORT_FRONTEND_UI_LOGIC.md` §1 п.7; **переносимый** NFR-канон — `docs/TEMPLATE_ERP_REPORTING_VITRINES.md`; реализация в этом репо — код + `docs/artifacts/SAAS_ARCHITECTURE_SPINE_2026.md` (не дублировать в TPF).

**Ключевые эндпойнты:** cashbox, transactions, service consumables, booking complete + payments.

### 4.6b. Абонементы и лояльность (Loyalty Engine)

**Страница:** `/admin/loyalty`; вкладка «Абонементы» в Drawer пациента; Checkout Hub; блок «Деньги в воздухе» в финансах; PWA — «Мои абонементы».  
**Документ:** `TPF_MODULE_LOYALTY.md`.

- **Digital Pass (PWA):** карточки абонементов в стиле Apple Wallet (прогресс, дата сгорания), кнопка «Записаться по абонементу» → мастер с фильтром услуг пакета; чекаут «Оплачено абонементом».
- **Family Sharing:** в Drawer пациента вкладка «Абонементы», кнопка «+ Добавить члена семьи» (Spotlight по пациентам); привязанные видят карту с пометкой «Доступ: [владелец]».
- **Auto-Checkout:** в Checkout Hub при подходящем пакете — галочка «Списать 1 визит с абонемента»; complete с `use_subscription_id`.
- **Liability Dashboard:** в финансах блок «Деньги в воздухе» (Unearned Revenue) — сумма неотработанных абонементов.

**Ключевые эндпойнты:** patient/loyalty/subscriptions, booking checkout-info (eligible subscriptions), complete с use_subscription_id, admin/loyalty/packages/{id}/family, admin/clinics/{id}/finance/liability.

### 4.7. Формы (Paperless)

**Страница:** раздел настроек или отдельный `/admin/forms`.  
**Документ:** `TPF_MODULE_FORMS.md`.

- Список шаблонов форм, кнопка «Создать шаблон». В контекстном меню пациента или записи — «Отправить форму»: генерация уникальной ссылки и отправка в WhatsApp/SMS.

**Ключевые эндпойнты:** form_templates CRUD, send form link (patient/booking, template).

### 4.8. Аналитика и маркетинг

- Метрики (бюджет, выручка с рекламы, CAC, ROMI), воронка (трафик → лиды → записи → оплата), таблица кампаний по UTM с drill-down в Drawer (пациенты по источнику), AI Marketing Advisor (текстовые инсайты).

### 4.9. Лента внимания и Mission Control

- Attention Feed (типы событий, кнопки «Взять в работу»), My Focus (задачи по SLA, Time-Bomb), AI Supervisor Summary для владельца.

### 4.10. Retention (Smart Retention Engine)

- AI-сегменты, генерация персональных офферов, омниканальный каскад (WA → Push → SMS), ROI кампании (воронка до кассы).

### 4.11. Omni-Vault (медиа и экспорт)

- Медиа-галерея (Masonry), фильтры по типу и дате. При наведении на карточку файла — overlay с аватаром клиента, иконкой канала (TG/WA), датой.
- Голосовые: отображение в виде waveform (wavesurfer.js или аналог), под плеером — блок с авто-расшифровкой текста (транскрипт).
- Data Export Builder (drag колонок, превью, Excel/CSV), Full Backup (кнопка → прогресс → ссылка в Telegram).

### 4.12. PWA (Patient App)

**Документ:** `TPF_MODULE_PWA.md`.

- Bottom Navigation, Next Visit Ticket (билет с QR), Stories Bar, мастер записи (визуальный выбор врача, карусель дат), Digital Wallet в профиле, Pull-to-Refresh.

## Часть V. Микро-взаимодействия и ощущение системы

- **Premium Empty States:** Иллюстрация + понятный текст + одна главная кнопка; не пустая таблица.
- **Smart Spotlight:** Cmd+K не только навигация, но и при необходимости «Спросить AI» (запрос к AI-агенту).
- **Skeleton Loaders:** На всех страницах загрузки — скелет по форме контента.
- **Optimistic Updates:** Drag, смена статуса, отправка сообщения — мгновенная реакция UI с откатом при ошибке.

## Часть VI. Связь с бэкендом и планом внедрения

- **Контракты:** Для каждого нового экрана или действия в TPF_MODULE_* указывается используемый эндпойнт (см. FUNCTIONAL_MAP_CURRENT, TECH_PASSPORT_BACKEND).
- **Приоритеты и критерии:** Следовать `REV_CRITERIA_IMPLEMENTATION.md` (приоритет P0–P5, чек-лист качества, согласование с V2).
- **RAG:** Полная карта инноваций и привязка к страницам/эндпойнтам — в `REV_RAG_MAP_INNOVATIONS.md`.
- **Отчётные витрины ERP — не отдельный TPF_*:** префикс `TPF_` зарезервирован под **фронтовые** модули и экраны. Переносимый канон (слои, PK, паритет, DoD) — `docs/TEMPLATE_ERP_REPORTING_VITRINES.md`; в этом репозитории — код + `docs/artifacts/SAAS_ARCHITECTURE_SPINE_2026.md`; NFR‑рамка — `docs/ARCHITECTURE_EXCELLENCE_PASSPORT.md` §5; UI‑нормы при метаданных ответа — `docs/TECH_PASSPORT_FRONTEND_UI_LOGIC.md` §1 п.7.
