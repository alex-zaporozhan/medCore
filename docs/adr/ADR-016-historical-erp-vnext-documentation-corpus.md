# ADR-016 — Корпус исторической документации ERP vNext / QA_ARCH

- **Статус:** Accepted  
- **Дата:** 2026-04-19  

## Контекст

В ходе работ по Business OS и волнам QA_ARCH накопился большой набор согласованных текстов (доменные чертежи, DEV-пакеты, пост-волновой фундамент, фронт-текпаспорта). Часть ссылок изначально указывала на несуществующий в репозитории путь `docs/artifacts/ARCH_DEV_*` и устаревшие имена CI.

## Решение

1. **Хранение:** пакет размещён под **`docs/archive/erp-vnext-2026-wave-planning/`** с явным README и INDEX. Это **архив намерений и волн**, не замена ADR и не исполняемый бэклог по умолчанию.

2. **Приоритет источников:** при расхождении с кодом или с файлами в **`docs/adr/`** побеждают **код и ADR**. Архив используется для контекста эволюции и формулировок DoD.

3. **Имена `BUSINESS_LOGIC_CURRENT` / `BUSINESS_LOGIC_V2`:** отдельных файлов нет; канон бизнес-логики — **`docs/artifacts/BUSINESS_LOGIC.md`**, маршруты — **`docs/artifacts/BUSINESS_ROUTES.md`**.

4. **Сопровождение:** при изменении структуры `docs/` обновлять относительные ссылки в README/INDEX архива; CI **`documentation-markdown-links.yml`** проверяет `docs/`.

## Последствия

- Онбординг и RAG могут подтягивать исторический контекст без смешения с живым `docs/artifacts/`.
- Риск устаревания остаётся для деталей внутри архива — явно помечать сверку с `docker-compose.yml`, `.github/workflows/` и `src/`.
