# ADR-010: Импорт из внешних CRM/ERP — scope v1

- **Статус:** Proposed  
- **Дата:** 2026-04-03  
- **Контекст:** Запрос на импорт из 1С, Битрикс24 и др. Универсальный «импорт всего» в одной итерации нереалистичен.

## Решение (целевое)

### Фаза A — канон и инфраструктура

- Каноническая модель импорта: **контакт/пациент**, **сделка/лид**, **услуга/прайс** (минимум); таблицы маппинга `external_id` → внутренний UUID; **idempotency** по `(source_system, external_id, entity_type)`.
- UI/API: загрузка файла или запуск синхронизации по credentials (отдельный секретный контур).

### Фаза B — коннекторы (по одному эпику)

| Источник | Типичный формат v1 | Примечание |
|----------|-------------------|------------|
| Битрикс24 | REST API + CSV fallback | Сущности: контакты, сделки |
| 1С | CommerceML / выгрузка XML / OData | Зависит от конфигурации; v1 — один сценарий обмена |
| Прочие | CSV с маппингом колонок | Наименьший TTM |

Полная матрица полей — в [modules/data_migration_import_connectors.md](../architecture/modules/data_migration_import_connectors.md).

## Не входит в v1 без отдельного ADR

- Двусторонняя синхронизация в реальном времени.
- Импорт медицинских документов и подписей.
- Полная бухгалтерская выгрузка из 1С.

## Последствия

- Отдельные задачи на каждый коннектор; нагрузка на БД при массовом импорте — батчи и очередь.

## Связь

## Фаза 3+ (репозиторий, старт исполнения)

- Ключ entitlement **`import.crm_v1`** (каталог `platform_catalog_options`); гейт **`require_entitlement`** на `admin_crm_import`.
- Таблица **`crm_import_staging_jobs`** и **dry-run stub** — задел под конвейер §25.0; матрица полей коннекторов по-прежнему в этом модуле и в эпиках Phase B.
- Профили источников v1 (имена для `source_profile`): `csv_contacts_v1`, `bitrix24_contacts_v1` (целевые; парсеры — следующие PR).
