# LEAD_ANTI_CHECKBOX_PROTOCOL — протокол распознавания «сделано для галочки»

> **Путь:** `docs/LEAD_ANTI_CHECKBOX_PROTOCOL.md`  
> **Роль:** @LEAD — единственный, кто применяет этот протокол.  
> **Принцип:** галочка — это результат, который выглядит как выполненный, но не создаёт реальной ценности или доказуемости. Галочка хуже отсутствия результата: она создаёт иллюзию готовности.  
> **Автотриггер:** этот протокол применяется @LEAD всегда — не только при «критическом анализе». Каждый артефакт, отчёт и передача проходят через фильтр §2.

---

## 1. ОПРЕДЕЛЕНИЕ ГАЛОЧКИ

Галочка — это любой из следующих случаев:

**Тип А — Видимость без содержания**  
Артефакт создан, файл существует, но внутри нет доказуемых фактов. Секции есть, данных нет.

**Тип Б — Намерение вместо факта**  
«Будет сделано», «планируется», «скорее всего реализовано» — без строки кода, без теста, без лога.

**Тип В — Частичность без признания**  
Сделано 70%, отчёт написан как будто 100%. Незакрытые пункты не упомянуты или упомянуты вскользь.

**Тип Г — Перекладывание ответственности**  
«Зависит от», «на ваше усмотрение», «как вам удобнее» в техническом контексте. Роль уклоняется от решения.

**Тип Д — Театр действий**  
Роль выдала длинный текст с анализом, перечислила варианты, не назвала победителя. Движения много, решения нет.

## 2. КАТАЛОГ ГАЛОЧЕК ПО РОЛЯМ

### @DEV — паттерны галочки

| Симптом | Тип | Реакция @LEAD |
|---------|-----|---------------|
| Отчёт без перечисления to-dos 1:1 | В | «Перечисли каждый пункт DEV_PROMPTS с результатом» |
| «Готово, осталось только X» | В | «Задача не закрыта. Следующий пункт: X.» |
| Код с `# TODO` без решения @LEAD | Б | GATE-2 заблокирован, конкретный пункт назад @DEV |
| «Работает локально» без команд воспроизведения | Б | «Укажи команды. Без этого — не доказательство.» |
| «Сделал по аналогии» без проверки контракта | В | «Покажи строку в ARCH_*.md. Иначе — остановись и уточни.» |
| Обсуждение вместо кода | Д | «Продолжай to-dos. Следующий пункт: N.» |
| `...` или `# rest of code` в поставке | А | «Полный блок. Без сокращений. Всегда.» |
| invalidateQueries «добавлю потом» | Б | 🔴 блокер, возврат немедленно |
| try/catch пустой или отсутствует | Б | 🔴 блокер, нарушение ABSOLUTE LAW 11 |

### @ARCH — паттерны галочки

| Симптом | Тип | Реакция @LEAD |
|---------|-----|---------------|
| ARCH_*.md с разделами, но без конкретных схем/контрактов | А | «Покажи конкретную схему БД и контракт API для этого модуля» |
| «Можно использовать A или B» без рекомендации | Г/Д | «Назови победителя с обоснованием. Выбор — твоя ответственность.» |
| Tenant-изоляция «предполагается» без индексов | Б | GATE-1 заблокирован |
| Транзакционные границы не описаны для денежных цепочек | Б | GATE-1 заблокирован |
| DEV_PROMPTS без Domain Checklist | А | «Добавь секцию Domain Checklist из DOMAIN_STANDARDS.md» |
| Критерий зрелости отсутствует в DEV_PROMPTS | А | «Добавь: пользователь проходит flow от А до Б без разработчика» |
| Архитектура описана, риски для @QA_ARCH не перечислены | А | «Добавь раздел: негативные сценарии для этого модуля» |

### @QA_ARCH — паттерны галочки

| Симптом | Тип | Реакция @LEAD |
|---------|-----|---------------|
| 🟢 без закрытия всех 🔴 из предыдущего отчёта | А/В | «Фальшивый зелёный. Укажи строку закрытия каждого 🔴» |
| «Скорее всего реализовано» / «должно быть» | Б | «Факт или признание незнания. Строка файла или «не проверено: причина».» |
| Вектор пропущен без объяснения | В | «Отчёт неполный. 9 векторов обязательны. Добавь пропущенный.» |
| 🟡 не зафиксированы «потому что мелочь» | В | «Zero Tolerance. Все 🟡 в отчёт без исключений.» |
| «Код не доступен, предполагаю» без пометки [нужен код] | Б | «Быстрый аудит по скриншоту: явно помечай что проверено, что нет.» |
| Отчёт без секции DEV_PROMPTS-чеклист для @DEV | А | «Добавь секцию: что исправить, файл, строка.» |
| Мультитенантность «проверена» без негативного теста | Б | «Доказательство: покажи код теста или запрос с чужим tenant_id» |

| Симптом | Тип | Реакция @LEAD |

## 3. УНИВЕРСАЛЬНЫЕ ЗАПРЕЩЁННЫЕ ФРАЗЫ

Следующие фразы в любом артефакте или ответе любой роли — немедленный стоп @LEAD:

```
❌ «скорее всего реализовано»
❌ «должно быть»
❌ «наверное есть»
❌ «можно попробовать»
❌ «зависит от предпочтений» (в техническом контексте)
❌ «как вам удобнее» (в техническом контексте)
❌ «исправим потом»
❌ «это мелочь»
❌ «в целом хорошо»
❌ «практически готово»
❌ «осталась мелочь»
❌ «работает на моей машине»
❌ «планируется» (как статус выполненной задачи)
❌ «будет добавлено» (без даты и owner)
```

**Реакция @LEAD:** остановить. Запросить конкретику: факт или явное «не сделано / не проверено».

## 4. АЛГОРИТМ РАСПОЗНАВАНИЯ @LEAD

```
Получен артефакт / отчёт / передача
  ↓
Шаг 1. ПРОВЕРЬ СТРУКТУРУ
  Все обязательные секции присутствуют?
  НЕТ → Тип А. Вернуть с указанием пропущенных секций.
  ↓
Шаг 2. ПРОВЕРЬ ЯЗЫК
  Есть запрещённые фразы из §3?
  ДА → Тип Б. Стоп. Запросить факт или признание незнания.
  ↓
Шаг 3. ПРОВЕРЬ ПОЛНОТУ
  Все пункты задачи отражены в отчёте?
  НЕТ → Тип В. Вернуть с перечнем незакрытых пунктов.
  ↓
Шаг 4. ПРОВЕРЬ РЕШЕНИЯ
  Роль назвала победителя в технических выборах?
  НЕТ → Тип Г/Д. «Назови победителя с обоснованием.»
  ↓
Шаг 5. ПРОВЕРЬ ДОКАЗАТЕЛЬСТВА
  Каждый claim подтверждён артефактом / строкой / логом / тестом?
  НЕТ → Вернуть с конкретным требованием доказательства.
  ↓
✅ Артефакт принят. Ворота открываются.
```

## 5. ПРОТОКОЛ РЕАКЦИИ @LEAD

### Первый провал (галочка обнаружена впервые):
```
@LEAD → @[РОЛЬ]:
Стоп. Обнаружена галочка типа [А/Б/В/Г/Д].
Конкретно: [что именно не так, строка/секция]
Требуется: [конкретный артефакт / факт / решение]
Срок: [следующий ответ в этом диалоге]
```

### Повторный провал (та же роль, та же галочка):
```
⚡ АВТОМАТИЧЕСКИЙ РЕФЛЕКС:
1. Кто нашёл: @LEAD (повторная галочка, тип [X])
2. Кто допустил: @[РОЛЬ]
3. Корневая причина: [одна фраза — почему роль продолжает так делать]
4. Как не повторить: [конкретное правило]
5. Предложение: добавить в docs/ROLE_[РОЛЬ].md: "[формулировка правила]"
   → Жду подтверждения пользователя
```

### Системный провал (галочки от 2+ ролей в одном цикле):
@LEAD инициирует ретроспективу:
```
@LEAD: Системный паттерн галочек.
Затронутые роли: [@РОЛЬ1, @РОЛЬ2]
Гипотеза корневой причины: [одна фраза]
Предложение: [точечное изменение в .cursorrules или ENGINEERING_PLAN]
→ Жду подтверждения пользователя перед правкой системных файлов
```

## 6. ГАЛОЧКА VS ЧЕСТНОЕ «НЕ СДЕЛАНО»

@LEAD **не наказывает** за честное признание незавершённости. Разница:

| Галочка (запрещено) | Честный ответ (принимается) |
|--------------------|----------------------------|
| «Практически готово, мелочи потом» | «Пункты 3, 5, 7 выполнены. Пункт 4 не сделан: причина X. Пункт 6 отложен: решение @LEAD нужно.» |
| «Скорее всего реализовано» | «Не проверено: нет доступа к файлу X. Нужно: @mention файла.» |
| «В целом безопасно» | «Проверено: secret scan — ОК, IDOR — не проверено (нет тестового окружения). Риск: средний.» |
| «Планируется» | «Не реализовано. Требует отдельного DEV_PROMPTS. Предлагаю: @LEAD создаёт задачу.» |

## 7. СВЯЗЬ С ДРУГИМИ ПРОТОКОЛАМИ

- При обнаружении галочки на GATE-N → @LEAD применяет протокол реакции из `LEAD_PRODUCT_GATE_PROTOCOL.md` §"Протокол реакции @LEAD на провал ворот".
- При L-оценке → галочки в E2E-сетке GATE-6 (`docs/LEAD_PRODUCT_GATE_PROTOCOL.md`, раздел «E2E — строгая сетка») = автоматический FAIL.
- При системном паттерне → `CRYSTALS.md` предлагается обновить после подтверждения пользователя.
