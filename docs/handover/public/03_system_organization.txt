ОРГАНИЗАЦИЯ СИСТЕМЫ ПО СМЫСЛУ
=============================

Описание без привязки к дереву файлов: как смысловые части складываются в целостный продукт.


ПОВЕРХНОСТЬ API
---------------

Версионированный REST-слой сгруппирован по ролям вызывающей стороны. Публичные маршруты отделены от аутентифицированных;
платформенные операции изолированы от клинического админа. Общие зависимости: сессия БД, контекст тенанта, проверка матрицы
прав, ограничение частоты запросов.


ПРИКЛАДНАЯ ЛОГИКА
----------------

Сервисы инкапсулируют сценарии: запись на приём, расписание, CRM и воронка, задачи и канбан, документооборот, лояльность,
маркетинг и атрибуция, omnichannel и AI-ассистенты, склад и касса, зарплаты, отчётность ERP, настройки клиники и сети,
биллинг SaaS. DTO отделяют контракт API от внутренних структур. События публикуются в шину и в outbox там, где нужна
гарантия после коммита.


МОДЕЛЬ ДАННЫХ И ДОСТУП
----------------------

Сущности отражают мультитенантность (клиника, организация), финансовые и медицинские сущности, коммуникации, каталог услуг
и прайс, платформенный каталог продуктов и entitlements. Репозитории инкапсулируют SQL; интерфейсы позволяют подменять
реализацию в тестах.


ИНТЕГРАЦИИ И ФОН
----------------

Клиенты внешних API изолированы в инфраструктурном слое. Задачи очереди выполняют длительные операции, ретраи outbox,
уведомления и сверки. Хранилище файлов — пресайны и загрузки через S3-совместимый API.


КЛИЕНТСКОЕ ПРИЛОЖЕНИЕ
---------------------

Маршрутизация по зонам продукта; общий клиент HTTP; хуки для доменной логики UI. Сборка оптимизирована под PWA и разделение
чанков по зонам навигации.


АВТОМАТИЗАЦИЯ ПОСТАВКИ
----------------------

Контейнеры backend и frontend; compose-стек для полного контура на одной машине; отдельный шаг миграций перед подъёмом
приложения. Скрипты и workflow CI описывают прогон тестов, аудит зависимостей, публикацию образов и альтернативный
корпоративный pipeline.


ДОКУМЕНТАЦИЯ И РЕШЕНИЯ
----------------------

Внутренние ADR фиксируют контракты вебхуков, outbox, реплики для отчётов, политики резервного копирования и др.
Продуктовые обзоры описывают состояние возможностей относительно кода.


ТРАССИРОВКА СЦЕНАРИЯ «ОТ ЗАПРОСА К ДАННЫМ»
------------------------------------------

  1. HTTP-обработчик проверяет аутентификацию и права.

  2. Сервис оркестрирует транзакцию, доменные правила и побочные эффекты.

  3. Репозиторий выполняет запросы к PostgreSQL.

  4. При необходимости публикуется событие или запись outbox; воркер доводит асинхронную часть до конца.
