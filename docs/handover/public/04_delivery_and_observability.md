# Поставка, эксплуатация, наблюдаемость

## Сборка и запуск

- **Локальная разработка** — подъём PostgreSQL и Redis контейнерами или нативно, применение миграций к схеме, запуск API с hot reload.
- **Полный стек** — compose-профиль с миграциями, API, статической отдачей frontend, воркерами очереди и планировщиком; опционально стек наблюдаемости.
- **Контейнеры** — отдельные образы для backend и frontend; на целевой среде задаются ссылки на образы в выбранном registry.

## Непрерывная интеграция

Набор параллельных pipeline-ов:

- основной прогон unit и интеграционных тестов backend с поднятием тестовой БД и Redis;
- расширенный прогон с сборкой frontend и браузерными проверками;
- узкий **ворота критического пути** — минимальный набор сценариев с жёстким требованием отсутствия пропусков и ошибок в отчёте;
- полный регрессионный gate перед релизом;
- сканирование файловой системы на уязвимости;
- проверка целостности ссылок в документации;
- учения по восстановлению из резервных копий;
- сборка образов без публикации для проверки Dockerfile;
- опциональная публикация в публичный Docker registry при настроенных учётных данных и политике веток или тегов.

Переменные окружения для CI подбираются так, чтобы маршруты, требующие внешних идентификаторов OAuth и токенов ботов, стабильно собирались без реальных секретов.

## Непрерывная поставка

Два типовых контура:

1. **Один сервер или небольшая инфраструктура** — сборка образов локально или в CI, публикация в выбранный registry, на целевой машине pull и `compose up` с подстановкой секретов из защищённого хранилища.
2. **Корпоративный Jenkins** — параметризуемые стадии тестов, сборка, push в приватный registry организации, выкладка по согласованному runbook.

GitHub Actions и Jenkins не взаимоисключают: выбор определяется политикой заказчика.

## Тестовая инфраструктура

Отдельная база данных с именем, явно помечающим тестовый контур; прогон очистки с защитой от случайного указания production-DSN. Интеграционные тесты Redis включаются флагом окружения.

## Наблюдаемость в эксплуатации

- Метрики в формате Prometheus.
- Правила алертинга под ключевые SLO: доступность, ошибки, очереди, БД, внешние интеграции.
- Дашборды Grafana для оперативного обзора.

## Секреты и конфигурация

- Единый перечень имён переменных окружения с пояснениями поставляется вместе с продуктом; production-значения не хранятся в репозитории.
- Опциональная подгрузка секретов из облачного хранилища до инициализации настроек.
- Редакция продукта (например enterprise vs базовая) задаётся согласованными переменными на backend и frontend.

## Операции

Резервное копирование, политики хранения и проверяемое восстановление описаны в архитектурных записях и сопутствующей эксплуатационной документации поставки.
