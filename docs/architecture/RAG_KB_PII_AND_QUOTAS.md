# RAG KB §24.3: PII, квоты и эксплуатация

**Связь:** [STREAM_PRODUCT_RAG_24_EPIC.md](./arch_plan/STREAM_PRODUCT_RAG_24_EPIC.md), [ADR-014](../adr/ADR-014-rag-retrieval-vectors-and-stores.md).

## Квоты (реализовано в API)

| Параметр | Env | Смысл |
|----------|-----|--------|
| `rag_kb_quota_max_documents_per_org` | `RAG_KB_QUOTA_MAX_DOCUMENTS_PER_ORG` | Максимум фрагментов KB на организацию; **0** = без лимита. При превышении admin `POST .../rag-kb/documents` → **409** `rag_kb_quota_exceeded`. |

Лимиты размера одного фрагмента остаются в схеме API (`title` ≤ 255, `body` ≤ 50 000 символов).

## PII и чувствительные данные (политика)

1. **Назначение KB:** публично-ориентированные ответы через embed-поиск. Не хранить в чанках то, что нельзя показывать посетителю сайта без явного согласия (например полные номера полисов, необезличенные медицинские заключения).
2. **Персональные контакты:** допустимы только **публичные** контакты клиники (телефон ресепшена, адрес). Избегать персональных данных конкретных сотрудников без их согласия.
3. **Автоматическая классификация:** автоматическое удаление PII из текста в v1 **не** выполняется; ответственность за содержимое — у оператора организации (@BIZ / владелец тарифа).
4. **Аудит:** мутации KB пишутся в `organization_rag_kb_audit_log` (кто/когда/действие); полный текст тела в аудит **не** дублируется (только укороченный `title` в `meta`).

## Режимы поиска

| Env | Значения |
|-----|----------|
| `RAG_KB_SEARCH_MODE` | `ilike` (default), `fts`, `hybrid` |

FTS использует конфиг PostgreSQL `simple` (минимальная морфология; подходит для смешанных языков при ограничениях).
