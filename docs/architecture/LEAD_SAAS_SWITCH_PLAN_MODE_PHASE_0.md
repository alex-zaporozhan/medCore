# Switch Plan Mode — Фаза 0 SaaS (первый шаг §15)

**Назначение:** готовый режим запуска по [LEAD_SAAS_PHASE_EXECUTION_PLAYBOOK.md](./LEAD_SAAS_PHASE_EXECUTION_PLAYBOOK.md) для **первого узла** дорожной карты мастер-плана: **Phase_0_Docs** / **D0 TARGET_ADR_LEAD_GAP** ([§15](./SAAS_STRENGTHENING_MASTER_PLAN.md#saas-sec-15), mermaid `p0`).  
**Не путать** с таблицей «Статус фаз» в [INDEX.md](./INDEX.md) (там фазы 0–7 — про покрытие модульными `.md` репозитория).

---

## 1. Эпик-срез (имя и одна фраза)

**ID среза:** `SaaS-P0-D0`  
**Формулировка:** выровнять **корпус документов и ADR** с [SAAS_STRENGTHENING_MASTER_PLAN.md](./SAAS_STRENGTHENING_MASTER_PLAN.md), зафиксировать **gap / риски / go-no-go** перед **первым кодовым срезом Фазы 1a**, без новых необратимых миграций платформенного контура без правил [§18](./SAAS_STRENGTHENING_MASTER_PLAN.md).

---

## 2. Границы (не делать в этом режиме)

- Не начинать **новые** необратимые миграции **platform** и публичные денежные пути без явного «go» после [§18](./SAAS_STRENGTHENING_MASTER_PLAN.md) и ворот [§19](./SAAS_STRENGTHENING_MASTER_PLAN.md) (исключение MVP spine B уже в коде — учитывать [§2d](./SAAS_STRENGTHENING_MASTER_PLAN.md)).
- Не объявлять «Фаза **1a** / **1b** закрыта» по мотивам только документов — DoD фаз остаётся в **§15b**.
- Не смешивать этот срез с полной реализацией **RLS, JWT Основателя, UI кабинета** — это следующие эпик-срезы **1a+**.

## 6. Подсказка: следующий режим после успешного P0
