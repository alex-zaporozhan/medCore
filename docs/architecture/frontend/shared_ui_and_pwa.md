# Shared UI и PWA

## Назначение

Переиспользуемые компоненты, ошибки, утилиты маршрутов; опционально PWA-слой.

## Как это работает

1. **Error boundary:** корневой `App.tsx` оборачивает дерево в `ErrorBoundary` из `@/shared/ErrorBoundary` — необработанные ошибки рендера React не роняют белый экран без сообщения (поведение см. реализацию компонента).
2. **Общие компоненты:** `frontend/src/shared/` импортируется алиасом `@/shared/...`; сюда вынесено то, что используется и в admin, и в app, и в marketing, чтобы не плодить копии.
3. **PWA:** код в `frontend/src/pwa/` подключается, если сборка предусматривает service worker (проверять `vite.config` и entry); в документе без запуска сборки остаётся только указание на каталог.
4. **Тесты структуры:** `structurePhase4.test.ts` и соседние файлы проверяют инварианты импортов/дерева, а не бизнес-сценарии.

## Точки входа

- `frontend/src/shared/` — общие компоненты (в т.ч. `ErrorBoundary.tsx`), хелперы, стилизация, переиспользуемые виджеты.
- `frontend/src/pwa/` — регистрация service worker и связанная логика (если включена сборкой).

## Тесты

- Структурные: `frontend/src/__tests__/structurePhase4.test.ts` (инварианты дерева/импортов по фазе 4).

## Статус

| Аспект | Статус |
|--------|--------|
| Error boundary в корне | `App.tsx` импортирует `@/shared/ErrorBoundary` |
| PWA | Зависит от конфигурации Vite/manifest; без рантайм-проверки — «по коду» |

## Непонятное

Фактическое поведение offline/cache — только после проверки в браузере и конфигов сборки.

### Enterprise-аудит (честная оценка)

- **Критические риски:** PWA/service worker при кэшировании API-ответов может нарушать консистентность данных без строгой политики версий.
- **Средние риски:** общий `ErrorBoundary` не заменяет мониторинг ошибок в проде (Sentry и т.д.) — вне репозитория или не задокументировано.
- **Формально / недоделано:** структурные тесты не ловят визуальные регрессии.
- **Рекомендуемые доработки:** явная политика cache для `/api` (обычно no-store).

### Соответствие фактам (проверка)

- Наличие `frontend/src/pwa/`, `shared/ErrorBoundary` — по дереву файлов; поведение SW — не прогонялось.

### Углубление (PRINCIPLE — фундаментальный обзор)

- **Сильные логические риски:** PWA-кэш может отдавать устаревшие данные API при неверной политике cache.
- **Что усилить:** явный `Cache-Control: no-store` для `/api` на edge.
- **С нуля:** интеграция error reporting (Sentry) — вне репозитория.
- **БД:** не применимо.
