# Админка: страницы и связь с API

## Назначение

UI сотрудника клиники под `/admin/*`: расписание, CRM, омниканал, задачи, отчёты и настройки.

## Как это работает (страница и бэкенд)

1. **Компонент страницы:** файл в `frontend/src/admin/pages/*.tsx` обычно объявляет локальные хуки `useQuery`/`useMutation` или импортирует хук из `frontend/src/hooks/` (если вынесена логика).
2. **Данные:** запросы идут в REST эндпоинты вида `/api/v1/admin/...` с префиксом клиники в path (`/admin/clinics/{clinic_id}/...`) там, где так задумано в OpenAPI/роутере — UI обязан подставлять тот же `clinic_id`, что и в JWT/storage (`getBoundAdminClinicId`).
3. **Ошибки прав:** 403 от `require_permissions` отображается как запрет; часть возможностей заранее скрыта в Box через `edition.ts`, но сервер остаётся источником истины.
4. **Навигация:** переходы между разделами — `<Link>` / `useNavigate` на пути из `ROUTE_PATHS.admin`; дублировать строки путей в компонентах без `routePaths` запрещено комментариями в коде канона.

## Точки входа

- Каталог: `frontend/src/admin/pages/` (десятки `Admin*.tsx`, плюс `SchedulePage.tsx`).
- Layout и навигация: `frontend/src/admin/layouts/AdminLayout.tsx` (и связанные компоненты shell).
- Защита маршрутов: `frontend/src/admin/AdminAuthGuard.tsx`.
- Контекст клиники: `frontend/src/contexts/AdminClinicContext.tsx`.

## Паттерн

Типично: страница → хуки `useQuery` / `useMutation` с ключами из `queryKeys` → вызовы функций из `frontend/src/api/*` или прямо `client.ts`.

## Непонятное

Соответствие «каждая кнопка → один эндпоинт» только по чтению конкретной страницы; RBAC на бэкенде может отрезать сценарий, не отражённый в UI.

### Enterprise-аудит (честная оценка)

- **Критические риски:** нет UI/API для управления жизненным циклом организаций как у SaaS-оператора (см. [INDEX.md](../INDEX.md)).
- **Средние риски:** частичное покрытие страниц тестами; регрессии в формах оплаты/PII дороги.
- **Формально / недоделано:** omni «owner» в API — это админ клиники; фронт не должен подписывать экраны как «владелец платформы» ([U-005](../UNRESOLVED_AND_CONFUSION_LOG.md)).
- **Рекомендуемые доработки:** contract-тесты OpenAPI для критичных admin flows.

### Соответствие фактам (проверка)

- Каталог `admin/pages`, хуки `frontend/src/hooks/` — по структуре репозитория.

### Углубление (PRINCIPLE — фундаментальный обзор)

- **Сильные логические риски:** формы с деньгами и PII без полного покрытия тестами — дорогие регрессии.
- **Что усилить:** сценарные тесты на оплату/бронь от лица админа в связке с API.
- **С нуля:** визуальные регрессии (Percy/Chromatic) — опционально.
- **БД:** косвенно — корректный `clinic_id` в запросах.
- **Полный разбор:** [FUNDAMENTAL_CODE_REVIEW_PRINCIPLE.md](../FUNDAMENTAL_CODE_REVIEW_PRINCIPLE.md).
