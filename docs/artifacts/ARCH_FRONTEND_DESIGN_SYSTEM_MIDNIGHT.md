## 1) Принцип

- Интерфейс как **инструмент**, не «сайт»: данные и действия впереди, хром нейтрален.
- **Поверхности:** Slate/Graphite, не чисто чёрный на белом; акценты **только по смыслу** (действие, AI, успех, риск).
- **Карточки:** граница + при необходимости лёгкая тень; без «плашечного» primary на пол-экрана.

## 3) Mantine (`theme.ts`)

| Параметр | Значение |
|----------|----------|
| `primaryColor` | `dark` (палитра Slate, primary-кнопки по умолчанию — графит) |
| `primaryShade` | `8` (≈ `#1E293B`) |
| `colors.dark` | 10 оттенков Slate (как в foundation) |
| `colors.ai` | 10 оттенков фиолетового (AI / RAG) |
| `Paper` / `Card` | `withBorder`, `shadow: none` (шум теней снижен), `radius: sm` по умолчанию |
| `Table` | плотность, `highlightOnHover`, фон шапки `dark.0` |
| `Text` | `size: sm` по умолчанию (14px) |

**Явные цвета на компонентах:** PAW/маркетинг — см. `SEMANTIC.action` и локальные CTA; метрики дашборда (`SEMANTIC.metrics`); AI (`color="ai"` или `SEMANTIC.ai.accent`). Глобальный `primary` (графит) не заменять «радугой» на каждом экране.

---

## 4) Навигация админки (sidebar)

- Фон **белый**, правая граница `--divider`.
- Активный пункт: **не** заливка primary — псевдоэлемент `::before` (полоска ~3×20px, скругление справа), цвет `dark.9`, лёгкая тень `--admin-nav-active-stripe-shadow` (визуальный «объём» полоски), текст `dark.9`, фон при hover `dark.0`.
- Реализация: класс `.admin-nav-link` в `index.css` + `data-active` в `AdminLayout.tsx`.

## 5) Модуль семантики (`shared/semanticUi.ts`)

`SEMANTIC.metrics`, `SEMANTIC.dateNav`, `SEMANTIC.ai.accent` (`"ai"`), `SEMANTIC.status.*` — Mantine-имена цветов для смысловых акцентов без привязки к глобальному primary.

**Кнопки и ссылки (`SEMANTIC.action`):** `send` — blue (отправка сообщений, ссылок, шаг «Далее»); `confirm` — teal (подтверждение, формы, оплата, запись); `danger` — red; `dismiss` — gray (отмена/назад); `link` — blue (вторичные ссылки PAW). Одна кнопка — один смысл; без лишней заливки экрана.

**Щадящее использование цвета:** насыщенный `filled` — у одного-двух главных действий в зоне (например «Отправить» в чате). Второй эшелон — `subtle` + один семантический оттенок (не пять разных `light` подряд). Нейтральные действия — `gray` / `default`, не конкурируют с текстом и данными.

## 5.1) Экономия внимания и площади (плотные панели, Omni / ERP)

Панели справа и нижние зоны с множеством контролов легко превращаются в «серую стену»: глаз устаёт от однородных `gray.0` / `variant="light"` без иерархии.

| Принцип | Практика |
|--------|----------|
| **Поверхность** | Инспекторы и карточки: `bg: var(--bg-card)` (белый), граница `var(--divider)`, `shadow: none`. Не заливать большие области сплошным `gray.0`, если это не данные. |
| **Табы** | Дорожка вкладок: лёгкий фон `var(--bg-main)` или белый + **тонкая рамка** `var(--divider)`; избегать тяжёлой серой «капсулы» без границы с фоном. |
| **Вторичные кнопки** | `variant="subtle"` + смысл: CRM / навигация в воронку — **blue**; запись, расписание, подтверждение — **teal** (`SEMANTIC.action.confirm`); фоновые / списки — **gray**. Иконки слева (`leftSection`) — узнаваемость без текста-кирпича. |
| **Вертикаль** | `gap="sm"`, короткие подписи; `minHeight` у панелей вкладок — по необходимости, без «резерва на весь экран». |
| **Герой** | В чате главный объект — **текст сообщения**; метаданные мельче и бледнее; действия «Скрыть» — иконка + tooltip, не строка вровень с текстом. |
| **Inbox (список диалогов)** | Превью строки: **имя и телефон крупнее** строки статуса; статусы API (**OPEN** и др.) — **одна** компактная строка (`fz` 9), без второго ряда `Badge` с точками; цвет статуса по смыслу, **одинаковый вес** с соседними сегментами (не «герой-бейдж» на OPEN); для **OPEN** — `title` с пояснением («диалог активен, можно обмениваться сообщениями»). Длинные ФИО — `truncate` + `minWidth: 0` на контейнере. |
| **Два сайдбара** | Левое меню админки — как прежде (`AdminLayout`). **Правый** инспектор Omni может схлопываться в **вертикальную рейку иконок** (56px), чтобы отдать ширину центральному чату — см. техпаспорт §2.2.1. |

**Референс в коде:** `AdminOmniChatPage` (`/admin/omni-chat`) — рабочий центр + вкладки Клиент / Анкеты / Таймлайн / AI; `ThreeColumnLayout` с пресетом `omni-inspector` и опцией `omniRightCollapsed`.

## 6) E2E и стабильность селекторов (@QA_ARCH)

**Цель:** визуальные изменения не ломают smoke, если опираться на **роли и доступные имена**, а не на классы Mantine/CSS-модули.

| Правило | Почему |
|---------|--------|
| Предпочитать `getByRole('button', { name: /…/ })`, `getByRole('link', { name: … })` | Текст кнопок/ссылок меняется реже, чем классы |
| Не использовать селекторы вида `.mantine-Button-root` | Генерируются/меняются с версией UI-kit |
| Для критичных сценариев B-1+ добавлять **`data-testid`** на shell (например `data-testid="admin-layout-main"`) — по отдельному эпику | Якорь без привязки к теме |
| `BASE_URL`, preview-порт | Как в `ARCH_QA_BROWSER_E2E_OPERATING_INSTRUCTIONS.md` |

**Переменные окружения** (не путать с дизайн-токенами): `BASE_URL`, будущие `E2E_*` для API — только для прогона Playwright.

**Регресс после смены темы:** прогон `npm run build`, `npm test`, `npm run test:e2e` (smoke); визуально — админ login, дашборд, расписание, PAW `/app`.
