## ARCH_ERP_NEXT — домен ERP (Finance, Payroll, Inventory)

### 1. Краткое описание домена

ERP‑домен сводит **операционку в деньги и запасы**:

- учёт касс и движений денег;
- расчёт зарплат;
- склад и материалы (техкарты услуг);
- главный узел: что происходит при завершении визита.

### 2. Актуальная модель сущностей (по коду / BUSINESS_LOGIC_CURRENT/V2)

По `BUSINESS_LOGIC_V2` и коду (`admin_finance.py`, `FinanceService`, `Inventory`/`Payroll` роутеры):

- **Финансы:**
  - `Cashbox` — касса клиники;
  - `FinancialTransaction` — приход/расход, связь с `booking_id`/`payment_id`;
  - `ClinicPaymentGateway` — платёжные провайдеры и настройки;
  - возможно, агрегаты/своды по кассам.
- **Зарплаты:**
  - `PayrollPolicy` — правила расчёта ЗП;
  - `SalaryTransaction` — начисления по врачам/ролям.
- **Склад:**
  - `Product` — номенклатура;
  - `Warehouse` — склады;
  - `InventoryTransaction` — приход/расход;
  - `ServiceConsumable` — техкарты услуг (расход материалов на визит).
- Frontend:
  - `AdminFinancePage.tsx` с вкладками «Кассы», «Транзакции», «Зарплаты», «Склад».

### 3. Целевая модель vNext (что нужно добавить/упростить)

1. **Жёсткий ERP‑узел при завершении визита:**
   - определено единое место (сервис/фасад), которое:
     - слушает `Booking.status` изменения;
     - запускает ERP‑процессы в **одной транзакции БД**:
       - создаёт `FinancialTransaction` по факту визита;
       - начисляет `SalaryTransaction` по `PayrollPolicy`;
       - списывает `InventoryTransaction` по `ServiceConsumable`.
   - при ошибке:
     - rollback по всем ERP‑операциям;
     - запись понятного события в `AttentionFeed`/Tasks.

2. **Разделение ERP‑сущностей по ответственности:**
   - чётко оформить:
     - какие поля и связи относятся к финансам;
     - какие к складу;
     - какие к зарплатам;
   - избегать «больших» сущностей, содержащих всё сразу.

3. **Согласование с Loyalty:**
   - покупка абонементов/пакетов фиксируется как аванс/обязательство;
   - списания по пакетам учитываются при расчёте выручки и ЗП (по правилам).

4. **ERP‑UX для админов/owner’ов:**
   - более понятная визуализация потоков:
     - «деньги из визитов»;
     - «ЗП по врачам»;
     - «расход материалов»;
   - быстрые переходы из ERP в конкретные визиты/пациентов/лидов.

### 4. Связи с другими доменами

- **Booking:** источник «события визита» и структуры оказанных услуг.
- **Payments:** фактические платежи/возвраты (YooKassa и др.).
- **Loyalty:** учёт авансов по абонементам/депозитам.
- **CRM:** данные для оценки `actual_value` сделок и LTV.
- **Tasks & AttentionFeed:** генерация задач/attention‑элементов при ошибках ERP (см. уже реализованные `erp_error_code`).
