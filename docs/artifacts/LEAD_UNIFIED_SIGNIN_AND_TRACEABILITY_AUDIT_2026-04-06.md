## 2. Почему были разные URL входа (пациент / админ / основатель)

**Факт из кода (проверено):**

- Пациент: JWT `type` patient, OTP/SMS и OAuth — `POST /v1/auth/*`.
- Сотрудник и **владелец (owner)**: один контур `POST /v1/admin/auth/login`, после входа **RBAC** (`roles`, `permissions`) определяет доступ; отдельного «входа владельца» нет.
- Основатель платформы: отдельный JWT `platform_founder`, `POST /v1/platform/auth/login` (+ MFA) — **изоляция платформенного контура** (ADR-007), не клинический тенант.

**Целевое поведение продукта:** одна **витрина входа** (один публичный URL и единый визуальный язык), внутри — выбор контура или вкладка, без смены домена. Три **технических** сессии остаются (patient / admin / platform_founder), потому что разные криптографические контексты и политики; объединять их в один JWT без архитектурного ADR нельзя.

## 3. Реализация (DEV) — этот коммит

- Канонический URL: **`/sign-in`** (`ROUTE_PATHS.other.signIn`).
- Обратная совместимость: `/login`, `/admin/login`, `/platform/login` → редирект на `/sign-in` с `tab=patient|clinic|founder`.
- Параметр **`returnTo`** (path-only, префиксы `/app`, `/admin`, `/platform`) — возврат после успешного входа сотрудника/основателя; пациент по умолчанию — `/app`.
- UI: общая оболочка Sign-in (бренд, градиент, двухколоночный layout на desktop), вкладки Mantine.

## 4. Дальнейший бэклог (не в этом изменении)
