# ARCH_PHASE_03_OMNI_CHAT_2026 — фаза 3 (роль @ARCH)

> **Ссылка:** `MASTER_PRODUCT_ROADMAP_2026.md` § фаза 3.

## 1. Цель

Омниканал как рабочее место: модалки записи и задач без ухода из чата, сплит-панель, визуальная иерархия, метки AI, интеграция с прайсом/услугами; **RAG только для ассистента клиента**, не для аналитики.

## 2. Границы

Контур **CLIENT** отделён от **STAFF** (фаза 1). Webhook-и провайдеров — подпись, идемпотентность, rate limit.

## 3. Данные

- Сообщения, вложения, статусы доставки (по возможности канала).
- Связь разговора с `patient_id`, `clinic_id`.
- RAG: хранилище документов/чанков клиники при включённом режиме — отдельный подпроект в границах чата.

## 4. Безопасность

PII в чате не в логах; AI-подсказки — audit по политике; запрет утечки данных другого tenant в контекст LLM.

## 5. UI

Фиксированный композер; различие фонов колонок; модалки — центр (`ARCH_CROSS_CUTTING_UI_I18N_2026.md`). Звонок/запись звонка — зависимость от интеграции; может быть GAP после MVP.

## 6. Риски

429 от AI; деградация без ключа — уже заложен fallback в продукте.

## 7. Зависимости

Фаза 2 (карточка записи, пациент); абонементы для контекста скидок.

## 8. Расширение: рабочее место оператора (2026)

Детальная стратегия и целевая архитектура (бек + фронт), gap analysis относительно enterprise-ожиданий и бизнес-ТЗ: **`ARCH_OMNI_AGENT_WORKSTATION_2026.md`**. Промпты для реализации: **`DEV_PROMPTS_OMNI_AGENT_WORKSTATION_2026.md`**.
