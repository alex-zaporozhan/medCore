# ARCH_PHASE_02_CLIENTS_SCHEDULE_2026 — фаза 2 (роль @ARCH)

## 1. Цель

Расписание как операционное ядро: drill-down клиент/мастер, комментарии к записи, ссылка на слот; список пациентов с колонками и фильтром по дате посещения; **абонементы** (коробка) отдельно от программы лояльности Enterprise.

## 2. Абонементы vs лояльность (зафиксированное UI-решение)

**Одна страница, один роут:** `/admin/loyalty`. Внутри — **две вкладки:** «Абонементы» | «Лояльность».

| Концепт | Коробка | Enterprise |
|---------|---------|------------|
| Вкладка **Абонементы** (пакеты, списание) | Видна | Видна |
| Вкладка **Лояльность** (баллы, уровни, сложные правила) | **Скрыта** (издание Box) | Видна |

Доменно — **общий** backend-модуль; различие изданий — feature flag / RBAC + условный рендер второй вкладки. Прямые ссылки: при необходимости `?tab=subscriptions` / `?tab=loyalty` (уточнить в реализации).

## 3. Данные

- Запись: комментарий админа, индикатор на сетке; связь patient/doctor/resource.
- Рабочие места: `resource_id` на слоте — см. IA салона.
- Пациенты: фильтр «были в интервале дат».

## 4. Мультитенантность

Все запросы расписания и пациентов — с `clinic_id`; публичная запись — валидация принадлежности слота клинике.

## 5. Безопасность
