# Enterprise: жизненный цикл персонала, «уволен», карточки сотрудника (план)

> **Статус:** не реализовано целиком; часть требований — **коробка + Enterprise**, отдельные эпики.

## Требования продукта (из QA)

1. **Статус «Уволен»** — не физическое удаление записи сотрудника; блокировка входа и деактивация учётной записи (нельзя «подобрать» пароль и зайти).
2. **Опционально «удалить карточку»** — по политике владельца (например, GDPR / право на забвение с оговорками по мед/трудовому учёту).
3. **Карточка персонала** — единая сущность UI для роли (администратор, менеджер, врач, мастер и т.д.): ФИО, телефон, почта, **история работы** (смены, посещения по роли врача/мастера, привязка к рабочему месту для салона красоты).
4. **Рабочие места / столы** — для маникюрных и аналогичных сценариев: место ведёт к **расписанию записи клиентов** и к ресурсам; отдельный эпик по **ресурсам расписания** (см. `docs/artifacts` / roadmap).

## Текущая связь с кодом

- Сотрудники админки — сущность `admins` с `clinic_id`, email, `full_name`; мягкое удаление `deleted_at`.
- **Коробка (реализовано):** поле `employment_status` (`active` | `terminated`), отказ во входе в `POST /admin/auth/login`, проверка в `get_current_admin`; при увольнении — `PATCH /admin/admins/{id}` с `employment_status: terminated` и снятие участия во всех комнатах внутреннего чата (`StaffCollaborationService.revoke_staff_chat_memberships_for_admin`).
- **Дальше (Enterprise / карточки):** история смен, рабочие места, отдельный UI карточки — отдельные эпики.
- Карточки и учёт смен — **новые таблицы** и экраны (не смешивать с одним только полем в `admins`).
