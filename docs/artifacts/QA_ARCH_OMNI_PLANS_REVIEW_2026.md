# @QA_ARCH: проверка архитектурных планов омничата (соответствие целям и ответственному продукту)

> **Дата:** 2026-03-25  
> **Объект:** `QA_ARCH_OMNI_CHAT_ENTERPRISE_ASK_ARCH_BIZ_2026.md`, `BIZ_TZ_OMNI_UNIFIED_INBOX_FOR_ARCH_2026.md`, `ARCH_OMNI_AGENT_WORKSTATION_2026.md`, `DEV_PROMPTS_OMNI_AGENT_WORKSTATION_2026.md`, связь с `ARCH_PHASE_03_OMNI_CHAT_2026.md`

---

## 1. Вердикт

Пакет документов **в целом соответствует** целям исходного запроса @QA_ARCH и бизнес-ТЗ @BIZ: зафиксирован **gap** по чату, **учтена существующая модель** (один открытый чат на контакт, канал на сообщении), заданы **приоритеты Must/Should/Could** и **путь для @DEV**. Для критериев **ответственного продукта** (безопасность, наблюдаемость, приватность, снижение рисков) план **сильный в операционной и продуктовой логике**, но **недостаточно явно закрепляет** ряд security/realtime/RBAC деталей — ниже раздел 4 и рекомендации.

## 2. Соответствие целям (матрица)

| Цель (источник) | Покрытие в планах | Оценка |

## 3. Дыры в чате (продукт / UX) — закрытие планами

| Дыра | Отражено в планах? |
|------|---------------------|
| Исходящее в «не тот» канал (риск для пациента) | **Да:** Must — OutboundPolicy, `reply_channel_id`, last-inbound default (`ARCH_OMNI`, `DEV_PROMPTS` P0) |
| История не читается (только последние N в UI) | **Да:** Must — cursor `before` на фронте (`DEV_PROMPTS` P0) |
| Нет realtime — устаревшая лента | **Да:** Should — SSE + тонкий payload (`ARCH_OMNI`, `DEV_PROMPTS` P1) |
| Нет «кто ответил» для аудита | **Да:** Should — `sender_admin_id` (`ARCH_OMNI`) |
| SLA/очередь/назначение | **Да:** Should — assignee, поля SLA (`ARCH_OMNI`, `DEV_PROMPTS` P1) |
| Дублирование `admin/chat` vs `omni-chats` | **Да:** риск + tech debt (`ARCH_OMNI` §6, `DEV_PROMPTS` P2) |
| VIP / оплата в UI | BIZ требует; **в ARCH** — не в Must таблице как отдельная фича данных | **Частично** — нужна явная связь с источником данных (CRM/ERP) или «отложено до API» |

## 4. Безопасность, приватность, злоупотребления (ответственный продукт)

| Тема | Есть в планах? | Замечание |
|------|----------------|-----------|
| Мультитенантность | BIZ §5; регрессия в `DEV_PROMPTS` | **Хорошо** |
| PII не в логах | BIZ §5; `ARCH_OMNI` InboundPipeline «без PII» | **Хорошо** на уровне принципа; **нет** чеклиста для @DEV (маскирование полей, запрет логирования `content` в middleware) |
| RBAC на PATCH/assignee/макросы | `DEV_PROMPTS` упоминает RBAC для PATCH и макросов | **Частично** — нет единой матрицы «эндпоинт — право» |
| SSE/WebSocket | Тонкий payload без текста сообщения | **Хорошо** — снижает утечку через события |
| Rate limit / злоупотребление админским API | Не раскрыто в omni-планах | **Пробел** — сослаться на существующие rate limits или добавить в Must для send message |
| AI и утечки между tenant | `ARCH_PHASE_03`, `ARCH_OMNI` кратко | **Достаточно** для ссылки; детали — в фазовом документе |

## 5. Критерии «ответственного продукта» — чеклист

- **Прозрачность приоритетов:** Must/Should/Could есть — **да**.  
- **Трассируемость до кода:** gap table в `ARCH_OMNI` — **да**.  
- **Тестируемость:** `DEV_PROMPTS` требует pytest, eslint, tenant tests — **да**.  
- **Риски названы явно:** legacy chat, дубликаты чатов, нагрузка realtime — **да**.  
- **Безопасность по умолчанию:** частично — усилить RBAC/PII в промптах или отдельным § в `ARCH_OMNI`.  
- **Наблюдаемость:** метрики SLA/доставки заявлены — **да**; SLO/алерты не заданы (нормально для архитектурного уровня).

---

## 6. Рекомендации (минимальный набор)

1. **Дополнить `ARCH_OMNI_AGENT_WORKSTATION_2026.md` §4.5 «Безопасность и RBAC»:** ссылка на `rbac_matrix` / существующие permissions, требование не логировать `content`, проверка `clinic_id` на `reply_channel_id` (уже в смысле DEV_PROMPTS — формализовать как Must).  
2. **Одна таблица «Enterprise backlog»** (как в исходном QA): колонки возможность / эталон / приоритет / зависимости API-RBAC — можно приложить к `DEV_PROMPTS` или отдельным `OMNI_ENTERPRISE_BACKLOG_2026.md` после приоритизации с @BIZ.  
3. **Эталоны UX:** либо отдельный короткий приложение к `ARCH_OMNI` (таблица 5–7 продуктов × паттерн), либо явная отсылка «out of scope документа, ведётся в …».  
4. **VIP/оплата:** одна строка в `ARCH_OMNI` рисков: «зависит от наличия сигналов в CRM/ERP; до данных — UI placeholder».
