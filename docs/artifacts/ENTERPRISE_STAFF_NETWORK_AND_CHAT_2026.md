# Enterprise: сеть салонов и общий внутренний чат (план обязателен)

> **Статус:** не реализовано в коробке; **входит в контур Enterprise** после явного эпика и ADR.

## Цель

Разрешить владельцу сети (несколько `clinic_id` в одной установке или в облаке) **осознанно** включать режим, в котором персонал **разных** клиник может видеть общие каналы/комнаты (например «Сеть — общий», «Регион — координаторы»), а не только изолированный чат внутри одной клиники.

## Зависимости (блокеры)

1. **Модель организации / сети** — сущность выше `clinic_id` (например `organization_id` или `network_id`), связь клиник с сетью, права владельца сети.
2. **Политика данных** — какие сущности остаются строго per-`clinic_id`, какие могут быть shared (чат, календарь сети, отчёты).
3. **RBAC** — роли «координатор сети», аудит кросс-клиники.
4. **Технически** — использование `clinics.staff_chat_scope = network` (или отдельного флага) **только после** пунктов 1–3; без молчаливого открытия данных между клиниками.

## UI настроек клиники: переключатель `staff_chat_scope` (Enterprise)

**Назначение:** экран настроек клиники (владелец / супер-админ), где **без SQL** задаётся политика внутреннего чата персонала:

| UI (план) | Значение в БД | Когда |
|-------------|----------------|--------|
| Только эта клиника (по умолчанию) | `clinic_isolated` | Текущая коробка; все комнаты внутри одного `clinic_id`. |
| Сеть салонов (общий контур) | `network` | **Только после** реализации модели организации/сети и бэкенда кросс-клиники; до этого переключатель **не показывать** или показывать disabled с пояснением. |

Сейчас колонка `clinics.staff_chat_scope` уже есть в БД (по умолчанию `clinic_isolated`); отдельная страница админки под переключатель входит в **этот Enterprise-эпик** вместе с режимом `network`, чтобы владелец не правил данные вручную.
