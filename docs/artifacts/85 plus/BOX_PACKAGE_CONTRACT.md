# BOX_PACKAGE_CONTRACT

> **Назначение:** коммерческий контракт пакета BOX для салонов и сетей салонов (presale + product truth).  
> **Принцип:** продавать только то, что подтверждено фактами и evidence.

---

## 1) Для кого этот пакет

- Одиночные салоны красоты.
- Малые и средние сети салонов, которым нужна операционная стабильность без enterprise-overhead.

---

## 2) Коммерческое обещание BOX (value proposition)

1. Надёжная запись и расписание.
2. Управляемые напоминания и снижение no-show.
3. Базовая CRM/аналитика владельца с практической пользой.
4. Быстрый запуск и предсказуемый onboarding.

---

## 3) Product scope: что входит / не входит

| Контур | Входит в BOX | Не входит в BOX |
|--------|---------------|-----------------|
| Booking/Schedule | Да: запись, слоты, базовые ограничения от дублей | Сложные enterprise-сценарии capacity governance |
| Notifications | Да: базовые напоминания и операционные уведомления | Глубокая кастомная orchestration per enterprise policy |
| CRM | Да: карточка клиента, история, базовые воронки/сегменты | Расширенные enterprise-only CRM модули |
| Reports | Да: базовые owner-метрики салона | Тяжёлые enterprise owner-attribution/ROI-слои (если policy ограничивает) |
| RBAC/Edition | Да: роли коробочного уровня + server-side box policy | Enterprise entitlement profile и расширенная governance-матрица |
| Integrations | Да: стандартный набор интеграций коробки | Глубокие корпоративные интеграции с кастомным SLA |
| Compliance | Базовый operational уровень | Полный enterprise compliance stack |

---

## 4) SLA/SLO обещание для BOX (публично продаваемое)

| Метрика | Обещание BOX | Условие валидности |
|---------|---------------|--------------------|
| API availability (рабочее окно) | >= 99.5% | При штатной инфраструктуре и соблюдении runbook |
| p95 latency (ключевые не-AI ручки) | <= 500ms | Для согласованного коробочного набора сценариев |
| Error rate на критичных ручках | < 1% | По релизной ветке с активными quality gates |
| MTTR (P1/P2) | <= 60 мин | При включённом мониторинге и эскалации |
| Restore readiness | минимум 1 подтверждённый drill/месяц | Ведение DR evidence в ops контуре |

---

## 5) Обязательные доказательства (evidence) перед продажей

1. Закрыты critical runway блокеры для BOX (A1/A2 box-critical).
2. Есть `Release Compliance Report` с уровнем не ниже `C2` для коробочного релиза.
3. Есть design readiness не ниже `D2` для P0 экранов BOX.
4. Есть integration evidence по box-критичным gate-сценариям.
5. Нет открытых L3 рисков по BOX.

Без этих пунктов пакет считается “не готов к честной продаже”.

---

## 6) Стоп-обещания (что нельзя обещать в presale)

1. Нельзя обещать enterprise-функции как часть BOX.
2. Нельзя обещать “безрисковую кастомизацию под любой процесс”.
3. Нельзя обещать compliance-уровень enterprise без подтверждённых доказательств.
4. Нельзя обещать Box-функции, если server-side policy их реально ограничивает.

| Уровень | Условие | Решение |
|---------|---------|---------|
| B0 | Есть открытые critical разрывы | Не продавать |
