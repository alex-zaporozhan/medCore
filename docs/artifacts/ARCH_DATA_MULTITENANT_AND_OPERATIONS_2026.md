# ARCH_DATA_MULTITENANT_AND_OPERATIONS_2026 — данные, мультитенантность, операции (роль @ARCH)

> **Назначение:** фундамент для **коробки и Enterprise**: даже «один салон» в коробке проектируем как **tenant = клиника/салон** с возможностью **многих** клиник в одной установке без переделки схемы.

---

## 1. Мультитенантность

| Принцип | Реализация |
|---------|------------|
| Граница tenant | **`clinic_id`** (или эквивалент) на всех бизнес-строках; отсутствие «глобальных» данных без явного системного назначения |
| Запросы | Любой read/write по домену — с фильтром tenant; RBAC не заменяет фильтр на уровне сервиса |
| Супер-роль | Только явные маршруты «все клиники» с аудитом; по умолчанию JWT одной активной клиники (текущая модель — эволюция к мультиконтексту в Enterprise) |
| Коробка | Несколько клиник в одной БД — **норма**; изоляция данных обязательна так же, как в Enterprise |

**Риск:** забытый `clinic_id` в новом эндпоинте → утечка. Митигация: код-ревью, негативные тесты, опционально middleware/dependency «текущая клиника».

---

## 2. База данных и миграции

| Принцип | Реализация |
|---------|------------|
| Схема | Alembic — единственный источник DDL; совместимость expand/contract при возможности |
| Индексы | Составные индексы с `clinic_id` для списков и отчётов |
| Конкурентность | Критичные инварианты (слот, оплата) — уникальные ограничения / транзакции (см. QA_ARCH §7) |

---

## 3. Резервное копирование и восстановление

| Принцип | Реализация |
|---------|------------|
| Backup | Регулярный `pg_dump` (или политика облака); сроки хранения — в runbook |
| Restore | Документированный сценарий; drill на staging — см. `SME_BOX_NFR_CHECKLIST.md` |
| После restore | Проверка `alembic_version`, smoke, **изоляция** — не подмешивать чужой tenant |

**Примечание:** Redis/Celery — по необходимости сброс очередей после восстановления; описать в runbook.

---

## 4. Безопасность данных

| Тема | Минимум |
|------|---------|
| Секреты | Не в репозитории; разные ключи staging/prod |
| PII | Маскирование в логах; доступ к телефонам по роли |
| Аудит | Админские действия с tenant и actor — для расследований (наращивание по фазам) |

## 5. Масштабирование (ориентир)

Коробка на одном хосте: пул соединений БД, воркеры Celery, Redis — мониторинг насыщения (полный SLO — Enterprise).
