# PRODUCT_PASSPORT_UX_DESIGN_BACKEND_2026 — UX, дизайн, бэкенд

> **Назначение:** единый паспорт для дизайна и реализации ключевых экранов и контуров (без дублирования мастер-роадмапа).  
> **Связь:** `MASTER_PRODUCT_ROADMAP_2026.md`, `PRODUCT_IA_RBAC_NAVIGATION_2026.md`.  
> **Сквозные инварианты UI:** центрированные модалки-карточки и русский язык интерфейса — `ARCH_CROSS_CUTTING_UI_I18N_2026.md` (канон при конфликте с черновиками ниже).

---

## 1. Дизайн-система и визуальная иерархия

### 1.1. Принципы

- **Нежные**, дифференцирующие оттенки для сообщений (клиент / админ / AI), без «радуги».
- Чёткое **разделение колонок:** список диалогов | активный чат | опциональная правая панель («планшет»).
- **Фиксированный** композер сообщений (нижний бар); скролл только в области истории.

### 1.2. Смайлики и emoji

**Проблема:** крупные системные emoji ломают верстку.

**Направление:**

- Единый класс для inline-emoji (например `font-size: 1.125rem; line-height: 1; vertical-align: -0.05em`) в зоне чата и ленты.
- Пикер стикеров (если есть `/admin/stickers`) — ограничить размер превью; не наследовать `font-size` от заголовков.
- Для богатого контента ленты — превью изображений/видео с **object-fit** и max-height.

### 1.3. Омниканал (`/admin/omni-chat`)

| Требование | UX |
|------------|-----|
| Разделение фона | Левая колонка списка — слегка отличающийся фон от области чата; вертикальный разделитель. |
| Поиск по контактам | Ширина поля поиска **не шире** колонки списка диалогов (выровнять с сеткой). |
| Верхняя панель (режим AI, статус) | Визуально отдельная «панель инструментов»; кнопки согласованы по размеру с нижним баром. |
| Сообщения AI | Отдельный нейтральный фон + метка «AI»; не смешивать с сообщениями человека. |
| Сплит-экран | Правая зона: drag-and-drop второго диалога **или** карточка клиента **или** Kanban **или** история звонков; кнопка «свернуть» в полноэкранный один столбец. |

### 1.4. Лента сотрудников (`/admin`)

- Верх: **сохранить** KPI-карточки (как сейчас).
- Низ: лента постов (текст, вложения, комментарии); политики: кто может постить (владелец / менеджеры / все), комментарии вкл/выкл — настройки в разделе владельца.
- Блок «Записи на сегодня» с дашборда **убрать** (дублирует расписание).

## 2. Уведомления (продукт)

| Канал | Событие | Звук |
|--------|---------|------|
| 1 | Лента: пост, упоминание, комментарий | `sound_feed` |
| 2 | Внутренний чат: личное / группа | `sound_staff` |
| 3 | Календарь и задачи: дедлайн, совещание, назначение исполнителем | `sound_task` |

Реализация: Web Audio или короткие файлы + user preference в профиле; визуально — toast + бейдж в сайдбаре.

---

## 3. Канбан (`/admin/tasks`)

- Колонки **настраиваемые** (разделы).
- Карточка: цвет по **остатку времени** до дедлайна (зелёный → жёлтый → оранжевый → красный; голубой — без срока; отдельный акцент для «срочно»).
- Модалка: постановщик (кликабельный), исполнители, сроки, просрочка, **чат задачи**, ссылка «добавить в календарь».
- Поиск по названию / постановщику / исполнителю.
- Бейдж непрочитанных в колонке при сообщениях в чате задачи.

---

## 4. Календарь (новый модуль)

- События, напоминания, дедлайны из задач (синхронизация одним направлением или двусторонняя — уточнить в реализации).
- Совещание: приглашённые участники из списка персонала, напоминание за 15 минут всем, кнопка «Подтвердил просмотр» у создателя.

## 5. База знаний

- Разделы/папки; вложения PDF, видео, презентации.
- **Изоляция по роли/профессии:** контент админов / мастеров / менеджеров — разные корневые разделы; RBAC на уровне API и UI.

## 6. Бэкенд — крупные сущности (ориентиры)

Без привязки к конкретным именам таблиц в этом паспорте; детали — в архитектурных ADR задачах.

| Контур | Сущности / сервисы |
|--------|-------------------|
| Лента | `posts`, `comments`, `attachments`, `policies` (кто может постить) |
| Чат персонала | `conversations`, `participants`, `messages`, `groups` |
| Календарь | `calendar_events`, `meeting_attendees`, `reminders` |
| Задачи | расширение существующих tasks: `assignees`, `task_messages`, `columns` |
| Знания | `knowledge_folders`, `documents`, `role_binding` |
| Омниканал | существующий поток + модалки записи/задач/скидки (вызовы API визитов) |

**Идемпотентность** на критичных write (запись, оплата) — в соответствии с roadmap NFR.

---

## 7. AI (ограничение scope)

- **Чат с клиентом:** режимы выкл / подсказки / автоответ (по политике клиники); визуальная маркировка AI.
- **RAG:** только для контекста ассистента (FAQ, прайс, расписание из структурированных данных или загруженных документов); **не** для аналитики в коробке.
- Тяжёлая страница **Retention** с ROI — не входит в коробку.

---

## 8. Практические улучшения (только с явной пользой)

- **Быстрые действия из чата:** запись, задача, отправка карточки услуги из единой библиотеки услуг.
- **Шаблон ответов** для админа в омниканале.
- **Глубокая ссылка на слот** расписания для клиента/коллеги.
