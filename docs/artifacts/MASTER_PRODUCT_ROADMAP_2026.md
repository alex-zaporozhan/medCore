# MASTER_PRODUCT_ROADMAP_2026 — интегрированный план продукта

> **Статус:** единый источник правды для глобальной реализации после консолидации ТЗ (сотрудники / клиенты / аналитика / владелец / настройки), согласован с **Variant 2**: сначала усиление базы и продукта, затем **пауза** и выпуск **базовой коробки**, после — Enterprise без упрощения основной кодовой базы.  
> **Связь с NFR:** `SME_BOX_NFR_CHECKLIST.md` (коробка), `docs/NONFUNCTIONAL_SCORECARD.md` + `docs/artifacts/85 plus/QA_ARCH_85_PLUS_ROADMAP.md` (целевой Enterprise-уровень).  
> **AI:** RAG и тяжёлая аналитика **не** в коробке v1; RAG — в рамках **ассистента в чате с клиентом** (и смежные grounded-ответы), см. фазу 7.

---

## 1. Принципы

1. **Одна кодовая база**, издания: **Enterprise** (полный функционал) и **Box** (feature flags / конфиг / compose-профиль), без обязательного форка репозитория.
2. **Социальный слой сотрудников** (лента, внутренний мессенджер, календарь, канбан с чатом задачи) — **база и для Enterprise**, не «упрощёнка только для коробки».
3. **Разделение контуров:** персонал (внутренняя сеть) / клиент (омниканал + PAW) / маркетинговый контент для клиента — отдельные продуктовые поверхности с единым RBAC.
4. **Коробка** продаётся с **простой аналитикой** (выручка, визиты, разрезы по специалистам и статусам клиентов) **без** LTV/ROI и без AI в аналитике.
5. **Абонементы** входят в коробку; **программа лояльности** (баллы, сложные уровни) — **Enterprise**. UI: **одна страница** `/admin/loyalty`, вкладки «Абонементы» / «Лояльность»; в коробке вторая вкладка скрыта — см. S-02.
6. **Сквозные векторы UI (все фазы):** центрированные модалки-карточки; **только русский** язык в пользовательском интерфейсе (кроме технических терминов вроде API) — `ARCH_CROSS_CUTTING_UI_I18N_2026.md`.
7. **Архитектура по фазам (@ARCH):** `ARCH_INDEX_PHASES_2026.md` (P0–P7); данные и мультитенантность: `ARCH_DATA_MULTITENANT_AND_OPERATIONS_2026.md`.

## 4. Разрешение «придатков» и дублей меню (план)

| Артефакт / роут | Решение |
|-----------------|--------|
| `/admin/attention` «Лента внимания» | Объединить с **Лентой сотрудников** на `/admin` или удалить отдельный пункт; бэкенд attention можно кормить виджетами в ленте или отключить дублирующий UI. |
| `/admin/dashboard` | Становится **«Лента»**: KPI карточки сверху, лента постов снизу; блок «Записи на сегодня» убрать с этой страницы (запись — в Расписании). |
| `/admin/channels` vs `/admin/omni-channels` | Одна **каноническая** страница настройки каналов/API; вторую удалить или редирект, функции не дублировать. |
| `/admin/client-reference` | Аудит: если нет функционала — удалить роут и пункт меню. |
| `/admin/recall` | Целевое ядро **рассылок** для коробки: сегменты/шаблоны/кампании; довести до работающих мутаций (см. раздел 6). |
| `/admin/retention` | **Enterprise:** Smart Retention, AI, ROI — в коробке скрыть или показать заглушку «недоступно в редакции Box». Не путать с Recall. |
| `/admin/marketing` | Перепрофилировать под **баннеры/контент PAW** (как в ТЗ), не «лента клиента» как сейчас по смыслу. |
| Дубль «Настройки» в левом меню | Убрать дублирование пунктов — одна точка входа. |

### 4.1 Статус P1 Staff Core (зафиксировано в репозитории)

| Решение §4 | Статус |
|------------|--------|
| `/admin/attention` → единая лента на `/admin` | **Сделано:** редирект в роутере; виджет ленты внимания на `/admin`; отдельная страница удалена. |
| `/admin` «Лента»: KPI + посты; убрать «записи на сегодня» | **Сделано:** три KPI (выручка, новые пациенты, отмены/неявки); подсказка про «Расписание». |
| Дубль «Настройки» в левом меню | **Сделано:** в боковом меню одна точка входа «Настройки» → `/admin/settings`; каналы, интеграции, касса, формы и др. убраны из сайдбара и перечислены на странице хаба. |
| Остальные строки таблицы §4 (channels vs omni как канон, client-reference, recall, …) | Без изменений в этом эпике — по отдельным задачам. |

### 4.2 Что значит «вне эпика» для строк §4

Строки про **каналы** (`/admin/channels` vs omni), **справочник клиента** (`client-reference`), **Recall**, **Marketing** и смежные пункты — это **отдельные продуктовые треки** (консолидация настроек каналов, аудит мёртвых роутов, доведение рассылок, перепрофилирование маркетинга). Они **не входили** в закрытый пакет P1 «Staff Core / единая лента на `/admin`» и остаются в бэклоге по своим задачам и PR, а не в одном релизе с лентой и внутренним контуром сотрудника.

Детали по мессенджеру, календарю, Kanban, KB и RBAC: `ARCH_PHASE_01_STAFF_CORE_2026.md` §9. **Сводка «где в коде»** по P1 (репозиторий): `ARCH_PHASE_01_STAFF_CORE_2026.md` §10.

## 5. Роли и видимость (сводка)

Полная матрица: `PRODUCT_IA_RBAC_NAVIGATION_2026.md`.

- **Мастер / врач:** блок сотрудника (лента, внутренний чат, календарь, расписание, зарплата/мои начисления **без** чужих карточек клиентов и без бизнес-аналитики) — настраивается политиками владельца.
- **Администратор:** клиенты, запись, омниканал, задачи; **без** общей выручки/стратегической аналитики — по политике.
- **Маркетолог:** расширенный доступ к маркетингу и отчётам — по политике.
- **Владелец:** полный доступ + раздел «Персонал» и платежи/интеграции.

## 6. Текущее состояние Recall / Retention (факт для плана)

- **Recall** (`AdminRecallPage`): реализованы хуки для сегментов, шаблонов, кампаний, автоматизаций; триггер в UI в основном `days_after_visit`. Если кнопки «не работают», нужна отладка цепочки: **RBAC на API**, ошибки мутаций в сети, пустой `clinicId`, или незавершённые backend-хендлеры — отдельный техдолг в рамках **фазы 4**.
- **Retention** (`AdminRetentionPage`): задокументирован как **Фаза 5**, AI/ROI/каскады — **не** целевой функционал коробки; UI может быть частично заглушкой.

## 7. Критерий готовности «коробки» (gate)

1. Пройден `SME_BOX_NFR_CHECKLIST.md`.
2. Зафиксирован профиль сборки **BOX** (переменные / флаги: отключены Enterprise-страницы и тяжёлая аналитика).
3. Приёмочный сценарий: онлайн-запись → визит → оплата/лояльность → рассылка по сегменту → базовый дашборд.
4. Документирован список **известных ограничений** v1.
