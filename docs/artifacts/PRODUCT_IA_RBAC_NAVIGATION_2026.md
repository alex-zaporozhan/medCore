## 1. Целевая структура меню (логические блоки)

Нумерация соответствует запросу владельца продукта; подписи — рабочие (RU), пути — текущие или целевые.

### I. СОТРУДНИКИ

| # | Пункт | Роут (целевой / текущий) | Box | Enterprise |
|---|--------|---------------------------|-----|------------|
| 1 | **Лента** | `/admin` (Dashboard → **Лента**): KPI сверху, лента постов и комментариев снизу | Да | Да |
| 2 | **Мессенджер (персонал)** | Новый: `/admin/staff-chat` (или вложенный) | Да | Да |
| 3 | **Календарь** | Новый: `/admin/calendar` — личный + совещания + дедлайны из Kanban | Да | Да |
| 4 | **Задачи (Kanban)** | `/admin/tasks` | Да | Да |
| 5 | **База знаний** | Новый: `/admin/knowledge` — разделы по ролям/профессиям | Да | Да |

**Уведомления:** три отдельных «канала» звука (1 — лента, 2 — внутренний чат, 3 — календарь/задачи) + бейджи; технически — единый сервис уведомлений с типами.

## 3. Матрица ролей (сводная, из ТЗ)

Детальная политика хранится в RBAC; здесь — продуктовые правила.

| Возможность | Владелец | Маркетолог | Админ | Мастер |
|-------------|----------|------------|-------|--------|
| Лента, внутренний чат, календарь, свои задачи | Да | Да | Да | Да |
| Клиенты: список, телефоны, карточки | По политике | Да | Да | **Нет** (по умолчанию) |
| Расписание (полное) | Да | Да | Да | Урезанное (свои слоты) |
| Омниканал с клиентом | По политике | Да | Да | Обычно нет |
| Аналитика выручки сети | Да | Частично | **Нет** (по умолчанию) | Нет |
| Финансы, кассы, интеграция 1С | Да | Нет | Нет | Нет |
| Рассылки, баннеры | По политике | Да | Частично | Нет |
| Настройка персонала и прав | Да | Нет | Нет | Нет |

**Конфиденциальность мессенджеров:** личные и групповые чаты персонала видны только участникам; клиентский чат — отдельный контур (омниканал).

## 4. Салон красоты — доменные нюансы (без новых сущностей в v1)

- **Мастера:** категории (топ / эксперт / мастер) и виды (маникюр, педикюр, ресницы) — атрибуты в профиле мастера + связь «мастер–услуга».
- **Рабочие места:** кресло/кушетка — привязка слотов к `resource`/`station` (эволюция уже существующей модели расписания).
- **Статусы визита:** записан → подтверждён → пришёл → в работе → завершён / не пришёл — цветовая схема на расписании и в списках.
