# Web Push: уточнения для продукта

> Ответы на вопросы владельца: сложно ли сделать, нужна ли платная подписка, когда запрашивать разрешение.

---

## 1. «Сложно» или «невозможно»?

**Возможно.** Web Push в браузерах реализуется стандартными средствами:

- На фронте (PWA): запрос разрешения у пользователя, подписка через PushManager (Service Worker), получение VAPID-ключей с backend.
- На backend: хранение подписок (endpoint + keys) по patient_id, отправка push через библиотеку (например, `pywebpush` в Python) при событии «новое сообщение в чате» или «новость от клиники».
- Ограничения: пользователь может отключить уведомления в браузере или в ОС; в некоторых браузерах/режимах push не приходят. Это не «невозможно», а «зависит от окружения» — как и у любых приложений.

---

## 2. Платная подписка для бизнеса?

**Нет.** Web Push не требует платных сервисов:

- **VAPID-ключи** генерируются один раз на наш backend (библиотека `py_vapid` или аналог) — бесплатно.
- **Доставка push** идёт через инфраструктуру браузера (Google FCM для Chrome, Mozilla для Firefox и т.д.) — для веб-приложений это бесплатно.
- Подписка (subscription) хранится у нас в БД; при отправке мы делаем HTTP-запрос на endpoint подписки с подписанным телом — никакого абонплаты за это нет.

Итого: «Service Worker, подписка, backend» — это наша разработка и хостинг, без покупки отдельного push-сервиса.

---

## 3. Когда запрашивать разрешение на уведомления

Варианты:

| Момент | Плюсы | Минусы |
|--------|-------|--------|
| **При регистрации (сразу)** | Пользователь уже в контексте «получать напоминания и новости». | Может отказать «на всякий случай» до того, как оценит пользу. |
| **При первом входе в чат или после первого сообщения** | Более релевантный момент («хотите получать уведомления о новых сообщениях?»). | Нужна отдельная логика и экран. |
| **При первом открытии раздела «Новости/Лента»** | Логично для «уведомления о новостях клиники». | То же. |

**Рекомендация:** Запрашивать разрешение не при самой регистрации (чтобы не перегружать первый экран), а при первом действии, где уведомления полезны: например, при первом открытии чата или при первом заходе в «Лента»/«Новости». Текст: «Включите уведомления, чтобы не пропустить ответ администратора и новости клиники». Либо добавить в настройки профиля кнопку «Включить уведомления» с тем же запросом. Пациент в любом случае может отключить уведомления в настройках браузера/телефона — мы только инициируем запрос один раз в подходящий момент.

Итог: автоматический запрос «разрешить» в момент регистрации возможен, но лучше привязать к первому использованию чата или ленты; «сразу попросить» при первом входе в приложение после регистрации — тоже допустимый вариант, если хотим максимум охвата.

---

## 4. Связь с планом

- Реализация: Service Worker (уже есть для PWA), эндпоинт сохранения подписки (`POST /api/v1/patient/push-subscription`), очередь отправки push при событиях (новое сообщение в чате, новая новость). Задача уже помечена в REQUEST_BATCH_UI как P1; детальный контракт — в зоне @ARCH при постановке в спринт.
