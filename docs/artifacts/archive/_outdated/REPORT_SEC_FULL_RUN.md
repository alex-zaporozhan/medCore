## Уязвимости (критично / высоко)

1. **Security-тесты не выполнены (окружение)**  
   - Описание: все тесты в `tests/security/*` завершились ERROR из‑за отсутствия БД `dental_booking_test`.  
   - Шаги: `poetry run pytest tests/security/ -v`.  
   - Рекомендация для @DEV: создать `dental_booking_test`, перезапустить `pytest tests/security/`, убедиться, что все проходят. Без зелёных security-тестов деплой не рекомендуется.

2. **Хэширование паролей**  
   - Описание: используется pbkdf2_sha256 (passlib). Стандарт приемлем, но для новых систем часто рекомендуют bcrypt/argon2.  
   - Рекомендация: в бэклог внести рассмотрение перехода на bcrypt или argon2 при смене паролей; текущее решение не блокирует деплой.

## Приоритеты

### До деплоя (обязательно)

- Создать тестовую БД, прогнать `pytest tests/security/` и устранить падения.
- Исправить возврат 401 для всех защищённых эндпоинтов из RBAC_CRITICAL_ENDPOINTS при запросе без авторизации (совместно с QA).

### В ближайший релиз

- Запускать `pip audit` и `npm audit` в CI; критичные уязвимости — обновить или задокументировать риск.
- Проверить фронт на XSS (экранирование вывода) и при наличии форм — CSRF/origin.

### Бэклог

- Усиление хэширования паролей (bcrypt/argon2).
- Явная проверка загрузок файлов (тип, размер, path traversal) и контейнеров (не root).
