# DEV_ARTIFACT_F1_DRAWER — Drawer вместо Modal для создания/редактирования

> **Фаза:** 1  
> **Зависимости:** F0_SHELL  
> **Оценка:** 1–2 дня (зависит от количества форм)

---

## 1. Цель

Заменить все формы **создания и редактирования** сущностей (пациент, запись, врач, услуга, задача, лид, касса, шаблон формы и т.д.) на открытие в **Drawer** справа (`position="right"`, `size="lg"` или `size="md"` для простых форм). Modal оставить только для подтверждений (Confirm/Alert): «Вы уверены, что хотите удалить?», «Сохранить изменения?».

## 4. Пошаговые инструкции

### Шаг 4.1. Определить все места с формами создания/редактирования

**Файл(ы):** Роуты и страницы админки.

**Действие:**

1. Составить список страниц и сущностей, где есть форма «Создать» или «Редактировать»:
   - Пациенты: создание/редактирование пациента
   - Записи (Bookings): создание/редактирование записи
   - Врачи (Doctors): создание/редактирование врача
   - Услуги (Services): создание/редактирование услуги
   - Задачи (Tasks): создание/редактирование задачи
   - CRM/Лиды: создание/редактирование лида (если есть форма)
   - Финансы: кассы, транзакции (формы внесения/изъятия)
   - Формы (Paperless): создание/редактирование шаблона формы
   - Настройки: администраторы, клиники и т.д. — любые формы редактирования сущности
2. Для каждого пункта проверить: открывается ли форма в `Modal` или в отдельной странице. Если Modal — помечать для замены на Drawer.

**Проверка:** Есть список «Сущность — файл/компонент — текущее открытие (Modal/страница)».

---

### Шаг 4.2. Общий паттерн: открытие формы в Drawer

**Паттерн для всех замен:**

1. Вместо `<Modal opened={opened} onClose={onClose} title="...">` использовать:
   - `<Drawer position="right" size="lg" opened={opened} onClose={onClose} title="..." padding="md">` для карточек с вкладками или сложных форм.
   - `<Drawer position="right" size="md" ...>` для простых форм (одна форма без вкладок).
2. Содержимое формы перенести без изменений внутрь `<Drawer>...</Drawer>`.
3. Кнопки «Сохранить» / «Отмена» оставить внутри Drawer (в футере или внизу формы). Закрытие по Escape и по клику вне области уже даёт Mantine Drawer.
4. Если форма открывалась на отдельной странице (например `/admin/patients/new`), решить по архитектуре: либо оставить страницу с формой внутри Drawer на ней, либо открывать Drawer со страницы списка (например `/admin/patients`) и убрать роут `/admin/patients/new`. По ТП предпочтительно: форма всегда в Drawer со страницы списка.

**Проверка:** Один пример формы переведён на Drawer по этому паттерну.

---

### Шаг 4.3. Заменить Modal на Drawer: пациенты

**Файл(ы):** Страница пациентов и компонент формы пациента (например `AdminPatientsPage.tsx`, модалка или отдельный компонент формы).

**Действие:**

1. Найти место, где открывается Modal создания/редактирования пациента (по кнопке «Добавить» / «Редактировать» из таблицы).
2. Заменить `Modal` на `Drawer` с `position="right"`, `size="lg"` (карточка пациента по ТП будет с вкладками — в Фазе 3; пока форма может быть простой, но открывается в Drawer).
3. Убедиться, что `onClose` сбрасывает выбранный id и закрывает Drawer; при открытии для редактирования в Drawer передаётся id и подгружаются данные.

**Проверка:** Кнопка «Добавить пациента» / «Редактировать» открывает Drawer справа; форма видна; закрытие по Escape и по кнопке.

---

### Шаг 4.4. Заменить Modal на Drawer: остальные сущности по списку

**Файл(ы):** Каждая страница из списка шага 4.1, где форма в Modal.

**Действие:**

1. Для записей (Bookings), врачей (Doctors), услуг (Services), задач (Tasks), касс/транзакций (Finance), шаблонов форм (Forms), администраторов и т.д. повторить замену:
   - Найти компонент Modal с формой.
   - Заменить на Drawer `position="right"`, `size="lg"` для сложных форм (несколько полей или будущие вкладки), `size="md"` для простых (одна небольшая форма).
   - Перенести содержимое и кнопки внутрь Drawer.
2. Не трогать модалки вида «Вы уверены, что хотите удалить?» / «Сохранить изменения?» — они остаются Modal (Confirm/Alert).

**Проверка:** Все формы создания/редактирования сущностей открываются в Drawer; диалоги подтверждения остаются Modal.

---

### Шаг 4.5. Единая точка стиля Drawer (опционально)

**Файл:** `frontend/src/theme.ts` или общий layout/провайдер.

**Действие:**

1. Если в проекте задаются дефолтные стили Mantine (например через `MantineProvider` defaultProps или `components`), можно задать для `Drawer` значения по умолчанию: `position="right"`, `size="lg"`, чтобы не повторять в каждом месте. Иначе оставить явные пропсы в каждом использовании (как в шагах 4.3–4.4).

**Проверка:** Drawer везде открывается справа, размер соответствует типу формы.

---

## 5. Критерий приёмки

- [ ] Нет ни одной формы создания/редактирования сущности, открывающейся в центре в Modal (кроме будущих, которые ещё не реализованы — тогда при добавлении сразу использовать Drawer).
- [ ] Подтверждения удаления / сохранения остаются в Modal.
- [ ] Drawer везде `position="right"`; размер `lg` для сложных форм, `md` для простых.
- [ ] Закрытие Drawer по Escape и по клику вне области работает (поведение Mantine по умолчанию).
