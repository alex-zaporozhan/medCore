## 1. Backend — формы и подписи

- [ ] **1.1. “Pending forms before visit” по контексту визита**
  - Сейчас `/patient/forms/pending` возвращает *все активные шаблоны* клиники без учёта визита/истории.
  - Нужен бизнес‑контракт:
    - какие формы обязательны для какого типа визита/услуги/врача;
    - что считается “pending” (нет submission для текущей версии шаблона; не подписано; истёк срок валидности анкеты).

- [ ] **1.2. Привязка submissions к жизненному циклу Booking**
  - Добавить сценарии:
    - автосоздание “checklist” на визит (формы + согласия);
    - запрет/предупреждение при завершении визита без обязательных форм (если бизнес требует).

- [ ] **1.3. Валидация схемы и расширение формата schema**
  - Сейчас валидация минимальная, “schema” — легковесный формат.
  - Хвосты:
    - формализовать формат schema (и версионирование) как источник правды;
    - добавить поддержку валидаторов (min/max, regex, conditional fields) и корректные ошибки для UI.

- [ ] **1.4. Управление чувствительными полями (sensitive)**
  - В `schema` есть флаг `sensitive`, но нет системной политики:
    - маскировка в админ‑просмотре;
    - запрет утечки в AI (AiSanitizer должен уметь исключать данные форм).

- [ ] **1.5. Экспорт в PDF/ZIP**
  - Сейчас `/admin/forms/export` возвращает JSON.
  - Требуется:
    - формат экспорта (PDF и/или ZIP с JSON+подписью);
    - контроль доступа и аудит скачиваний.

## 2. Frontend — UX форм и документов

- [ ] **2.1. Подпись в PWA**
  - В PWA `FormsPage` нет UX для рукописной подписи, хотя backend поддерживает `signature_payload`.
  - Нужны:
    - UI‑виджет подписи (canvas), сбор `signature_payload` + meta;
    - UX‑контроль: форма “требует подпись” → без подписи не отправлять.

- [ ] **2.2. Админ‑просмотр submissions**
  - `AdminFormsPage` показывает submissions, но выводит `template_id`, нет раскрытия “template code/name” и нет просмотра содержимого/подписи.
  - Добавить:
    - просмотр деталей submission (данные формы, подпись, мета);
    - фильтры по пациенту/визиту/типу формы.

- [ ] **2.3. Интеграция в OmniChat**
  - По ARCH: в правой панели OmniChat нужен виджет статуса форм/согласий.
  - Добавить:
    - “Forms status” (какие формы pending/подписаны, версии);
    - кнопки “Отправить анкету/согласие” (генерация ссылки/QR).
