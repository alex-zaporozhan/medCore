# DEV_ARTIFACT_F6_MAGIC — The 1% Magic (Полировка UX)

> **Фаза:** 6  
> **Зависимости:** Фазы 0–5 завершены (Spotlight, Kanban, задачи, Лента внимания, OmniChat в наличии).

---

## 1. Цель

Добавить четыре слоя «магии одного процента»: (1) плавные анимации списков при изменении (Kanban, Лента внимания, список задач); (2) микро-звуки на ключевые события с возможностью Mute; (3) быстрые действия в Spotlight (Создать запись, Создать задачу, Отправить форму) с открытием соответствующих Drawer; (4) опционально — confetti/микро-награда при пустой Ленте внимания и при крупной сделке. Без новых API.

## 4. Пошаговые инструкции

### Шаг 4.1. Установить @formkit/auto-animate и применить к динамическим спискам

**Файл(ы):** `frontend/package.json`, затем страницы с динамическими списками.

**Действие:**

1. Установить зависимость: `npm install @formkit/auto-animate` (в каталоге `frontend`).
2. В `frontend/src/admin/pages/AdminSalesPipelinePage.tsx`: импортировать `useAutoAnimate` из `@formkit/auto-animate`. Для каждой колонки Kanban, в которой рендерятся карточки лидов, обернуть список карточек в контейнер с ref от `const [parent] = useAutoAnimate()`. То есть на контейнер внутри `KanbanColumn` (например `<Stack ref={parent} gap="xs">`) повесить ref из `useAutoAnimate()`. Убедиться, что ключи элементов стабильны (id карточки).
3. В странице задач (`AdminTasksPage.tsx`): если список задач или колонки канбана рендерятся как список — добавить `useAutoAnimate()` на контейнер списка (таблица строк или колонки канбана).
4. На странице Ленты внимания (`AdminAttentionFeedPage.tsx`) и/или в блоке Attention Feed на Dashboard (`AdminDashboardPage.tsx`): на контейнер, в котором рендерятся карточки алертов, повесить `useAutoAnimate()`.
5. При необходимости в расписании (слоты дня): на контейнер записей в слоте можно повесить auto-animate для плавного появления/исчезновения.

**Проверка:** Перемещение карточки в Kanban, добавление/удаление задачи, появление/исчезновение алерта в Ленте — сопровождаются плавной анимацией, без «телепортации».

### Шаг 4.2. Установить use-sound, добавить звуковые файлы и контекст Mute

**Файл(ы):** `frontend/package.json`, `frontend/public/sounds/`, контекст или хранилище для Mute, страницы событий.

**Действие:**

1. Установить: `npm install use-sound` (в каталоге `frontend`).
2. Создать каталог `frontend/public/sounds/`. Положить в него три файла (при отсутствии — использовать короткие бесплатные из OpenGameArt/ Freesound с лицензией, допустимой для проекта):
   - `success.mp3` — короткий приятный тон (завершение визита/задачи).
   - `pop.mp3` — лёгкий pop (drop карточки в Kanban).
   - `notification.mp3` — мягкий bubble (новый алерт в ленте / новое сообщение в OmniChat).
3. Реализовать хранение настройки Mute: в настройках профиля или в `AdminLayout`/глобальном контексте — флаг `soundsMuted` (например в localStorage `admin_sounds_muted`). В настройках (`/admin/settings` или профиль) добавить переключатель «Отключить звуки интерфейса» и сохранять значение.
4. Создать хук или утилиту, например `useSoundEffect(name: 'success' | 'pop' | 'notification')`, которая при вызове проверяет `soundsMuted`; если не muted — воспроизводит соответствующий файл из `/sounds/...` (громкость умеренная, например 0.3).
5. Привязать звуки к событиям:
   - **success:** при успешном завершении визита (Checkout Hub «Завершить») и при закрытии задачи в Done.
   - **pop:** при `onDragEnd` в Kanban, когда карточка успешно перенесена в другой столбец (после оптимистичного обновления или после успешного ответа API).
   - **notification:** при появлении нового элемента в Ленте внимания (если есть реальтайм или при открытии страницы с новыми алертами — один раз); при новом сообщении в OmniChat (если есть событие/подписка) — по контракту текущей реализации.

**Проверка:** При переносе карточки в Kanban слышен pop; при завершении визита/задачи — success; при новом алерте/сообщении — notification. При включённом Mute звуков нет.

### Шаг 4.3. Расширить Spotlight группой «Быстрые действия»

**Файл(ы):** `frontend/src/admin/layouts/AdminLayout.tsx` (или место, где собираются `spotlightActions`).

**Действие:**

1. Добавить группу действий Spotlight с `description` или визуально отделённую группу «Быстрые действия» (например через префикс в id или отдельный массив действий с общим описанием группы).
2. Минимум три действия (по нажатию Enter открывается соответствующий Drawer или переход с открытием Drawer):
   - **Создать запись** — открывает Drawer создания записи (тот же поток, что и с расписания/кнопки «Новая запись»). Если Drawer управляется через роут или глобальное состояние — вызвать открытие (например `navigate('/admin/schedule?openBooking=new')` или вызов setter из контекста).
   - **Создать задачу** — открывает Drawer создания задачи (как со страницы задач).
   - **Отправить форму** — открывает выбор шаблона формы и контекста (можно вести на страницу форм с query-параметром или открыть мини-Drawer выбора шаблона по контракту из Фазы 2).
3. Вставить эти действия в начало списка `spotlightActions` (или сразу после «Спросить AI»), чтобы они были в верхней части Spotlight. Поддержать поиск: при вводе «запись», «задача», «форма» соответствующие действия подсвечиваются/фильтруются (стандартное поведение Spotlight по `label`/поиску).
4. По клику/Enter вызывать существующие обработчики открытия Drawer; не дублировать логику создания — только триггер.

**Проверка:** Cmd+K → ввод «запись» → Enter открывает Drawer создания записи; аналогично «задача» и «форма».

### Шаг 4.4. (Опционально) Gamification: confetti и микро-награды

**Файл(ы):** `frontend/package.json`, страница Ленты внимания, страница CRM/Dashboard.

**Действие:**

1. Установить `react-confetti` (или реализовать лёгкий CSS-эффект «частицы»).
2. **Пустая Лента внимания:** когда админ «разгребал» все алерты (0 алертов в Feed) — показывать Premium Empty State с иконкой (например кубок) и один раз при достижении этого состояния воспроизвести короткий confetti (1–2 секунды). Не повторять при каждом открытии страницы, если состояние уже было пустым (например флаг в sessionStorage или один раз за сессию).
3. **Крупная сделка (опционально):** при переводе лида в этап «Успех» (или аналог) с бюджетом > 50 000 ₽ — лёгкая пульсация золотым цветом по краю экрана или карточки (CSS animation, 1–2 сек). Не обязательно; можно ограничиться только confetti при пустой ленте.
4. Убедиться, что анимации не навязчивы и не блокируют интерфейс (confetti поверх контента, закрывается по таймауту).

**Проверка:** При 0 алертах в Ленте — отображается Empty State с акцентом и однократный короткий confetti. При желании — пульсация при крупной сделке.

## 5. Критерий приёмки

- [ ] Во всех динамических списках (Kanban, Лента внимания, список задач) применён `useAutoAnimate`; перемещение/добавление/удаление элементов плавно анимировано.
- [ ] Установлен `use-sound`; в `public/sounds/` лежат `success.mp3`, `pop.mp3`, `notification.mp3`; звуки привязаны к завершению визита/задачи, drop в Kanban, новому алерту/сообщению; в настройках есть переключатель Mute, при Mute звуки не воспроизводятся.
- [ ] В Spotlight добавлена группа быстрых действий: Создать запись, Создать задачу, Отправить форму; по Enter открываются соответствующие Drawer/потоки.
- [ ] (Опционально) При пустой Ленте внимания — Empty State с кубком и однократный confetti; при желании — пульсация при сделке > 50 000 ₽.
