## FRONTEND_GAPS_Admin_NEXT — админское приложение `/admin`

### 1. Общие наблюдения

- Архитектура админки опирается на `AdminLayout` с боковым меню, ContextBar, Spotlight, Attention‑баром.
- Многие страницы уже используют современный UI (таблицы, EmptyState, PageSkeleton, трёхколоночные layout’ы).
- Одновременно присутствуют:
  - экраны с новым дизайном (Omnichannel, CRM‑board, Finance);
  - экраны с более простым/старым UI или сырым отображением данных (например, статусы как сырой текст).

### 2. Ключевые модули и GAPS

#### 2.1. Booking/Schedule (`/admin/schedule`, `/admin/bookings`, `/admin/waitlist`, `/admin/prepayment`)

- **FADM-1:** требуется унифицированный UX: единая визуализация статусов записей, связка с ERP/CRM; сейчас часть UI отражает только «операционные» детали без бизнес‑контекста.
- **FADM-2:** лист ожидания и политики предоплаты визуально и навигационно отделены от расписания; нужно продумать более цельный UX.

#### 2.2. CRM (`/admin/sales`)

- **FADM-3:** Kanban реализован хорошо технически, но:
  - нужны быстрые переходы в связанные сущности (визиты, платежи, пациенты) из карточки;
  - визуализация «гниющих» лидов и важных сумм может быть усилена (отдельные индикаторы/фильтры).

#### 2.3. Omnichannel & AI (`/admin/omni-chat`, AI‑страницы)

- **FADM-4:** UI собирает Omnichannel в удобный рабочий стол, но:
  - AI‑agent как функция в Spotlight пока отдаёт заглушку — для пользователя это «поломанная» фича;  
  - нужно продумать визуальные оговорки/лейблы «beta» и плавный rollout реального AI‑функционала.

#### 2.4. Finance/ERP (`/admin/finance`)

- **FADM-5:** вкладки «Кассы», «Транзакции», «Зарплаты», «Склад» логичны, однако:
  - мало прямых переходов из ERP к конкретным визитам/пациентам/лидам;
  - требуется более наглядные summary‑блоки для владельца (не только таблицы).

#### 2.5. Loyalty, Forms, Marketing, Tasks, Reports

- **FADM-6:** части этих модулей могут отображать статусы/типы в сыром виде; требуется единый словарь и дизайн для:
  - статусов задач, кампаний, отчётов, форм;
  - inline‑метки (pill‑labels, цветные значки).
- **FADM-7:** навигация между модулями (отчёты → CRM/Booking/ERP, Tasks → доменные сущности) нуждается в систематическом усилении.

### 3. Инварианты для фронтенд‑рефакторинга админки

1. Везде использовать **единые компоненты** для:
   - статусов (включая цвет и иконки),
   - пустых состояний (со смысловыми подсказками о следующем шаге),
   - таблиц/панелей (стили шапок, разделителей, hover’ов).
2. Все high‑level страницы (CRM, ERP, Reports, AttentionFeed) должны позволять переход в детали одним‑двумя кликами.
3. AI‑фичи, находящиеся в состоянии beta/stub, ясно маркируются в UI, чтобы не вводить пользователя в заблуждение.
