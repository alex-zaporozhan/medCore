> Этот документ фиксирует результаты аудита и формирует «мастер‑дорожную карту» апгрейда продукта до премиального уровня.

## 1. Цель апгрейда (бизнес‑уровень)

Сделать из системы записи «Dental Booking» полноценный **Business OS** для клиники/салона:

- **Операционное ядро**: запись, расписание, чаты, уведомления, предоплата.
- **Доход и удержание**: CRM‑воронка, Loyalty, smart‑recall.
- **Управленческий учёт**: ERP (финансы/ЗП/склад) с прозрачной выручкой без дублей.
- **Премиум‑сервис**: Paperless (формы/согласия/подписи), маркетинговая атрибуция и ROI, AI‑агент и AI‑задачи.

Критерии успеха (продуктовые):

- владелец видит **выручку, LTV и ROI** по каналам и сегментам;
- администратор закрывает обращения в OmniChat быстрее (инструменты + контекст + AI‑подсказки);
- клиника может продавать пакеты/баллы без финансовых «провалов» и двойного учета;
- данные защищены: ПДн не утекут в внешние LLM и в логи.

## 2. Системные дыры (кросс‑модульные)

- **2.1. Единый контракт событий (EventBus)**
  - Сейчас события существуют, но требуется «контракт‑источник правды» и фабрики событий.
  - Риск: модули начнут по‑разному трактовать payload → хрупкая интеграция.

- **2.2. Единый контекст доступа (RequestContext)**
  - Есть базовый `RequestContext`, но он должен стать стандартом для модулей V2 и фоновых задач.
  - Риск: расхождение в `clinic_id` и правах в API vs Celery.

- **2.3. Единая политика ПДн для AI**
  - `AiConfigService` и `AiSanitizer` должны быть обязательными для всех AI‑точек (agent/reports/tasks).
  - Риск: утечка ПДн через payload в LLM и audit‑логи.

## 3. Стратегия апгрейда по фазам (рекомендуемо)

### Phase A — «Стабильность и контракты»

- Формализовать event contracts + фабрики.
- Стандартизировать `RequestContext` и RBAC‑проверки.
- Выровнять использование `AiConfigService` и PII‑санитайзинга.
- Привести API к стабильным DTO (убрать «сырые dict» на критичных роутерах).

### Phase B — «Деньги без ошибок»

- ERP: расчёт сумм и edge‑кейсы, транзакционность, понятные ошибки.
- Loyalty: покупка/использование пакетов, оплата баллами, запрет двойного учёта выручки.
- Интеграционные тесты ERP+Loyalty как quality gate.

### Phase C — «Рост и удержание»

- CRM: детерминированные переходы стадий, правильные суммы, OmniChat‑интеграция.
- Marketing Attribution: связывание UTM → Lead → Booking → FinancialTransaction, отчёты ROI.
- Smart‑recall: генерация задач/кампаний на основе лояльности/CRM/ERP сигналов.

### Phase D — «Premium UX»

- Трёхколоночные экраны: OmniChat / CRM / Tasks / Finance.
- Контекстные виджеты: LTV, Loyalty, Forms, Tasks внутри OmniChat.
- Улучшение лендинга и единой дизайн‑системы.

### Phase E — «Paperless + compliance»

- Формы/подписи: конструктор, workflow “pending forms before visit”, экспорт.
- Security/Legal: минимизация ПДн, контроль доступа, аудит.

## 4. Премиум‑сервис (предложения)

Набор «Premium» (как продуктовые пакеты, не только тех. задачи):

- **Premium AI Concierge**
  - AI‑агент в OmniChat: бронирование, подбор альтернатив, мягкая эскалация на оператора.
  - Аудит `AiToolEvent` + объяснимость действий.

- **Premium Revenue Intelligence**
  - ROI по каналам + LTV сегменты + «качество трафика».
  - Авто‑задачи на удержание и рост (AI Task Generator + system tasks).

- **Premium Paperless**
  - Формы/согласия/подписи + экспорт PDF/ZIP.
  - Виджет статуса согласий в OmniChat и before‑visit чек‑лист.
