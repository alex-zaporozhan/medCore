## На потом (@QA_ARCH — предложения)

Рубрика для **будущих итераций** после архитектурного задела PPR‑1: юридически значимая ЭП, реальные провайдеры и эксплуатация. Не дублирует §6 TASKS — фиксирует **риски и качество**, которые стоит заложить до прод‑релиза ЭП.

1. **Юридический и SEC‑гейт** — отдельное согласование с LEGAL/SEC до включения реальных вызовов провайдера: какие подписи считаются действительными в РФ/регионе, хранение квитанций, сроки хранения, ответственность клиники vs вендора.
2. **Различие «форма signed» vs «ЭП подписана»** — в UI и в `BookingCompletionService` явно правило: при `esign_required=True` нельзя завершать визит/считать документ юридически закрытым только по `FormStatus.signed` без `esign_status=signed` (или согласованного исключения); иначе ложное чувство безопасности для бизнеса.
3. **Колбэки/webhooks провайдера** — идемпотентность, защита от повторной доставки, подпись запроса (HMAC/JWT), allowlist IP, rate limit; отдельные интеграционные тесты на «дубликат signed» и «поздний failed».
4. **Feature flag / kill switch** — быстрое отключение ЭП‑потока при инциденте у провайдера без деплоя схемы БД; понятное сообщение админу и пациенту (не тихий провал).
5. **Контрактные тесты** — песочница провайдера + записанные фикстуры ответов; регрессия при смене версии API провайдера.
6. **Связь с PPR‑2** — матрица: шаблон с `required_for_visit_completion` + `esign_required` + статусы формы; сценарии в `ARCH_DEV_PPR_MODEL_018_TASKS` «На потом» (ревокация после визита и т.д.) согласовать с ЭП‑аудитом.
7. **ПД и логи** — политика: что уходит провайдеру (минимизация), запрет логирования тела формы и токенов подписи в plain text; соответствие `ARCH_DEV_OMNI_POLICY_016` / токенизации при любых AI‑копилотах вокруг форм.
8. **Наблюдаемость** — метрики: время цикла `request_esign` → `signed`, доля `failed`, ошибки провайдера по кодам; алерты для owner.
9. **Эксплуатация** — короткий runbook: «провайдер недоступен», «массовый failed», «откат версии интеграции»; кто эскалирует (on‑call vs вендор).
10. **Гигиена документа** — в файле два полных дубля §1–6 под одним заголовком; при следующей правке TASKS свернуть в одну версию и оставить ссылку на **«На потом»** в конце как единственный хвост для @QA_ARCH / @LEAD.
