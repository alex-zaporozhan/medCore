## Задача 2. Подтверждение переноса записи в расписании

**Цель:** при перетаскивании записи на другой слот (другой врач или время) показывать модальное окно «Вы действительно хотите перенести запись [клиент] на [дата] [время] [врач?]?» и выполнять перенос только после нажатия «Перенести».

### Шаги

1. **Состояние модалки переноса**  
   В `frontend/src/admin/pages/SchedulePage.tsx` завести состояние для «ожидающего подтверждения переноса», например:
   - `pendingReschedule: null | { bookingId: string; toDoctorId: string; date: string; time: string }`
   - При вызове `onReschedule` из `ScheduleCalendarGrid` не вызывать сразу `rescheduleMutation.mutate`, а записать данные в `pendingReschedule` (и при необходимости открыть модалку).

2. **Данные для текста подтверждения**  
   По `pendingReschedule` и `bookings`/`patientNameMap`/`doctors` вычислить:
   - ФИО/телефон клиента (из `bookings` по `bookingId` → `patient_id` → `patientNameMap`);
   - целевую дату и время;
   - имя целевого врача (если `toDoctorId` отличается от текущего врача записи).

3. **Модальное окно**  
   Использовать существующий паттерн модалок (например, `Modal` от Mantine или `GlassModal`). Текст:
   - Если врач меняется: «Вы действительно хотите перенести запись [ФИО/телефон] на [дата] [время] к [ФИО врача]?»
   - Если только время/дата: «Вы действительно хотите перенести запись [ФИО/телефон] на [дата] [время]?»
   Кнопки: **«Отмена»** (очистить `pendingReschedule`, закрыть модалку), **«Перенести»** (вызвать `rescheduleMutation.mutate` с данными из `pendingReschedule`, затем очистить `pendingReschedule` и закрыть модалку).

4. **Интеграция с grid**  
   В пропсе `onReschedule` у `ScheduleCalendarGrid` вызывать не `rescheduleMutation.mutate(...)` напрямую, а установку `pendingReschedule` (и открытие модалки). После подтверждения в модалке — вызов mutation.

**Критерий готовности:** перетаскивание записи в другой слот открывает модалку; отмена не переносит; «Перенести» выполняет перенос и закрывает модалку.

**Файлы:** `frontend/src/admin/pages/SchedulePage.tsx`, при необходимости переиспользуемый компонент модалки в `frontend/src/shared/` или внутри страницы.

## Задача 3. Перенос пункта «Предоплата» в зелёный блок меню

**Цель:** пункт «Предоплата» отображать в блоке «Маркетинг и отчёты» (зелёный фон), а не в «Ежедневная работа».

### Шаги

1. Открыть `frontend/src/admin/layouts/AdminLayout.tsx`.
2. В массиве `navGroups` в группе с `title: "Ежедневная работа"` удалить элемент:
   `{ to: "/admin/prepayment", label: "Предоплата" }`.
3. В группе с `title: "Маркетинг и отчёты"` добавить в массив `items` элемент:
   `{ to: "/admin/prepayment", label: "Предоплата" }`
   (место — например, сразу после «Маркетинг» или по согласованию с дизайном).
4. Сохранить, проверить в браузере: «Предоплата» видна в зелёном блоке, переход на `/admin/prepayment` работает.

**Критерий готовности:** в сайдбаре «Предоплата» находится в блоке «Маркетинг и отчёты».

**Файл:** `frontend/src/admin/layouts/AdminLayout.tsx`.

## Задача 4. Лента внимания: сквозная полоска сверху и переключатель показа

**Цель:** опциональная полоска «ленты внимания» сверху в админке (одно напоминание за раз) и возможность отключить её через меню/настройку.

### Шаги

1. **Данные ленты в layout**  
   В `AdminLayout` (или в обёртке роутов админки) при наличии `currentClinicId` подписаться на данные attention-feed (хук или `useQuery` к `GET /api/v1/admin/clinics/{clinic_id}/attention-feed`). Объединить `follow_up`, `retention_gap`, `conflicts` в один список и выбрать один элемент для отображения (например, первый открытый по приоритету или по дате).

2. **Настройка «Показывать ленту сверху»**  
   Хранить в `localStorage` ключ, например `admin_attention_bar_visible` (значение `"true"` / `"false"`). По умолчанию можно `true`. В меню (в блоке «Маркетинг и отчёты» или в Настройках) добавить пункт — переключатель или ссылку «Скрыть ленту внимания сверху» / «Показывать ленту внимания сверху», меняющую это значение и перерисовывающую layout.

3. **Полоска сверху**  
   Если `admin_attention_bar_visible === "true"` и есть выбранный элемент ленты — под шапкой (или в шапке) отрисовать полоску: краткий текст напоминания (title/description), кнопка/ссылка «Перейти» → переход на `/admin/attention` или в чат (если есть `conversation_id`). Стиль — ненавязчивый, в духе существующей темы (см. `ARCH_FRONTEND_TECH_PASSPORT.md`).

4. **Не ломать страницу ленты**  
   Страница `AdminAttentionFeedPage` и маршрут `/admin/attention` не менять по функционалу (три колонки, закрытие follow-up); при необходимости только поправить импорты/типы, если появятся общие компоненты.

**Критерии готовности:**
- При включённой настройке и наличии элементов ленты сверху отображается полоска с одним напоминанием и переходом в ленту/чат.
- Переключатель в меню скрывает/показывает полоску; состояние сохраняется в `localStorage`.
- Страница «Лента внимания» по-прежнему работает.

**Файлы:** `frontend/src/admin/layouts/AdminLayout.tsx`, при необходимости новый хук или использование существующего для attention-feed (например, в `frontend/src/hooks/useAttentionFeed.ts`), возможно компонент полоски в `frontend/src/admin/components/` или `frontend/src/shared/`.
