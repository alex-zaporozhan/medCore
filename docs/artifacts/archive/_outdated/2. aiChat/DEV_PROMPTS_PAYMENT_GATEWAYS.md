## 2. Текущее состояние страницы

- Select: «Платёжная система» с вариантами ЮKassa, Сбербанк, Тинькофф, Своя.
- Для ЮKassa отображаются поля Shop ID и Секретный ключ; для «Своя» — название. Для Сбербанк и Тинькофф полей нет.
- Бэкенд: в клинике хранятся `payment_gateway`, `payment_gateway_custom_name`, `yookassa_shop_id`, `yookassa_secret_key_encrypted`. Остальные провайдеры не сохраняются.

## 3. Задачи для @DEV

### 3.1. Обязательно: описания и плейсхолдеры для ЮKassa и Custom

- Для полей ЮKassa подставить (или обновить) **description** и **placeholder** из таблицы «ЮKassa» выше.
- Для «Своя касса» добавить **description** к полю названия из таблицы «Своя касса».

### 3.2. Показать поля для остальных касс (Сбербанк, Тинькофф, Robokassa, Stripe, PayPal)

- Расширить `GATEWAY_OPTIONS` (или эквивалент): добавить при необходимости Robokassa, Stripe, PayPal; оставить Сбербанк, Тинькофф.
- Для каждого выбранного значения в Select показывать свой блок полей (как для ЮKassa):
  - **Тинькофф:** Terminal Key, Пароль терминала (с description из таблицы).
  - **Сбербанк:** Логин (UserName), Пароль API.
  - **Robokassa:** Merchant Login, Пароль #1, Пароль #2.
  - **Stripe:** Secret key, опционально Publishable key.
  - **PayPal:** Client ID, Client Secret.
- Поля вводить в state; при сохранении пока отправлять на бэкенд только то, что бэкенд умеет (см. п. 3.4). Остальное можно не сохранять до появления API или сохранять в одном JSON-поле клиники (требует миграции и договорённости с бэкендом).

### 3.3. Одна активная касса — видимость в настройках

- Оставить выбор **одной** платёжной системы (один Select или переключатель между карточками касс). Все перечисленные кассы **видны** в настройках (в списке выбора); активна та, которую пользователь выбрал и сохранил.
- Не реализовывать в этой задаче «несколько касс с выбором по умолчанию» — только одна активная, но список касс полный и у каждой свои поля с подсказками.

### 3.4. Бэкенд (поэтапно)

- **Сейчас:** при сохранении продолжать отправлять в API только `payment_gateway`, `payment_gateway_custom_name`, для `yookassa` — `yookassa_shop_id`, `yookassa_secret_key`. Остальные провайдеры: либо не сохранять, либо добавить на бэкенде хранение (например, отдельная таблица `clinic_payment_gateways` с типом и JSON credentials, или расширение полей клиники). Задача на текущий шаг — **UI и тексты**; сохранение новых провайдеров оформить отдельной задачей после согласования схемы хранения.
