## Техпаспорт фронтенда: Dental Booking

> Стек: Vite + React 18 + TypeScript + Mantine 7 + React Query

Этот документ фиксирует **визуальные и технические решения фронтенда** и служит источником правды для @DEV.

---

### 1. Базовый стек и структура

- **Сборка**: Vite (`frontend/`)
- **UI**: React 18 + TypeScript
- **Компоненты и тема**: Mantine 7 (`frontend/src/theme.ts`)
- **Слой данных**: TanStack Query v5 (`frontend/src/hooks/*`)
- **Стили**:
  - `frontend/src/index.css` — CSS‑переменные, палитра, базовые стили
  - Mantine theme (`appTheme`): палитра `brand`, `fontFamily`

Основная структура описана в `docs/ROLE_FRONTEND.md` и уже соответствует реализованному коду.

---

### 2. Шрифты и лицензии

- **Основной шрифт интерфейса**: `Inter, system-ui, -apple-system, sans-serif`
  - Задан в:
    - `frontend/src/theme.ts` → `fontFamily`
    - `frontend/src/index.css` → `body { font-family: Inter, ... }`
- **Лицензия**: Inter распространяется под **SIL Open Font License 1.1 (OFL)**.
  - Бесплатен для **коммерческого использования** (веб‑приложения, SaaS, мобильные приложения, PDF, печать и т.п.).
  - Можно:
    - встраивать в сайт/приложение;
    - модифицировать и распространять вместе с продуктом.
  - Нельзя:
    - продавать сам шрифт как отдельный продукт;
    - оставлять имя `Inter` у модифицированной версии шрифта (при форке требуется переименовать).
- **Требование к проекту**: отдельная покупка лицензии для Inter **не нужна**. При выкладке онбордингов/бандлов важно не удалять текст лицензии из репозитория шрифта, если он копируется как артефакт.

Если в будущем понадобится сменить шрифт, выбирать только шрифты с открытой лицензией (OFL/Apache/MIT) или системные стеки. Решение о покупке коммерческого шрифта — отдельный согласованный с @BIZ/@LAWYER шаг.

---

### 3. Визуальные решения: фон, паттерны, «осветление» темы

#### 3.1. Общий принцип

- Основа — **спокойная медицинская светлая тема** (палитра уже зашита в `index.css`).
- Тёмные участки (омниканальный чат, панели навигации) **не должны быть глухо чёрными**:
  - использовать тёмные сине‑угольные тона вместо `#000000`;
  - добавлять мягкие градиенты и полупрозрачные слои.

#### 3.2. Фон‑паттерны

- Для «сшивки» страниц используется **единый фоновый слой**:
  - тонкий SVG‑паттерн (точки/диагональная сетка/волны);
  - непрозрачность 2–5%;
  - размещается либо как `background-image` на `body`, либо на корневом `AppLayout`/`AdminLayout`.
- SVG‑паттерн должен быть:
  - самописным или взятым из открытого источника (Public Domain / CC0 / OFL‑совместимая лицензия);
  - захостенным локально в `frontend/src/assets/` и подключённым как обычный ресурс (без удалённых CDN).

Примеры подходящих источников (для вдохновения, не как прямая зависимость): SVGeez, Haikei, простые dot‑patterns с FreeSVG.

#### 3.3. Слои и карточки

- Фон приложения (`--bg-main`) — светлый, чуть «теплее» медицинского серого.
- Основные рабочие блоки:
  - `Paper`/`Card` с `background: var(--bg-card)` и лёгкой тенью;
  - в тёмных разделах — стеклянные панели (полупрозрачный фон + `backdrop-filter: blur`), уже частично реализованные для модалок.

---

### 4. Что считается частью дизайн‑системы

- CSS‑переменные в `index.css`:
  - цвета фона, текста, акцентов (`--bg-main`, `--bg-card`, `--primary`, `--text-main`, `--text-muted` и др.);
  - возможно, переменная `--font-family-app` (переопределяется из настроек клиники).
- Mantine theme:
  - `fontFamily`, `colors.brand`, `defaultRadius`;
  - компоненты с преднастроенными `defaultProps` (`Modal`, `Button` и др.).
- Паттерн фона и градиентные подсветки:
  - реализуются один раз на уровне layout, **не размножаются по компонентам**.

Эти договорённости менять только через правку техпаспорта и согласование с @LEAD/@ARCH.

---

### 5. Ограничения для @DEV

- Не подключать внешние шрифты с неясной лицензией (коммерческие Google Fonts/Adobe Fonts) без отдельного решения @LAWYER.
- Не вставлять крупные SVG/изображения как base64‑строки непосредственно в компоненты — использовать файлы в `frontend/src/assets/`.
- Не добавлять новые глобальные тёмные фоны/градиенты без согласования с @FRONTEND и обновления этого документа.
