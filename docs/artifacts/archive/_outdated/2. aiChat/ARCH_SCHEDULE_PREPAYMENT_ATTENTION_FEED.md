## 2. Задача 2: Подтверждение переноса записи (расписание)

### 2.1. Текущее состояние (по коду)

- **Фронтенд:** `frontend/src/admin/pages/SchedulePage.tsx` использует `ScheduleCalendarGrid` с пропсом `onReschedule`. При `handleDragEnd` в `ScheduleCalendarGrid.tsx` сразу вызывается `onReschedule({ bookingId, toDoctorId, date, time })` без диалога.
- **API:** `PUT /api/v1/admin/bookings/{booking_id}/reschedule` с телом `{ appointment_date, appointment_time, to_doctor_id? }` — уже есть, менять не требуется.
- **Риск:** Случайное перетаскивание записи на другого врача или на другое время без подтверждения.

### 2.2. Архитектурное решение

- Перед вызовом `rescheduleMutation.mutate(...)` показывать **модальное окно подтверждения**.
- Текст: **«Вы действительно хотите перенести запись [ФИО/телефон клиента] на [дата] [время] [к врачу ФИО]?»** (если врач не меняется — не показывать «к врачу» или показать «на другое время у того же врача»).
- Кнопки: **«Отмена»** (закрыть, отмена переноса) и **«Перенести»** (подтвердить → вызвать mutation).
- Реализация только на фронтенде; бэкенд не меняется.

### 2.3. Критерии готовности (задача 2)

- При перетаскивании записи в другой слот (другой врач и/или другое время) перед отправкой запроса показывается модальное окно с однозначной формулировкой (клиент, дата, время, врач при смене врача).
- Отмена в модалке не выполняет перенос; подтверждение выполняет перенос и закрывает модалку.

## 3. Задача 3: Перенос «Предоплата» в зелёный блок меню

### 3.1. Текущее состояние (по коду)

- **Файл:** `frontend/src/admin/layouts/AdminLayout.tsx`.
- Навигация задаётся массивом `navGroups`:
  - Группа 0 — **«Ежедневная работа»** (синий фон `rgba(59, 130, 246, 0.06)`): Дашборд, Расписание, Записи, Единый чат, Очередь, **Предоплата**.
  - Группа 1 — «Справочники».
  - Группа 2 — **«Маркетинг и отчёты»** (зелёный фон `rgba(34, 197, 94, 0.05)`): Маркетинг, Скидки и акции, Recall, Лента внимания, Отчёты.
  - Группа 3 — Настройки.

### 3.2. Архитектурное решение

- Удалить пункт `{ to: "/admin/prepayment", label: "Предоплата" }` из группы «Ежедневная работа».
- Добавить пункт `{ to: "/admin/prepayment", label: "Предоплата" }` в группу «Маркетинг и отчёты» (например, после «Маркетинг» или в другом согласованном месте внутри этой группы).
- Роут и страница `AdminPrepaymentPage` не меняются; меняется только расположение в сайдбаре.

### 3.3. Критерии готовности (задача 3)

- В боковом меню админки «Предоплата» отображается в зелёном блоке «Маркетинг и отчёты», а не в «Ежедневная работа».
- Переход по ссылке «Предоплата» по-прежнему открывает страницу предоплаты.

## 4. Задача 4: Лента внимания — контекст от @BIZ и план

### 4.1. Что такое «Лента внимания» (по коду и логике продукта)

По текущей реализации (бэкенд + фронтенд):

- **Назначение:** это не «планировщик задач» в смысле ручного добавления произвольных дел. Это **автоматически формируемая лента напоминаний** по данным клиники:
  1. **Обещали перезвонить** (`follow_up`) — из чата: сообщения, у которых в БД выставлен `follow_up_at` и не закрыт флаг `follow_up_closed`. Напоминание «пора перезвонить» с привязкой к пациенту и диалогу.
  2. **Давно не были** (`retention_gap`) — пациенты с подтверждёнными/завершёнными визитами и суммой оплат > 0, у которых последний визит был более 6 месяцев назад; сортировка по выручке, топ N.
  3. **Конфликты и жалобы** (`conflicts`) — сообщения пациентов в чате за последние 30 дней, содержащие негативную лексику (жалобы, недовольство и т.п.); по одному пункту на пациента.

- **Как «добавляются» задачи:**
  - **Follow-up:** через чат — оператор выставляет по сообщению «напомнить перезвонить» (дата/время и причина), в БД сохраняются `follow_up_at`, `follow_up_reason`, `follow_up_closed`.
  - **Retention и conflicts:** добавляются только автоматически на основе правил (последний визит, текст сообщений); ручного «добавить задачу» в ленту нет.

- **Где фронтенд:** отдельная страница «Лента внимания» — `AdminAttentionFeedPage.tsx`, маршрут `/admin/attention`, три колонки (Обещали перезвонить / Давно не были / Конфликты и жалобы). Закрытие follow-up — кнопка «Закрыть» по элементу, вызов `close_follow_up` на бэкенде.

- **Итог для @BIZ:** продукт задуман как «лента внимания администратора» по трём автоматическим/полуавтоматическим источникам; ручной планировщик задач в текущей реализации не предусмотрен. «Премиум»-доработка может включать: единую сквозную ленту сверху (по одному напоминанию) и возможность скрыть её через настройку/меню.

### 4.2. Решение @ARCH по доработке (премиум-уровень)

- **Сквозная лента сверху (опционально):**
  - В `AdminLayout` (или в общем layout админки) при наличии данных ленты внимания показывать **полоску/бар сверху** (под шапкой или внутри шапки): по одному элементу за раз (например, самый приоритетный открытый пункт из `follow_up` + `retention_gap` + `conflicts`), с кратким текстом и ссылкой «Перейти» на страницу ленты или в чат.
  - Источник данных: существующий API `GET /api/v1/admin/clinics/{clinic_id}/attention-feed`; на фронте — один общий запрос (например, в layout) с кэшем/интервалом обновления.

- **Управление показом:**
  - В меню (например, в блоке «Маркетинг и отчёты» или в Настройках) — пункт/переключатель **«Показывать ленту внимания сверху»** (вкл/выкл). Состояние хранить в `localStorage` (или в настройках пользователя на бэкенде, если такой сущности уже есть). При выключении верхняя полоска не отображается; страница «Лента внимания» остаётся доступной по пункту меню.

- **Не в scope данной итерации (оставить на потом):**
  - Ручное добавление «произвольных задач» в ленту (отдельная модель и UI) — не планировать в текущем плане.
  - Менять логику формирования follow_up / retention / conflicts на бэкенде не требуется — только фронт: верхняя полоска + настройка видимости.

### 4.3. Критерии готовности (задача 4)

- В админ-панели при включённой настройке отображается сквозная полоска «ленты внимания» сверху (одно напоминание за раз, с переходом в ленту/чат).
- В меню (или настройках) есть возможность отключить показ этой полоски; после отключения полоска не показывается.
- Страница «Лента внимания» (`/admin/attention`) продолжает работать как сейчас (три колонки, закрытие follow-up).
