# TPF_MODULE_CRM — CRM и продажи (Kanban воронка)

> **Префикс TPF_** — Tech Passport Frontend. Модульный техпаспорт.  
> **Связь:** `TPF_MASTER.md` (разд. 4.4), `REV_RAG_MAP_INNOVATIONS.md` (раздел 5).

---

## 1. Назначение

Визуализация денег: лиды как карточки по этапам воронки, с суммами по столбцам и быстрым доступом к чату и предоплате.

---

## 2. Структура экрана

### 2.1. Макет

- Трёхколоночный: слева при необходимости фильтры/метрики, центр — Kanban, справа — Drawer с деталями выбранного лида.
- Горизонтальный скролл. Столбцы = этапы воронки (LeadStage).

### 2.2. Столбцы (колонки)

- В шапке каждого столбца: название этапа, количество карточек, сумма бюджетов. Пример: «Думают (5) — 150 000 ₽».
- Drag-and-Drop карточек между столбцами. При сбросе — оптимистичное обновление и PATCH lead_cards/{id} (stage_id).

### 2.3. Карточка лида

- Отображать: Имя (контакт), Бюджет (ожидаемая сумма), иконка источника (TG, WA, Site), дата последнего контакта, тег «AI Активен» (если бот ведёт диалог).
- **Lead Rotting:** если карточка в этапе «Думает» (или аналог) больше N дней (например 2), карточка визуально «краснеет» (рамка или фон).
- Клик по карточке открывает Drawer справа: история чата + кнопка «Сгенерировать ссылку на предоплату». Опционально: клик по иконке WhatsApp на карточке открывает тот же Drawer с фокусом на чате.

### 2.4. Drawer лида

- Вкладки или секции: Инфо (контакт, источник, бюджет), Чат (встроенное окно или ссылка на OmniChat с этим контактом), Задачи, Заметки.
- Кнопка «Сгенерировать ссылку на предоплату» → ввод суммы → отправка ссылки в выбранный канал (например WhatsApp).

---

## 3. Эндпойнты

| Данные | Метод/путь | Примечание |
|--------|------------|------------|
| Этапы воронки | `GET /api/v1/admin/lead-stages` или из конфига | Список LeadStage для колонок. |
| Карточки лидов | `GET /api/v1/admin/lead-cards` (filter by stage, clinic) | С полями: contact, budget, source channel, last_contact_at, ai_active. |
| Перемещение | `PATCH /api/v1/admin/lead-cards/{id}` (stage_id) | Идемпотентно для Optimistic UI. |
| Агрегаты по этапам | То же API с агрегацией или отдельный endpoint | Сумма бюджетов по stage. |
| Чат, платежи | Omnichannel + Payments | Как в TPF_MODULE_OMNICHAT. |

---

## 4. Правила UI

- EmptyState: если по этапу нет карточек — не пустая колонка, а текст «Перетащите сюда» или минимальный placeholder.
- При пустой доске — EmptyState «Нет лидов» с подсказкой по источникам (чат, сайт).
- Skeleton при первой загрузке колонок и карточек.
- Drawer открывается справа, не перекрывая весь Kanban (или перекрывая только правую часть).
