## ARCH_LOYALTY_NEXT — домен Loyalty & Wallets

### 1. Краткое описание домена

Loyalty‑домен — это **движок лояльности и капитала**:

- пакеты/абонементы (count‑based и balance‑based);
- депозиты и кэшбэк‑кошельки;
- триггеры recall и retention;
- интеграция с ERP (обязательства/авансы) и Booking (списания по визитам).

### 2. Актуальная модель сущностей (по коду / BUSINESS_LOGIC_CURRENT/V2)

По `BUSINESS_LOGIC_V2` и коду (`admin_loyalty.py`, `patient_loyalty.py`, `LoyaltyService`):

- `SubscriptionPackage` — шаблон пакета (тип, цена, срок действия, список доступных услуг).
- `CustomerSubscription` — купленный пакет клиента, статусы `active/frozen/expired/exhausted`.
- `SubscriptionUsage` — история списаний.
- `Wallet` и `WalletTransaction` — кэшбэк и виртуальный баланс (по коду).
- Политики лояльности (`LoyaltyPolicy`) определяют пороги/правила.
- Celery‑таски для проверки истекающих пакетов и снижения активности (частично реализованы).

Frontend:

- `AdminLoyaltyPage.tsx` — управление пакетами, кошельками, политиками.
- `LoyaltyPage.tsx` — PWA‑экран лояльности для пациента.

### 3. Целевая модель vNext

1. **Семейный шэринг и FamilyLink:**
   - сущность `FamilyLink` (или аналог) для связи пакетов с несколькими пациентами;
   - UI и правила списания в многочленной семье (приоритеты, лимиты).

2. **Глубокая интеграция с ERP:**
   - покупка пакета:
     - отражается как `FinancialTransaction` с типом `liability` (обязательство);
   - списание визита из пакета:
     - уменьшает обязательство;
     - начисляет ЗП и отражается в отчётах выручки.

3. **AI‑управляемые триггеры:**
   - фоновые задачи (Celery/beat) находят:
     - истекающие пакеты;
     - неиспользованные депозиты;
     - неактивных, но «богатых» клиентов;
   - передают данные в AI‑слой для генерации персонализированных предложений/напоминаний.

4. **UX для пациента/админа:**
   - пациент видит:
     - оставшиеся визиты/баланс;
     - историю списаний;
     - понятные истечения/рекомендации;
   - админ видит:
     - долгосрочные обязательства (liability);
     - «здоровье» лояльности по клинике.

### 4. Связи с другими доменами

- **Booking:** списание из пакетов/кошельков при завершении визитов.
- **ERP:** обязательства/авансы и их погашение.
- **CRM:** дополнительные признаки сегментации (VIP‑клиенты, high‑LTV, низкая активность).
- **Tasks & AttentionFeed:** генерация задач и attention‑элементов по событиям лояльности (сгорающие пакеты, неиспользованные депозиты).
