# TEMPLATE_DEV_ARTIFACT — Шаблон артефакта пошаговой инструкции для @DEV

> **Назначение:** @ARCH или @LEAD заполняют по этой структуре каждый документ из стека `DEV_STACK_INDEX`. Артефакт даёт @DEV всё необходимое, чтобы **не думать, а выполнять** код по инструкции в рамках уже выстроенной архитектуры.

**Куда сохранять:** `docs/dev_artifacts/DEV_ARTIFACT_<ID>.md` (например `DEV_ARTIFACT_F0_SHELL.md`).

---

## Структура артефакта (копировать и заполнять)

## Правила заполнения (для @ARCH / @LEAD)

1. **Цель** — только то, что делается в этом артефакте. Не расписывать всю фазу.
2. **Входы** — минимум нужных TPF_* и REV_*; разделы указать явно, чтобы @DEV не искал по всему документу.
3. **Шаги:**
   - Нумеровать 4.1, 4.2, …
   - В каждом шаге: **Файл(ы)** (полный путь от корня репозитория), **Действие** (что именно менять/добавлять), **Проверка** (как убедиться, что шаг выполнен).
   - Указывать имена компонентов, пропсы, пути импортов. При необходимости — фрагмент кода или псевдокод в блоке ` ```tsx `.
   - Не оставлять выбор «на усмотрение разработчика»: если цвет/размер заданы в TPF — указать значение (например `dark.8`, `size="lg"`).
4. **Критерий приёмки** — чек-лист, по которому @DEV или @QA может проверить результат без обращения к другим документам.
5. **Объём:** один артефакт = один выполнимый объём (обычно 0,5–2 дня). Если получается больше — разбить на два артефакта.

---

## Связь с DEV_STACK_INDEX

В `DEV_STACK_INDEX.md` для каждого ID указан файл артефакта. При создании нового артефакта:

1. Взять этот шаблон.
2. Заполнить все разделы по правилам выше.
3. Сохранить как `docs/dev_artifacts/DEV_ARTIFACT_<ID>.md`.
4. В DEV_STACK_INDEX в колонке «Файл» путь уже указан; при необходимости обновить статус в разделе «Текущий статус артефактов».

---

*Конец шаблона. Использовать для каждого артефакта из стека @DEV.*
