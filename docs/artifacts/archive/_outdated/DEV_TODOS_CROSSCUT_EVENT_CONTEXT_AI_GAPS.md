## 2. RequestContext

- [ ] **2.1. Расширение использования RequestContext в новых сервисах**
  - Сейчас `RequestContext` используется в AI‑орchestrator и RBAC‑зависимостях, но:
    - не все новые модули (ERP, Loyalty, Tasks, Attribution) принимают `RequestContext` в явном виде в публичных методах.
  - Требуется:
    - пройтись по ключевым сервисам V2 (ERP, CRM, Tasks, Loyalty, Attribution) и либо добавить `ctx: RequestContext` как аргумент, либо гарантировать, что `clinic_id`/права берутся консистентно из уже построенного контекста.

- [ ] **2.2. Фоллбек‑режимы и системные задачи**
  - Явно задокументировать и протестировать поведение `RequestContext` для:
    - системных вызовов (Celery, batch‑джобы), когда нет JWT;
    - сценариев multi‑clinic, если они появятся (как выбирается `clinic_id` для системных задач).
