## 0. Каркас админки (App Shell)

Целевой эталон **Enterprise Pro-SaaS** (навигация отделена от работы):

- **Двудольная схема:** контрастный **тёмный sidebar** (навигация) + **светлый main** (таблицы, формы, карточки).
- **Схлопывание** sidebar до полосы иконок; группировка пунктов по доменам (OPERATIONS, CRM, ERP, SYSTEM и т.д.).
- **Без тяжёлого глобального header:** заголовок страницы и главное действие — в **Context Bar** внутри рабочей зоны.
- **Spotlight / Cmd+K** — глобальный поиск и быстрые переходы (по мере наполнения данными).
- **Светлая рабочая зона (main):** фон не «чисто белый», а **уровень 0** — нейтральный серый (`gray.0` / `#F8F9FA`), чтобы **уровень 1** (карточки, `Paper`/`Card`) читались как белые «листы» с микрограницей и при необходимости лёгкой тенью. Нормы **Crisp SaaS** — **§7**; операционный микро-стиль (скролл, карточки, статусы, типографика, кнопки) — **§9**.

Фактическая разметка и компоненты — сверять с `frontend/src/admin/layouts/AdminLayout.tsx` и проектным паспортом; токены светлой темы и карта файлов — `docs/ARCH_FRONTEND_UI_LOGIC.md`.

## 1. Универсальные законы интерфейса

1. **Relational integrity** — формы не создают «висящие» сущности:
   - **Task:** обязательны `assignee_id`, `due_date`; опционально привязка к пациенту/лиду/записи.
   - **Финансовая транзакция:** `cashbox_id`, `amount`, `type`, `category`.
2. **Drawer > Modal для данных** — `Modal` по центру только **Confirm / Alert**. Создание и редактирование сущностей — в `<Drawer position="right" size="md" | "lg">`, контекст списка сохраняется.
3. **Data density** — таблицы компактные (`verticalSpacing="sm"`); в каждой строке справа **ActionMenu** (три точки) с бизнес-действиями.
4. **EmptyState** — при `length === 0` не пустой экран: иконка, заголовок, описание, **одна CTA** (см. `.cursorrules` и DOMAIN_STANDARDS).
5. **Zero-click context** — на имена пациента/врача и ключевые сущности — `HoverCard` / `Tooltip` с телефоном, LTV, датой визита где уместно (без UUID в UI).
6. **Keyboard** — `Escape` закрывает Drawer; `Cmd/Ctrl+K` — Spotlight (когда подключён). **Omni Chat** (`/admin/omni-chat`, `AdminOmniChatPage`): `mod+J` — фокус поиска диалогов; `mod+Enter` — отправить сообщение; `Escape` — закрыть Drawer формы/задачи; **`mod+shift+l`** — свернуть/развернуть **правый** инспектор «Рабочий центр» (в полях ввода по умолчанию не срабатывает). Канон: `ARCH_FRONTEND_TECH_PASSPORT_DENTAL_BOOKING.md` §2.2.1.

7. **Владельческие отчёты (ERP / аналитика по периодам)** — не смешивать с визуалом маркетинга:
   - Бэкенд может отдавать агрегаты из **витрины** (предагрегат) с fallback на «сырой» запрос; **переносимые** нормы — `docs/TEMPLATE_ERP_REPORTING_VITRINES.md`; контракт и факты этого репозитория — `docs/artifacts/ARCH_DEV_ERP_VITRINES_026.md`, `docs/artifacts/ARCH_PERF_ENGINE_L2_DEEP_2026.md` §6.
   - **UI:** те же четыре состояния (Loading / Empty / Error / Success), см. `ARCHITECTURE_EXCELLENCE_PASSPORT.md` §11. Если API возвращает признак устаревшей витрины (например `aggregate_stale`), допустим **ненавязчивый** индикатор или подсказка «обновить отчёт» (копирайт и размещение — по продукту); **не** показывать пользователю внутренние имена таблиц, Celery или UUID без необходимости.
   - Детализация по экранам финансов/ROI — в `docs/TPF_MASTER.md` §4.6 / соответствующем `TPF_MODULE_*`.

## 2. Модули (ожидаемая режиссура)

Кратко **что** должен уметь экран; детали API — в `docs/artifacts/ARCH_DEV_*` и бэкенд-контрактах.

| Модуль | Суть |
|--------|------|
| **Дашборд** | Метрики; **Attention Feed** (~60%) + таймлайн/карточки дня (~40%). |
| **Омни-чат** | 3 колонки: inbox + диалог + инспектор («Рабочий центр» + вкладки); правый столбец может схлопываться в рейку иконок; действия без ухода со страницы. Факты по сетке, `fluid` main и хоткеям — §2.2.1 проектного техпаспорта. |

| **Формы** | Шаблоны; отправка ссылки из контекста пациента/записи. |

## 3. Обогащённые сущности (вкладки в Drawer)

Правило: карточка сущности **не сводится к 3 полям** — `Tabs` / связанные таблицы по домену.

### 3.1. Пациент

Шапка: аватар, ФИО, контакты, теги, LTV, баланс лояльности при наличии.

| Вкладка | Содержание |
|---------|------------|
| Основное | ДР, пол, категория, согласия ПД, UTM |
| Записи | История визитов |
| Финансы | Платежи, абонементы, остатки |
| Медкарта / заметки | Протоколы, вложения |
| Коммуникации | Уведомления, быстрый переход в чат |

### 3.2. Запись (визит)

| Вкладка | Содержание |
|---------|------------|
| Детали | Пациент, врач, слот, статус визита |
| Услуги и чек | Несколько услуг, скидки, касса |
| Расходники | По техкарте ± ручная правка |
| Задачи | Задачи, привязанные к визиту |

### 3.3. Сотрудник

Профиль, расписание, мотивация (если в продукте), допустимые услуги.

### 3.4. Услуга

Описание, цена, длительность; исполнители; техкарта; флаги онлайн-записи.

### 3.5. Checkout Hub

При завершении визита: услуги/товары, оплата (касса / абонемент), склад расходников в `Accordion` при необходимости.

## 4. Омни-чат (углублённо)

**Факт реализации в репозитории** (`AdminOmniChatPage`, см. также `ARCH_FRONTEND_TECH_PASSPORT_DENTAL_BOOKING.md` §2.2.1, `ARCH_FRONTEND_DESIGN_SYSTEM_MIDNIGHT.md` §5.1):

- **Inbox:** фильтры и превью строк; метастатус (**OPEN**, последний актор, AI) — **компактная одна строка** мельче ФИО/телефона; длинные имена с ellipsis; выделение строки нейтральное (не «primary на всю карточку»).
- **Поле диалога:** ввод, отправка, скрытие сообщений; быстрые кнопки записи/анкеты по контексту.
- **Правая колонка («Рабочий центр»):** быстрые ссылки CRM / Расписание / Задачи; вкладки Клиент / Анкеты / Таймлайн / AI; может **схлопываться** в вертикальную рейку иконок (`localStorage`), горячая клавиша **`Ctrl+Shift+L` / `⌘⇧L`**.
- **Продуктовая цель** (по мере API): бейджи «ждёт ответа» / AI, rich-карточки оплат, идентификация и воронка в инспекторе — без ухода со страницы.

## 5. Микро-интерфакции и ощущение системы

- **TanStack Query:** для DnD и смены статусов — по возможности **optimistic** updates с откатом при ошибке.
- **Загрузка:** **Skeleton** по контуру контента, не полноэкранный `Loader` для списков/таблиц.
- **Spotlight:** расширение режимом «вопрос AI» только при наличии эндпойнта и решении @ARCH (без фоллбека в выдуманные API).

## 7. Светлая тема админки: Crisp SaaS / Enterprise (визуальная иерархия)

**Назначение:** зафиксировать **продуктовый** стиль светлой рабочей зоны (аналог ощущения у Linear, Vercel, Stripe): глубина слоёв, микроконтрасты, иерархия кнопок — без «плоского» серо-белого каша и без тяжёлых сплошных заливок на метриках. Это **не** маркетинговый glass-лендинг (`TEMPLATE_DESIGN_UX.md`), а **операционный** интерфейс.

**Палитра Enterprise 85+:** **Swiss Slate / Ink** — детали токенов, теней и кнопок в `docs/artifacts/85 plus/DESIGN_ENTERPRISE_85_PLUS_CONCEPT.md` **§3.6** (primary `#1c2e45`, единый hue для focus и alpha-слоёв).

### 7.1. Elevation (глубина)

| Уровень | Назначение | Токен / смысл |
|--------|------------|----------------|
| **0** | Фон приложения в зоне main (`AppShell.Main`, при необходимости `body`) | `gray.0` (`#f4f6f8`, Swiss Slate) — **не** `#ffffff` |
| **1** | Карточки, панели контента, основной «лист» | `#ffffff`, обязательная **микрограница** `1px solid` по шкале Mantine `gray-2` (или эквивалент `rgba(0,0,0,0.06)`), иначе белое «плывёт» на сером |

Плавающие слои (модалки, Drawer, дропдауны) используют **слоиcтые** тени из темы (§7.3), а не размытые «пятна».

### 7.2. Границы и карточки

- **`Paper` / `Card`:** по умолчанию с **рамкой** и осмысленным `radius`; тень — умеренная (`sm` и выше по смыслу), согласованная с палитрой теней темы. Цель — эффект «вырезанной бумаги», а не бесконечный flat.
- **Контекст-бар, липкие шапки таблиц:** допустим **light glass** — полупрозрачный белый фон + `backdrop-filter` + нижняя граница (класс/стиль в глобальном CSS, см. репозиторийный паспорт).

### 7.3. Тени (Crisp / layered)

- Избегать **дефолтных «мыльных»** теней; в `createTheme` задавать **многослойные** значения `xs`–`xl` (два слоя `box-shadow` с малыми альфа), чтобы границы модалок и карточек были чёткими.
- Конкретные строки для этого репозитория — в `docs/ARCH_FRONTEND_UI_LOGIC.md` (единая точка синхронизации с `frontend/src/theme.ts`).

### 7.4. Иерархия кнопок

- **Primary (1–2 на экране):** главное действие — `variant="filled"`, акцентный цвет темы — **`brand`** (шкала **Swiss Slate / Ink**, `#1c2e45` на `brand.6`); в коде также доступен алиас `indigo` = та же шкала. Канон: `DESIGN_ENTERPRISE_85_PLUS_CONCEPT.md` §3.6.
- **Secondary / отмена / фильтры:** `variant="default"` — белый фон, видимая серая обводка, текст `gray.7`, при наведении фон `gray.0`; **не** заливать второстепенные действия тем же серым, что и фон страницы.
- **Light / мягкий акцент (опционально):** полупрозрачный фон оттенка primary (`*.0`) + текст насыщенного оттенка — для «Добавить»/вторичного позитивного действия без конкуренции с одной главной CTA.

### 7.5. Навигация (sidebar)

- Активный пункт **не** серой «грязной» подложкой на всю ширину без смысла; целевой паттерн — лёгкий фон оттенка бренда (**`brand.0`**) + текст/иконка **`brand.6`** (ink), либо эквивалент через `indigo.*` (алиас), чтобы активное состояние читалось с первого взгляда.

### 7.6. Дашборд и метрики

- Виджеты метрик — **белые карточки** §7.1 с иконками/бейджами цвета тренда (зелёный/красный и т.д.), без **тяжёлой** сплошной цветной заливки всего блока (исторический антипаттерн «одна синяя простыня»).
- Смысл и доли Attention Feed / таймлайна не меняются (§2); меняется только визуальная лёгкость.

### 7.7. Внедрение в репозиторий

- Точки кода, чеклист для @FRONTEND и согласование с Midnight/Graphite — **`docs/ARCH_FRONTEND_UI_LOGIC.md`**. Промпты и задачи — через `DEV_PROMPTS` / эпики, а не обязательные блоки «ПЕРЕДАЧА @LEAD» из черновиков.

## 9. Premium Micro-Design Codex (Mantine v7)

**Обязательно к применению @FRONTEND при любой вёрстке продуктовых экранов** (`/admin/*`, `/app/*`). Цель: интерфейс ощущается как **дорогое desktop-приложение** (Linear / Stripe / Google Calendar), а не как рыхлый веб-сайт 2010-х.

Связь с остальным техпаспортом: **§7** — токены светлой темы и глобальная тема; **§1–6** — модули и сущности; **ниже** — конкретные паттерны JSX/Mantine. При конфликте формулировок приоритет у согласованного **§7** + `frontend/src/theme.ts`, затем §9.

### 9.1. Правило «Desktop App» (layout и скролл)

- **Никакого глобального скролла страницы** на операционных экранах: чат, календарь (сетка), канбан, плотные таблицы — **запрещено** прокручивать всю страницу целиком как «длинный лендинг».
- **Имплементация:** корневой контейнер рабочей области получает ограничение по высоте, например `style={{ height: "calc(100vh - …px)" }}` или цепочку `flex: 1` / `minHeight: 0` от `AppShell` до целевого блока. Внутри колонки оборачиваются в `<ScrollArea>` там, где нужна прокрутка **только контента** (лента сообщений, тело таблицы, список карточек дня).
- **Шапки колонок** (заголовок чата, заголовок календаря по дням, тулбар канбана) — **вне** `ScrollArea` или с `position: sticky` + нижняя граница, чтобы не «уезжали» при прокрутке.

### 9.2. Правило «вырезанной бумаги» (Crisp Cards)

- **Запрет на грязные «облачные» тени** на обычных карточках в потоке списка/дашборда.
- **Имплементация:** карточка (`Paper`, `Card`) — **белый** фон (`bg="white"` / `#ffffff`), **тонкая** рамка `1px solid var(--mantine-color-gray-2)` (или `withBorder` + токен темы), **минимальная** тень: целевой минимум — `shadow="xs"`; допустимо `sm`, если так задано глобально в теме для `Paper` — но **не** `md`/`lg` на каждой карточке в списке.
- Тени **`md` / `lg` / `xl`** — **только** для модалок, `Drawer`, `Menu.Dropdown`, `Popover`, намеренного hover-elevate на интерактивной плитке (см. §7.3 и `ARCH_FRONTEND_UI_LOGIC.md`).

### 9.3. Правило цветового сигнала (Status Colors)

- **Запрет на тяжёлую сплошную заливку** статусной сущности (запись, задача, событие календаря) на всю глубину карточки.
- **Имплементация (Google Calendar style):**
  - Фон: оттенок **0** палитры статуса, например `bg="orange.0"`, `var(--mantine-color-teal-0)`.
  - Акцент: **левая граница** толщиной **3–4px** цветом **5–6** той же шкалы, например `style={{ borderLeft: "4px solid var(--mantine-color-orange-5)" }}`.
  - Текст: **`c="*.9"`** (например `orange.9`) для основного контента внутри блока.
- Итог: читаемость и «профессиональный» вид без конкурирующих с текстом плашек цвета.

### 9.4. Правило микро-типографики (Data Hierarchy)

- **Метки полей (labels):** мелкие, заглавные, с лёгким трекингом.
  - Пример: `<Text size="xs" tt="uppercase" c="dimmed" fw={600} style={{ letterSpacing: 0.5 }}>Дата визита</Text>`
- **Значения:** контрастные, основной текст.
  - Пример: `<Text size="sm" c="gray.9" fw={500}>25 марта, 14:00</Text>`
- **Группировка:** пара label + value в `<Stack gap={4}>` или `gap={2}` — минимальный вертикальный зазор между подписью и значением.

### 9.5. Правило кнопочной дисциплины (Action Cleanliness)

- **Правило одной primary CTA:** на экране по смыслу **одна** главная кнопка с `variant="filled"` (или `gradient`, если принят в эпике). Остальные действия — `variant="default"`, `light`, `subtle`.
- **Скрытые действия:** если в строке таблицы или карточке **больше двух** действий — второстепенные прячутся в **`Menu`** с триггером `<ActionIcon variant="subtle">` (три точки). Не размножать «Редактировать», «Удалить», «Копировать» в ряд одинаковых кнопок.
- **Иконки** в кнопках: Tabler — **`stroke={1.5}`**; размер `16` или `18` px, не «толстые» 24+ без причины.

### 9.6. Правило «живого интерфейса» (Ghost Hover)

- Интерактивные строки таблицы, список диалогов, карточки лидов/событий должны реагировать на наведение.
- **Имплементация:** `styles` или `className` с `&:hover { backgroundColor: "var(--mantine-color-gray-0)" }` (или `theme.colors.gray[0]`); для кликабельного ряда — `cursor: "pointer"`.

### 9.7. Внедрение в репозиторий

- Глобальные токены — `frontend/src/theme.ts`, `frontend/src/index.css`, `docs/ARCH_FRONTEND_UI_LOGIC.md`.
- Роль **@FRONTEND:** при ревью и спецификациях проверять соответствие **§9** наряду с §7.
