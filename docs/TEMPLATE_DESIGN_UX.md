# TEMPLATE: Дизайн и UX фронтенда — от брифа до готового сайта

> **Назначение:** единственный инженерный чек-лист по визуалу и вёрстке. Закрывает разрыв между «что написано в техпаспорте/бизнес-логике» и «что реально должно появиться на экране».  
> **Для кого:** @FRONTEND, @DEV, Cursor/агенты. Используется вместе с TECHPASSPORT_* и BUSINESS_LOGIC.md.  
> **Версия:** v1.1 | Ориентир: Premium SaaS (Vercel/Stripe/Linear). Референс-реализация: Mantine v7 + index.css, без Tailwind.

## 1. Зачем этот документ

### 1.1. Разрыв, который он закрывает

| Документ | Что даёт | Чего не хватает |
|----------|----------|------------------|
| **TECHPASSPORT_AI_LANDING.md** (и аналоги) | Стек, сетка, имена секций, токены цветов, общие классы (`.section`, `.grid-12`) | **Геометрия:** конкретные радиусы, тени, glow; **композиция:** как выглядит hero (mockup-фрейм, лейбл, CTA); **полосы фона** (banding); **иерархия типографики** в пикселях/rem. |
| **TEMPLATE_BIZ_LOGIC.md** | Суть продукта, пользователь, правила | Ничего про внешний вид и структуру экранов. |
| **ROLE_FRONTEND.md** | Роль, стек по умолчанию (Mantine/Vite), палитра, принципы | Нет пошагового плана «с нуля до готового сайта» и явного перечня **артефактов вёрстки**. |

**Итог:** можно иметь корректный техпаспорт и бизнес-логику, но получить «голый» каркас без визуальной системы — без мягких углов, без выделенного hero-mockup, без чередования фонов и без явной типографической иерархии. Этот шаблон задаёт **что именно нужно спроектировать и проверить**, чтобы сайт выглядел законченно.

### 1.2. Что этот шаблон задаёт

- **Слой дизайн-решений:** токены геометрии (радиусы, тени, отступы), а не только цвета.
- **Пошаговый план сборки фронта:** от токенов → layout → компоненты → секции → движение и полировка → проверка.
- **Формат брифа сайта:** один заполняемый блок (логика, тексты, опциональный референс), по которому Cursor/агент понимает, что строить от А до Я.
- **Критерии готовности** по визуалу и UX на каждом шаге.

## 3. Слой дизайн-решений (что должно быть явно описано)

Чтобы вёрстка не была «калекой», нижеперечисленное должно быть **зафиксировано** (в техпаспорте или в отдельном DESIGN_UX.md проекта).

### 3.1. Токены геометрии и эффектов

Не только цвет. В `:root` (например в `index.css`) или в теме должны быть явно заданы:

| Категория | Переменные (пример) | Назначение |
|-----------|----------------------|------------|
| **Радиусы** | `--radius-sm`, `--radius-md`, `--radius-lg`, `--radius-xl` (8px, 12px, 20px, 32px в референсе) | Кнопки, карточки, mockup, инпуты. Карточки и ключевые блоки — `--radius-lg` / `--radius-xl`. |
| **Тени** | `--shadow-glass`, `--card-glow`, `--card-glow-hover` | Карточки в покое и при hover; сияние акцентное, мягкое. |
| **Свечение** | `--glow-accent` | Hero-пьедестал, акцентные блоки; при hover CTA — лёгкий box-shadow. |
| **Контейнер** | `--max-w-content` (1000–1120px) | Максимальная ширина контента. |
| **Анимации** | `--transition-smooth` (0.4s cubic-bezier), `--reveal-duration`, `--reveal-offset-y` | Единый ритм hover и reveal. |
| **Фоновый паттерн** | Координатная сетка в `.page-gradient::before` (60×60px, линии rgba(255,255,255,0.03), маска по ellipse) | Премиальный «сеточный» фон без точечного шума; плавное растворение к краям. |

**Стек без Tailwind (Mantine):** все токены задаются в `index.css` (`:root`); компоненты Mantine стилизуются через `style`, `sx` или классы, ссылающиеся на эти переменные. Отдельного tailwind.config не требуется.

### 3.2. Композиция ключевых блоков

- **Hero:**  
  - Сетка (например 7/5): слева — заголовок → **крупный подзаголовок** (size xl, ведущий взгляд) → буллеты (List с ThemeIcon-галочкой) → 2 CTA → строка доверия. Текст без излишнего max-width.  
  - Справа (desktop): **пьедестал** — обёртка с классом glass-card, крупный радиус, `box-shadow: inset 0 0 40px rgba(255,255,255,0.02), var(--glow-accent)`; внутри — иллюстрация/mockup по центру.  
  - Фон hero: общий `.page-gradient` + координатная сетка (глобально); дополнительный слой (например `.bg-glow-blob`) допустим для глубины.

- **Секции ниже:**  
  - **Фон страницы единый и бесшовный** — без чередования цвета между секциями («зебра» запрещена, см. п. 3.6). Разделение смысловых блоков — только за счёт вертикальных отступов (padding) и карточек `glass-card`.  
  - Заголовки секций: единый компонент (SectionHeader) с чёткой иерархией (размер, цвет, max-width подзаголовка).

- **Карточки (боли, фичи, шаги, тарифы):**  
  - Единый стиль: фон, граница, **крупный радиус** (из токенов), padding, hover (граница + тень/лёгкий glow).

### 3.3. Типографика по уровням

Зафиксировать в одном месте (техпаспорт или этот шаблон):

| Уровень | Назначение | Пример (Tailwind) | Примечание |
|---------|------------|-------------------|------------|
| **Hero H1** | Единственный самый крупный заголовок | `text-4xl sm:text-5xl lg:text-6xl font-semibold tracking-tight` | Длина строки ограничена (например max-w или ch). |
| **Section H2** | Заголовки секций | `text-2xl sm:text-3xl font-semibold tracking-tight` | Заметно меньше hero. |
| **Card H3** | Заголовки внутри карточек | `text-base sm:text-lg font-semibold` | |
| **Body** | Основной текст | `text-sm sm:text-base text-text-muted` | |
| **Eyebrow / label** | Маленький лейбл над заголовком | `text-[11px] font-medium uppercase tracking-wider` + капсула (border-radius 999px, padding) | |

Шрифт (например Inter) и способ подключения (next/font и т.д.) — из техпаспорта; здесь фиксируется **масштаб и назначение**.

### 3.4. Кнопки и CTA

- **Primary:** заливка акцентом, при hover — светлее + опционально тень/glow.  
- **Ghost / secondary:** прозрачный фон, граница, при hover — фон elevated и граница ярче.  
- Размеры: достаточно двух (обычная и `btn-sm` для хедера). Всё через классы утилит или компонента Button.

### 3.5. Анимации, движение и фоновые слои

- **Появление секций (Reveal):** класс `.reveal` (opacity 0, translateY 30px), при появлении в viewport — `.reveal-visible`. Transition 0.8s, easing из `--transition-smooth`. Хук `useReveal` (IntersectionObserver). Опционально stagger для дочерних элементов.  
- **Hover карточек:** `transition: all var(--transition-smooth)`; при hover — translateY(-4px) scale(1.01), смена границы и box-shadow на `--card-glow-hover`.  
- **Hover кнопок:** плавные border/background/shadow; для header CTA — дополнительно сдвиг иконки-стрелки (translateX(4px)).  
- Фоновый паттерн: малоконтрастный (линии ≤ 0.03–0.05), с маской для растворения к краям.

### 3.6. Протокол премиального фона (обязательно)

- **Единое поле фона:** вся страница имеет один непрерывный фон (например `.page-gradient`: базовый цвет + градиенты + опционально точечная сетка/шум). Резкие горизонтальные переходы цвета между секциями (**«зебра»**) не допускаются — это снижает премиальность и конфликтует с бесшовным паттерном.
- **Секции без собственного фона:** классы `.section` и `.section-alt` задают только **вертикальные отступы** (padding-top / padding-bottom). Фон секций — **прозрачный** (`background: transparent`). Не задавать секциям `background` / `background-color` для чередования полос.
- **Разделение блоков:** визуальное членение страницы достигается **только** за счёт:
  - щедрых вертикальных отступов между секциями;
  - карточек (`glass-card`, ContentCard и т.п.) и контента внутри них.
- В компонентах (App, секции) не прописывать жёстко цвет фона для обёрток секций (например `bg="var(--surface)"` или `backgroundColor` на контейнере секции).

### 3.7. Рекомендуемые технологии (для полноценного Premium SaaS)

- **Стили:** Mantine v7 + один глобальный `index.css` с CSS-переменными. **Tailwind не использовать** — все токены и классы в одном месте, проще поддерживать эталон.
- **Карусели:** `@mantine/carousel` + `embla-carousel-react` + `embla-carousel-autoplay` — плавное автолистание без самописных таймеров; версия carousel должна совпадать с Mantine (v7).
- **Reveal:** хук `useReveal` (IntersectionObserver) + классы `.reveal` / `.reveal-visible`; длительность 0.8s, offset 30px, easing из `--transition-smooth`.
- **Фоновый паттерн:** координатная сетка (два `linear-gradient` 1px в `.page-gradient::before`) с маской ellipse — выглядит дороже точечного шума и не перегружает экран.
- **Иконки:** `@tabler/icons-react`; в премиум-блоках — без заливки фона, тонкий stroke и лёгкий drop-shadow по акценту (например Amethyst/Grape).

## 4. Артефакты, которые должен производить фронт

Чтобы считать фронт «полноценным», а не «калекой», нижеперечисленное должно существовать и быть связанным с токенами.

| Артефакт | Где живёт | Что проверять |
|----------|-----------|----------------|
| **CSS-переменные** (цвета + геометрия + тени + анимации) | `index.css` (`:root`) | Радиусы, тени, glow, icon-contrast, transition-smooth, reveal-*. |
| **Mantine theme** (при использовании Mantine) | `theme.ts` | defaultRadius и цвета согласованы с переменными; Tailwind не обязателен. |
| **Контейнер и секции** | `index.css` | `.container-page`, `.section`, `.section-alt` (отступы 2.5rem → 3rem → 3.5rem по брейкпоинтам). |
| **Фон страницы** | `index.css` + layout | `.page-gradient` (градиенты + bg); `.page-gradient::before` — координатная сетка 60×60px с маской. |
| **Карточки** | `.glass-card` в `index.css` + Paper/Card | Blur 20px, border, shadow, hover (translateY, scale, card-glow-hover). |
| **SectionHeader** | `components/ui/SectionHeader.tsx` | H2 + подзаголовок; выравнивание, типографика из переменных. |
| **Hero** | `components/sections/Hero.tsx` | Grid 7/5; слева — заголовок, подзаголовок, List с ThemeIcon, CTA; справа — пьедестал (glass-card + inset glow). |
| **Карусель** (при наличии) | `@mantine/carousel` + `embla-carousel-autoplay` | Слайды с p="xl" для теней; карточки одной высоты (flex, h="100%"). |
| **Секции контента** | `components/sections/*` | section/section-alt, контейнер, Grid; карточки через glass-card/ContentCard. |
| **Reveal** | `index.css` + хук `useReveal` | .reveal / .reveal-visible; offset 30px, duration 0.8s; IntersectionObserver. |
| **Header** | Fixed, glass (blur 20px, bg rgba), h 70px; лого без тяжёлого фона + дескриптор (desktop) + одна CTA-таблетка; класс `.header-cta` для hover. | main paddingTop ~100px. |
| **Footer** | Граница сверху, контейнер, ссылки/контакты. | |

Если чего-то из этого нет или оно не опирается на токены — фронт считается незавершённым по дизайну.

## 5. Пошаговый план: от нуля до готового сайта

Использовать при старте нового фронта или при доведении «калеки» до полноценного вида. Каждый шаг завершается проверкой критериев перед переходом к следующему.

### Шаг 0. Входные данные (бриф)

- **Логика сайта:** одностраничный лендинг / многостраничный; список секций или страниц; ключевые действия (оставить заявку, перейти в каталог и т.д.).  
- **Тексты:** hero (заголовок, подзаголовок, CTA), секции, футер. Можно в виде списка или в BUSINESS_LOGIC + LANDING_PAGE_*.md.  
- **Референс (опционально):** ссылка на макет или пример (например FlowAI-подобный HTML). Не для копипаста, а для стиля: геометрия, контраст, наличие mockup, типографика.

**Критерий:** по брифу однозначно понятно, какие блоки на странице и какой тон (строгий продукт / мягкий маркетинг и т.д.).

---

### Шаг 1. Токены и базовая тема

**Задача:** завести в одном месте все переменные, от которых зависит вид.

**Действия:**

1. В `globals.css` (или аналоге) в `:root` задать:  
   цвета (фон, surface, текст, акцент, границы), **радиусы** (sm, md, lg, xl), **тени** (soft, strong), **glow** (accent), **--max-w-content**.
2. В `tailwind.config.ts` (если используется Tailwind) — связать `theme.extend` с этими переменными (colors, borderRadius, boxShadow).
3. Задать базовые стили: `html`, `body` (фон, цвет текста, шрифт), при необходимости `scroll-behavior: smooth`.

**Критерий:** смена `--radius-lg` или `--glow-accent` в одном месте потенциально меняет вид карточек и кнопок; никаких «магических» чисел в компонентах для радиусов и теней.

**Результат:** обновлённые `index.css` (или `globals.css`) с полным набором переменных. При использовании Mantine без Tailwind — тема в `theme.ts`, связанная с переменными.

---

### Шаг 2. Layout и сетка

**Задача:** общая оболочка страницы и правила раскладки секций.

**Действия:**

1. Определить контейнер: класс (например `.container-page`) с `max-width: var(--max-w-content)`, `margin: 0 auto`, горизонтальные отступы по брейкпоинтам.
2. Определить сетку: например `.grid-12` (12 колонок, gap), использовать в секциях.
3. Секции: классы `.section` и `.section-alt` — только **вертикальные отступы**; фон у обоих прозрачный (без чередования «зебра», см. п. 3.6).
4. Фон страницы: класс на `body` (например `.page-gradient`) — градиенты; при необходимости псевдоэлемент или отдельный слой с точечной сеткой и/или шумовым PNG/SVG (mask/opacity управляются токенами).

**Критерий:** любая новая секция может быть добавлена по одному и тому же паттерну (section + container-page + grid-12); фон визуально не «плоский лист».

**Результат:** в `globals.css` (или аналоге) и в корневом layout применены контейнер, сетка, секции, фон.

---

### Шаг 3. Базовые UI-компоненты

**Задача:** кнопки, карточки, заголовки секций — с опорой на токены.

**Действия:**

1. **Button:** варианты primary и ghost (и при необходимости outline); размеры; классы из дизайн-системы (радиус, тень при hover).
2. **Card:** фон, граница, **радиус из токена** (например `--radius-lg` или `rounded-2xl` через тему), padding, тень; при hover — смена границы/тени/лёгкий glow.
3. **SectionHeader:** заголовок H2 + подзаголовок; опционально eyebrow; выравнивание и max-width подзаголовка по макету.
4. При необходимости: **Input, Textarea, Label** — единые border-radius и цвета из токенов.

**Критерий:** Card визуально «мягкий» (крупные скругления); кнопки и карточки не используют захардкоженные тени/радиусы.

**Результат:** компоненты в `components/ui/*`, использующие CSS-переменные или классы темы.

---

### Шаг 4. Hero и ключевой визуальный блок (mockup)

**Задача:** первый экран читается как «сцена»: текст + выделенный демо-блок, а не просто две колонки карточек.

**Действия:**

1. **Структура Hero:**  
   - Сетка (например 7/5 или 6/6 на desktop); слева — колонка с eyebrow, H1, подзаголовком, буллетами, двумя CTA, строкой доверия.  
   - Справа — обёртка под «демо приложения» (не просто Card, а отдельный визуальный объект).
2. **Mockup (BrowserFrame / AppPreview):**  
   - Внешняя оболочка: большие скругления (из токенов), граница, тень, опционально glow.  
   - Внутри: «браузерная» полоска (три точки или иконка) + контент (список чатов, диалог, дашборд — по продукту).  
   - На мобильных: mockup под текстом или скрыт; не ломает чтение.
3. **Фон hero:** при необходимости дополнительный слой (пятна, точечная сетка) для глубины.
4. **Типографика hero:** H1 по таблице из 3.3; ограничение длины строки (max-w или ch); подзаголовок и буллеты — читаемый размер.

**Критерий:** при открытии страницы сразу видно «продуктовый» блок (mockup) с мягкими углами и акцентом; текст не упирается в край экрана; на мобильном нет горизонтального скролла.

**Результат:** Hero.tsx + компонент mockup (например ChatCenterDemo внутри BrowserFrame), оба опираются на токены и сетку.

---

### Шаг 5. Остальные секции

**Задача:** все секции из брифа/техпаспорта реализованы с единой геометрией и ритмом.

**Действия:**

1. Для каждой секции: обёртка `section` с id, при необходимости `section-alt`; внутри `container-page` и `grid-12`.  
2. Контент: SectionHeader + карточки/списки через Card; колоночные пропорции по техпаспорту (например 5/7, 4/8).  
3. Формы (заявка, подписка): поля и кнопка в Card; валидация и отправка по API по техпаспорту.  
4. Логотипная полоска, метрики, отзывы, тарифы — те же радиусы и тени, что и в шаге 3.

**Критерий:** фон страницы единый, без горизонтальных полос; все карточки выглядят из одной системы; нет «голых» блоков без скруглений и теней.

**Результат:** все секции из списка в техпаспорте/брифe реализованы и подключены на странице.

---

### Шаг 6. Header, Footer, навигация

**Задача:** фиксированный glass-header и footer в одном стиле с остальной страницей (Premium SaaS).

**Действия:**

1. **Header:**

   - Внутри: Container (maxWidth из переменной), Group justify="space-between".  
   - Слева: логотип (иконка без заливки фона, например IconCpu) + название + дескриптор только на desktop (visibleFrom="sm").  
   - Справа: одна CTA-кнопка-таблетка (radius="xl", полупрозрачный фон, граница, rightSection — стрелка с классом `.cta-arrow`). В CSS: `.header-cta:hover` — акцентная граница, лёгкий glow, сдвиг стрелки.  
2. **Компенсация под header:** у `main` задать `paddingTop: 100` (или у первой секции), чтобы контент не заходил под шапку.  
3. **Footer:** граница сверху, контейнер, ссылки/контакты; шрифт и отступы из токенов.  
4. Мобильное меню (если есть): без потери контраста и читаемости.

**Критерий:** header всегда «стеклянный», не меняет стиль при скролле; footer визуально из той же системы.

**Результат:** Header и Footer подключены; main с отступом под фиксированный header.

## 8. Краткий чек-лист «фронт не калека»

- В `:root` есть **радиусы, тени, glow**, а не только цвета.  
- **Card** и ключевые блоки используют **крупные скругления** из токенов.  
- **Hero** содержит **выделенный mockup** (browser-frame / app-preview) с рамкой, тенью и опционально glow.  
- Фон страницы **единый и бесшовный** (без чередования полос); разделение — отступы и карточки.  
- **Один самый крупный заголовок** — только в hero; остальные уровни иерархии заданы явно.  
- **Header** при скролле получает фон и blur; **Footer** в том же стиле.  
- **Reveal** и **hover** работают без рывков.  
- Нет горизонтального скролла; форма и CTA ведут куда нужно и обрабатывают состояния.

## 9. Эталонные дизайн-решения (Premium Mantine)

**Когда применять:** по запросу пользователя «нужно дизайн решение», «дизайн решение», «design solution» или при необходимости заполнить пустую зону экрана без картинок. Все решения — только Mantine + CSS, без внешних иллюстраций.

### 9.1. Триггер для @FRONTEND

Если пользователь просит **дизайн-решение** для блока, секции или «занять пустое пространство», @FRONTEND предлагает варианты из этого раздела и реализует (или передаёт @DEV) в том же премиум-качестве: анимации, иконки, стеклянные карточки, абстрактные композиции.

### 9.2. Анимации (чистый CSS в `index.css`)

| Класс / keyframes | Назначение | Параметры |
|-------------------|------------|-----------|
| **`.floating-element`** | Плавное парение (левитация) блока | `animation: float 6s ease-in-out infinite` |
| **`@keyframes float`** | Вертикальное смещение вверх-вниз | `0% translateY(0)` → `50% translateY(-15px)` → `100% translateY(0)` |
| **`@keyframes pulse`** | Мягкое пульсирование (бейджи, индикаторы) | `0%,100% opacity:1` → `50% opacity:0.7`; использовать как `animation: pulse 2s infinite` |

Дополнительно: все интерактивные элементы — `transition: all var(--transition-smooth)`; hover карточек и кнопок без рывков.

### 9.3. Абстрактные композиции (без картинок)

- **Парящая карточка с 3D-наклоном:**  
  Обёртка `Box` с `className="floating-element"`, `style={{ perspective: '1000px' }}`. Внутри — декоративное свечение (абсолютный `Box` с `background: var(--accent)`, `filter: blur(80px)`, `opacity: 0.3`, размер ~200×200px, `zIndex: 0`). Поверх — `Paper` с классом `glass-card`, `transform: 'rotateX(10deg) rotateY(15deg)'`, `transformStyle: 'preserve-3d'`, `border: 1px solid rgba(99, 102, 241, 0.3)`.

- **Имитация интерфейса внутри карточки:**  
  Заголовок карточки — `ThemeIcon` (variant="light", color="indigo") + иконка из `@tabler/icons-react` (например `IconChartBar`) + `Badge` с текстом («AI Анализ») и `style={{ animation: 'pulse 2s infinite' }}`. Подзаголовок — `Text c="dimmed" size="xs" tt="uppercase"`. Тело — несколько `Skeleton` (height 8px, radius="xl", разная ширина 100% / 70% / 85%, opacity 0.2) как «полоски отчёта». Внизу — иконка (`IconBrain`) + короткий текст («Поиск точек роста...»).

- **Декоративное свечение (blur blob):**  
  `Box` с `pos="absolute"`, центрирование через `top="50%" left="50%" style={{ transform: 'translate(-50%, -50%)' }}`, размер 200×200, `background: var(--accent)`, `filter: blur(80px)`, `opacity: 0.3`, `zIndex: 0` — ставится позади карточки для глубины.

### 9.4. Иконки и акценты

- **Библиотека:** `@tabler/icons-react` (IconCpu, IconChartBar, IconBrain, IconGift, IconCheck, IconX и т.д.).
- **ThemeIcon:** для премиум-блоков — `variant="light"` или `variant="gradient"` (gradient `from: 'indigo', to: 'grape'` / `grape` → `violet`), цвет `color="indigo"`; размеры 40–56px для карточек, 22–24px в списках.
- **Иконки без фона (воздушные):** в Hero/WhoFor — иконка с `filter: drop-shadow(0 0 12px rgba(217, 70, 239, 0.6))`, цвет `var(--text-primary)` или `var(--accent)`.
- **Badge:** для статусов и меток — `variant="light"`, цвет green/indigo; при необходимости анимация `pulse` для «живого» индикатора.

### 9.5. Карточки и типографика

- **Единый стиль карточек:** класс `.glass-card` (см. раздел 3 и 4); для акцентных блоков — дополнительная граница `border: 1px solid rgba(99, 102, 241, 0.3)` и при необходимости `boxShadow: var(--card-glow)`.
- **Заголовки с градиентом:** для ключевых блоков (например «Бонусы при покупке») — `Text` с `style={{ background: 'linear-gradient(...)', WebkitBackgroundClip: 'text', WebkitTextFillColor: 'transparent' }}`, `fontSize: 'var(--type-hero)'` или аналог.

### 9.6. Чек-лист «дизайн-решение премиум»

- Анимации только через CSS (float, pulse) или Mantine transition; без тяжёлых JS-анимаций.
- Пустые зоны заполняются абстрактными композициями (парящая карточка, скелетоны, иконки + текст), не случайными картинками.
- Иконки — только из @tabler/icons-react, оформленные через ThemeIcon или с лёгким glow.
- Все токены (цвет, радиус, тень, glow) — из `:root` / `index.css`; не хардкодить HEX в компонентах.
- Результат визуально согласован с остальной страницей (тёмная тема, glass-card, единый акцент).

## 10. Производительность анимаций и фона (scroll & GPU)

Этот раздел задаёт минимальный протокол по производительности для анимаций, blur-эффектов и фоновых паттернов. Применяется **во всех лендингах и витринах**, которые используют `.reveal`, `.glass-card`, фоновую сетку/паттерн.

### 10.1. Reveal-анимации и `useReveal`

- **Класс `.reveal`** должен анимировать **только** `transform` и `opacity` — никаких `top/left/margin` в переходе:

```css
.reveal {
  will-change: transform, opacity;
  transform: translateY(24px);
  opacity: 0;
  transition:
    transform 0.8s cubic-bezier(0.22, 1, 0.36, 1),
    opacity 0.8s ease;
}

.reveal-visible {
  transform: translateY(0);
  opacity: 1;
}
```

- **Важно:** `will-change` задаётся **перед** анимацией и снимается **после её завершения**, чтобы браузер не держал лишние слои в памяти:

```ts
// пример паттерна в хуке useReveal
element.classList.add('reveal');
element.style.willChange = 'transform, opacity';

// после завершения transition:
element.addEventListener(
  'transitionend',
  () => {
    element.style.willChange = 'auto';
  },
  { once: true }
);
```

- **IntersectionObserver в `useReveal`:**

```ts
const observer = new IntersectionObserver(
  (entries) => {
    entries.forEach((entry) => {
      if (entry.isIntersecting) {
        entry.target.classList.add('reveal-visible');
        observer.unobserve(entry.target); // отписываемся — экономим ресурсы
      }
    });
  },
  {
    rootMargin: '-80px 0px',
    threshold: 0,
  }
);
```

- **Принцип:**  
  - Анимация запускается немного **до** появления секции во вьюпорте (`rootMargin`), чтобы не было «подпрыгивания».  
  - После первого появления элемент **больше не наблюдается** (`unobserve`) — нет лишних вызовов колбэка при каждом скролле.

### 10.2. Backdrop-filter и скролл

`backdrop-filter: blur()` — дорогая операция. Для стеклянных карточек и header нужно уметь **временно отключать blur во время активного скролла**, чтобы не блокировать перерисовку.

- **Паттерн JS:**

```ts
let scrollTimer: number | undefined;

window.addEventListener(
  'scroll',
  () => {
    document.body.classList.add('is-scrolling');

    if (scrollTimer) {
      window.clearTimeout(scrollTimer);
    }

    scrollTimer = window.setTimeout(() => {
      document.body.classList.remove('is-scrolling');
    }, 150);
  },
  { passive: true }
);
```

- **Паттерн CSS:**

```css
.glass-card {
  backdrop-filter: blur(20px);
  -webkit-backdrop-filter: blur(20px);
  transition: backdrop-filter 0.2s ease-out;
}

.is-scrolling .glass-card {
  backdrop-filter: none;
  -webkit-backdrop-filter: none;
}
```

- **Обязательно:** обработчик `scroll` всегда вешается с `{ passive: true }`, чтобы браузер не ждал завершения JS перед прорисовкой кадра.

### 10.3. Фоновые паттерны и SVG (`svg_pattern.png`)

- Если фоновый паттерн реализован через `svg_pattern.png` или похожее изображение, нужно проверить:
  - размер файла — **≤ 50 КБ**;
  - разрешение — **≤ 1000×1000px**;
  - режим — без `background-repeat: repeat` на тяжёлой картинке.
- Если хотя бы одно условие нарушено, паттерн должен быть переведён в **CSS-/SVG-решение**:
  - **inline SVG** через `background-image: url("data:image/svg+xml,...")` с небольшим тайлом (например 40×40px);  
  - или **чистый CSS-паттерн** через `linear-gradient` / `radial-gradient`.

```css
.bg-pattern {
  background-image: url('data:image/svg+xml,...'); /* лёгкий SVG-тайл */
  background-size: 40px 40px;
  background-repeat: repeat;
}
```

- **Приоритет исполнения при оптимизации:**  
  1. Заменить тяжёлое фоновой изображение на CSS-паттерн (п. 10.3).  
  2. Заморозить blur (`backdrop-filter`) во время скролла (п. 10.2).  
  3. Перевести reveal-анимации на `transform + opacity` с `will-change` (п. 10.1).  
  4. Тонко настроить параметры `useReveal` (rootMargin, threshold, `unobserve`).
