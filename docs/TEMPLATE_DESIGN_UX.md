## 3. Слой дизайн-решений (зафиксировать до вёрстки)

### 3.1. Токены в `:root` (`frontend/src/index.css`)

| Категория | Примеры | Назначение |
|-----------|---------|------------|
| Радиусы | `--radius-sm` … `--radius-xl` | Кнопки, карточки, mockup |
| Тени / glow | `--shadow-*`, `--card-glow-hover`, `--glow-accent` | Карточки, hero-пьедестал |
| Контейнер | `--max-w-content` | Ширина контентной колонки |
| Motion | `--transition-smooth`, reveal | Hover и появление секций |
| Паттерн фона | `.page-gradient::before` (сетка + маска) | Премиальный фон без шума |

### 3.2. Композиция

- **Hero:** сетка (например 7/5); слева заголовок → подзаголовок → буллеты → 2 CTA; справа **пьедестал** (glass/mockup) с крупным радиусом и акцентным свечением.
- **Ниже hero:** **единый непрерывный фон** страницы; разделение секций — **отступы и карточки**, не чередование фона («зебра» запрещена, см. 3.5).

### 3.3. Типографика (Mantine — ориентиры)

Задавать через `Title` / `Text` и переменные, не через Tailwind-классы.

| Уровень | Mantine (пример) | Правило |
|---------|------------------|---------|
| Hero H1 | `Title order={1}` + крупный `fz` на breakpoints | Один самый крупный H1 на странице |
| Секция H2 | `Title order={2}` | Меньше hero |
| Карточка H3 | `Title order={3}` или `fw={600}` | |
| Body | `Text size="sm"` / `md` | `c="dimmed"` для вторичного |
| Eyebrow | `Text size="xs" tt="uppercase" fw={600}` | Опционально капсула |

### 3.4. Кнопки

Primary / ghost / outline; ховеры с `transition` из токенов; не дублировать «магические» px радиусов в каждом компоненте.

### 3.5. Протокол фона (обязательно для маркетинга)

- Одно «поле» градиента/паттерна на страницу.
- `.section` / `.section-alt` — **только вертикальные отступы**, `background: transparent`.
- Визуальное членение — карточки (`glass-card` и т.п.) и padding.

### 3.6. Стек

- Mantine Carousel + embla при необходимости; версии согласовать с Mantine.
- Иконки: `@tabler/icons-react`.
- Reveal: `useReveal` + классы `.reveal` / `.reveal-visible` (детали — §10).

## 5. Пошаговый план (маркетинговая страница)

### Шаг 0. Бриф

Тип страницы, список секций, тексты CTA, референс (URL) — в задаче или `docs/artifacts/DEV_PROMPTS_*.md`.

### Шаг 1. Токены и тема

1. Все переменные в `frontend/src/index.css` (`:root`).
2. `theme.ts` согласовать с переменными (`defaultRadius`, brand).
3. **Не** добавлять `tailwind.config` по умолчанию.

**Критерий:** смена `--radius-lg` или glow меняет карточки и CTA без правок в десятках компонентов.

### Шаг 2. Layout

`.container-page`, `.section`, `.page-gradient`, сетка секций; нет полосатого фона.

### Шаг 3. Базовые UI

Кнопки, карточки, `SectionHeader` — из токенов.

### Шаг 4. Hero + mockup

Сцена «текст + демо-блок»; адаптив без горизонтального скролла.

### Шаг 5. Остальные секции

По списку из брифа; единая система карточек.

### Шаг 6. Header / footer маркетинговой страницы

Если используются fixed header с blur — см. §10.2 (скролл); для админки — отдельные правила в `ROLE_FRONTEND`.

### Шаг 7. Reveal и полировка

Подключить reveal; проверить hover, контраст WCAG AA, обрезку теней в каруселях.

### Шаг 8. Чеклист

- [ ] Токены геометрии используются в компонентах  
- [ ] Hero с выделенным mockup  
- [ ] Фон единый, без зебры  
- [ ] Один главный H1  
- [ ] Нет горизонтального скролла  
- [ ] Формы и CTA с состояниями loading/error

## 8. Эталонные «премиум» блоки (маркетинг)

**Триггер:** запрос пользователя на «дизайн-решение» для **маркетинговой** пустой зоны.

- CSS: `.floating-element`, `@keyframes float`, `pulse` для бейджей.
- Абстрактные композиции: 3D-наклон карточки, blur-blob, skeleton-полоски + иконки Tabler — **без** случайных stock-изображений.
- Всё из токенов `:root`; согласованность с тёмной/светлой темой страницы.

Подробные сниппеты — по необходимости в том же эпике, что и код; не раздувать системные файлы копипастой.

## 9. Производительность (motion, blur, фон)

> Связь с `ROLE_FRONTEND`: протокол blur/reveal для **витрин**; для **админки** — приоритет скорости и читаемости, без обязательного glass.

### 9.1. Reveal

Анимировать только `transform` и `opacity`; `will-change` до анимации, снять в `transitionend`; `IntersectionObserver` с `unobserve` после первого показа.

### 9.2. Backdrop-filter и скролл

На время активного скролла — класс `.is-scrolling` на `body`, ослабление или отключение blur для тяжёлых узлов; слушатель `scroll` с `{ passive: true }`.

### 9.3. Фоновые изображения

Тяжёлые PNG > 50 КБ или > 1000×1000 — заменить на CSS/SVG-тайл или inline SVG data-URI.

## 10. MARKETING DESIGN GATE (вход до вёрстки)

Перед стартом вёрстки маркетинговой страницы @LEAD/@FRONTEND фиксируют:

```
□ ICP и сегмент страницы (для кого конкретно)
□ One-liner value proposition (1 фраза)
□ Message hierarchy (H1 → proof → CTA)
□ Цель страницы (лид / демо / заявка / клик в мессенджер)
□ Список секций по порядку (Hero, Proof, Features, CTA, FAQ, Footer)
□ Юридические ограничения (обязательные дисклеймеры, оферта, consent)
□ Analytics цель (какое событие = success)
```

Без этого пакета страница визуально "красивая", но коммерчески пустая.

## 11. State Spec для маркетинговых форм

Каждая форма на витрине имеет обязательные состояния:

```
Loading:
- submit disabled
- текст кнопки "Отправляем..."
- spinner/loader внутри кнопки (без прыжка layout)

Validation Error:
- inline ошибка под полем
- фокус на первое невалидное поле
- текст без техничных кодов

Network/Error:
- alert/toast с человеческим текстом
- кнопка повторить
- введённые данные не теряются

Success:
- явное подтверждение (toast/inline)
- reset формы или переход по сценарию
- аналитическое событие success отправлено один раз
```

## 12. SEO / A11y / Analytics Acceptance

### 12.1 SEO (минимум)
- Уникальные `title` и `meta description` для страницы.
- OpenGraph/Twitter meta для шаринга.
- Канонический URL.
- Один `h1` на страницу.

### 12.2 Accessibility (минимум)
- Контраст WCAG AA.
- Логичный tab-order и видимый focus ring.
- Кнопки и ссылки имеют понятные accessible labels.
- Форма отправляется с клавиатуры (`Enter` где уместно).

### 12.3 Analytics (минимум)
- Определён namespace событий страницы (пример: `landing_*`).
- Отправляются события: `view`, `cta_click`, `form_submit`, `form_success`, `form_error`.
- События не дублируются при re-render.

## 13. Компонентный контракт секций (marketing)

| Секция | Обязательные элементы | Ошибка |
|--------|------------------------|--------|
| Hero | 1 H1, 1 supporting text, до 2 CTA, visual proof/mockup | 2+ равнозначных primary CTA |
| Social Proof | Логотипы/кейсы/цифры доверия | "Голые" заявления без подтверждения |
| Features | 3-6 карточек с чёткой пользой | Список фич без связи с ICP |
| Pricing/Offer | Ясные условия и границы оффера | Непрозрачные условия |
| FAQ | 4-8 реальных возражений | Маркетинговая вода вместо возражений |
| Final CTA | Один целевой сценарий конверсии | Конкурирующие CTA внизу |

## 14. Anti-patterns (блокируют приёмку)

```
❌ Смешение маркетингового glass-стиля с операционными admin-экранами
❌ Более одного H1
❌ Отсутствие явного primary CTA в Hero
❌ Несогласованные отступы/радиусы вне токенов
❌ Анимации, влияющие на layout (top/left/margin)
❌ Форма без состояния ошибки/успеха
❌ Нет mobile-проверки (горизонтальный скролл)
❌ Нет SEO/OG мета при публичной странице
```
