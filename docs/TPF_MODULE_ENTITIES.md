# TPF_MODULE_ENTITIES — Обогащённые карточки сущностей (Entity Tabs)

> **Префикс TPF_** — Tech Passport Frontend. Модульный техпаспорт.  
> **Связь:** `TPF_MASTER.md` (Часть III), `REV_RAG_MAP_INNOVATIONS.md` (раздел 9).

---

## 1. Назначение

Любая карточка сущности в Drawer строится на вкладках (Tabs). Цель — плотность данных уровня Yclients/Bitrix24, без «пустых» форм из 3–5 полей.

---

## 2. Пациент (Patient 360°)

- **Header:** Аватар, ФИО, телефон, email, теги (VIP, Должник, Склонен к отменам), LTV, баланс бонусов/кэшбэка.
- **Вкладка [Основное]:** Дата рождения (с тегом «Скоро ДР» при необходимости), пол, категория клиента, согласия на ПД, источник (UTM).
- **Вкладка [Визиты]:** Таблица истории записей: дата, врач, услуга, статус, сумма, отзыв (NPS).
- **Вкладка [Финансы]:** История платежей, возвратов, списаний с бонусного счёта, абонементы и остаток.
- **Вкладка [Медкарта/Заметки]:** RichText (TipTap или аналог) для протоколов; прикрепление файлов (снимки, до/после).
- **Вкладка [Коммуникации]:** История уведомлений (SMS/Email/TG), быстрый переход к чату с этим клиентом.

**Открытие:** Drawer или страница `/admin/patients/[id]`. API: patient CRUD, вложенные bookings, payments, notes, comms.

---

## 3. Запись (Booking)

- **Вкладка [Детали]:** Пациент (с быстрым созданием нового), врач, кабинет/кресло, время начала/окончания, длительность, статус (Ожидает, Пришел, В кресле, Завершен, Неявка).
- **Вкладка [Услуги и чек]:** Несколько услуг, итог, ручная скидка, списание бонусов, выбор кассы для оплаты.
- **Вкладка [Расходники]:** Список по техкарте выбранных услуг с возможностью ручной корректировки.
- **Вкладка [Задачи]:** Задачи, привязанные к этому визиту.

**Открытие:** Клик по слоту в календаре или из списка записей. API: booking CRUD, services, consumables, tasks.

---

## 4. Сотрудник/Врач (Employee/Doctor)

- **Вкладка [Профиль]:** ФИО, специализация, контакты, цвет в календаре, роль доступа.
- **Вкладка [Расписание]:** Настройка графика (2/2, чет/нечет, индивидуальные часы).
- **Вкладка [Зарплата]:** Схема мотивации: ставка за выход, % от услуг, % от кросс-сейла.
- **Вкладка [Услуги]:** Чекбоксы — какие услуги может оказывать (связь Many-to-Many).

**Открытие:** Drawer из списка врачей. API: doctor CRUD, working_hours, payroll policy, service_doctor.

---

## 5. Услуга (Service)

- **Вкладка [Описание]:** Название, категория, базовая цена, длительность, цвет в календаре.
- **Вкладка [Исполнители]:** Кто из сотрудников может выполнять (Many-to-Many).
- **Вкладка [Техкарта]:** Список продуктов и количество (расходники при оказании услуги).
- **Вкладка [Онлайн-запись]:** Флаг «Доступна для онлайн-записи», описание для клиента, обязательна ли предоплата.

**Открытие:** Drawer из списка услуг. API: service CRUD, service_doctor, consumables, флаги онлайн-записи.

---

## 6. Общие правила

- Все карточки открываются в `<Drawer position="right" size="lg">`.
- Загрузка данных по вкладкам — ленивая или единым запросом с вложенными коллекциями; при загрузке — Skeleton внутри вкладки.
- В каждой карточке при необходимости — ActionMenu в шапке (Печать, Скопировать, Удалить и т.д.).
- Zero-Click Context: в полях «Пациент»/«Врач» при наведении — HoverCard с телефоном, LTV, след. визит (если API отдаёт).
