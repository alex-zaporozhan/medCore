# Smoke после деплоя (SME §3.3)

Минимум после выката новой версии backend:

1. **`GET /health`** — HTTP 200, тело с признаком живости приложения и БД (как в реализации проекта).
2. **Один read-only публичный сценарий**, например:
   - `GET /api/v1/health` или
   - публичное расписание / справочник услуг с валидным `clinic_id` (см. чеклист релиза).

При ошибке — откат по runbook деплоя; инцидент по регламенту @LEAD.

## Первый прогон в production (@LEAD)

Для первого выката (новый URL, TLS, реестр) — расширенный чеклист: проверка с **внешней** стороны (как у клиента), фиксация тега/SHA образа, запись результата. Подробно: [`LEAD_FIRST_RUN_OPS.md`](LEAD_FIRST_RUN_OPS.md) (раздел 1).

## Связь с CI

Регресс «поднять API и дернуть /health» частично покрывается E2E и job **restore-drill** (проверка БД). Полный smoke на **production** — шаг оператора.
