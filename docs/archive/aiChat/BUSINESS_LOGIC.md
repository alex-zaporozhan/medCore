## 1. Суть продукта (одна фраза)

Мы помогаем **стоматологическим клиникам** автоматизировать запись пациентов **без** ручных звонков и потери клиентов из-за забывчивости администраторов.

---

## 2. Целевой пользователь

- **Кто платит:** Владелец стоматологической клиники или администратор (малые клиники: 1-10 врачей, до 50 сотрудников)
- **Кто использует:** 
  - Администраторы клиники (веб-админка)
  - Пациенты (мобильное PWA приложение)
- **Главная боль:** 
  - Потеря клиентов из-за забывчивости администраторов (не перезвонили, не напомнили)
  - Ручная запись по телефону отнимает время администратора
  - Нет автоматических напоминаний пациентам
  - Нет предоплаты (пациенты не приходят, клиника теряет деньги)
- **Как решают сейчас:** 
  - Excel/Google Sheets для записи
  - Телефонные звонки для напоминаний
  - Нет предоплаты или ручная обработка

---

## 3. Монетизация

- **Модель:** Разовая продажа готового решения
- **Цена входа:** $1,500–3,000 (разово) или 120 000–250 000 ₽; кастомизация +$500–1,500. (Детали и обоснование: [BIZ_PLAN_UNIVERSAL_BUSINESS_AND_PRICING.md](BIZ_PLAN_UNIVERSAL_BUSINESS_AND_PRICING.md). Ранее фигурировало $2,000–5,000 — скорректировано под сегмент «альтернатива Yclients за 2 года подписки».)
- **ROI для клиента:** 
  - Экономия времени администратора: 2-3 часа в день × стоимость часа = ~₽15,000/мес
  - Снижение no-show (неявок): предоплата снижает неявки на 30-50%
  - Окупается за 2-3 месяца при экономии времени + снижении no-show

## 5. Бизнес-правила (логика которая НИКОГДА не меняется без явного решения)

### Правило 1: Предоплата опциональна для подтверждения записи
**Условие:** Пациент выбирает слот и подтверждает запись
**Действие:** Если у клиники включена предоплата (настройка «Предоплата» в админке) и для данной записи по правилам политик требуется предоплата — система предлагает внести предоплату (сумма настраивается, по умолчанию 500₽). Если предоплата выключена или политика «без предоплаты» — запись подтверждается сразу без оплаты.
**По умолчанию:** предоплата ВЫКЛ (prepayment_enabled = false). Гибкость по услугам/врачам — через политики предоплаты (none / partial / full по scope: doctor, service, doctor_service).
**Исключения:** Администратор может создать запись без предоплаты вручную в любом случае.

### Правило 2: Автоматические напоминания пациенту
**Условие:** Запись подтверждена (создана и в статусе, при необходимости — предоплата внесена)
**Действие:** 
- Уведомление за 24 часа до приёма
- Уведомление за 2 часа до приёма
**Исключения:** Запись отменена до времени уведомления

### Правило 3: Возврат предоплаты при отмене
**Условие:** Запись была с внесённой предоплатой; пациент или администратор отменяет запись
**Действие:** Автоматический возврат предоплаты через ЮKassa
**Исключения:** Отмена менее чем за 2 часа до приёма — возврат по решению администратора (можно настроить)

### Правило 4: Один слот — одна запись
**Условие:** Время слота занято другой записью
**Действие:** Слот недоступен для выбора (красный в календаре)
**Исключения:** Администратор может вручную перезаписать слот (с предупреждением)

### Правило 5: CSV-экспорт только закрытых записей
**Условие:** Экспорт данных для 1С
**Действие:** Экспортируются только записи со статусом "Оказано" (закрытые)
**Исключения:** Нет

## 8. A-B решения (зафиксированные выборы)

| Вопрос | Выбран | Причина | Условие пересмотра |
|--------|--------|---------|-------------------|
| PWA vs React Native vs нативные приложения | PWA | Быстрая разработка, один код для iOS/Android, не нужно скачивать из магазинов | Если нужны push-уведомления без браузера (тогда React Native) |
| Telegram vs только SMS | Telegram + SMS fallback | Telegram бесплатно, SMS платно; но нужен fallback на случай блокировки Telegram | Если Telegram заблокируют — переключиться на SMS/Email |
| CSV vs API для 1С | CSV (MVP) | Не требует доступа к API 1С, работает сразу | Если клиент предоставит доступ к API 1С — сделать полноценную интеграцию |
| Один админ vs роли | Один админ (MVP) | Быстрее реализовать, достаточно для малых клиник | Если клиент просит роли (админ, врач, кассир) — добавить в доработку |
| Предоплата обязательна vs опциональна | Опциональна (по умолчанию ВЫКЛ) | Гибкость под клиника/салон; при включении снижает no-show | Политики по услугам/врачам уже поддерживаются в коде |

## 10. Метрики успеха

- **Технические:** 
  - Uptime: >99% (цель)
  - API response time: <200ms для интерактивных операций (p95)
  - Database query time: <100ms для простых, <500ms для сложных
- **Бизнесовые:** 
  - Количество клиентов через 6 мес: 5-10 клиник (цель для MVP)
  - Churn: <10% (клиенты не отказываются от решения)
  - Выручка: $10,000-25,000 (5 клиентов × $2-5k)
- **Пользовательские:** 
  - Время до первой записи: <5 минут (от входа до подтверждения)
  - Процент успешных записей: >80% (завершённых до оплаты)
  - Процент no-show: <20% (с предоплатой должно снизиться)

## 11. Явно за скобками (не делаем в этой версии)

- **Полноценная интеграция с 1С через API** — причина: требует доступа к API 1С от клиента, сложнее реализовать. В MVP: CSV-импорт/экспорт.
- **Push-уведомления в мобильное приложение** — причина: PWA не поддерживает полноценные push без браузера. В MVP: SMS/Telegram.
- **Расширенная аналитика и отчёты** — причина: для MVP достаточно базовых отчётов (записи, no-show, выручка). Расширенная аналитика — в доработке.
- **Роли администраторов** — причина: для малых клиник достаточно одного админа. Роли (админ, врач, кассир) — в доработке.
- **Мультитенантность (несколько клиник в одной системе)** — причина: MVP для одной клиники. Multi-tenancy — если будем делать SaaS-версию.

## 12. База сущностей (от @BIZ)

### Стандартные сущности в системах записи:

- ✅ **Расписание (Schedule)** — слоты времени для врачей
- ✅ **Врачи (Doctors)** — карточки врачей с фото, специализацией, рейтингом
- ✅ **Услуги (Services)** — каталог услуг с категориями и ценами
- ✅ **Пациенты (Patients)** — профили пациентов с историей посещений
- ✅ **Записи (Bookings)** — записи на приём со статусом (подтверждена, отменена, оказана)
- ✅ **Платежи (Payments)** — предоплаты через ЮKassa
- ✅ **Уведомления (Notifications)** — история отправленных уведомлений
- ✅ **Отчёты (Reports)** — статистика по записям, no-show, выручке

### Конкуренты (кратко):

- **Yclients:** Много функций, интеграции (1С — через посредников, не нативно; Битрикс24 — нет). Чат с клиентом через мессенджеры (WhatsApp, Telegram, VK), не встроенный чат в приложении клиента. Предоплата при записи есть (обязательная и необязательная, настраивается). Расчёт зарплат и отчёты по персоналу — есть. Подробно: [BIZ_YCLIENTS_HONEST_COMPARISON.md](BIZ_YCLIENTS_HONEST_COMPARISON.md).
- **1С:Медицина:** Корпоративное решение, интеграция с 1С. Избыточно для малых клиник; дорого, нужен специалист по 1С.
- **Telegram-боты (самописные):** Только запись, нет веб-админки, отчётов, оплаты.

**Запрос владельца (отчёты):** Ежемесячный отчёт для контроля: по врачам — часы/дни работы, сколько заработали; по администраторам — часы/дни работы. План: добавить в разработку (отдельный отчёт за период), см. BIZ_YCLIENTS_HONEST_COMPARISON.md.
