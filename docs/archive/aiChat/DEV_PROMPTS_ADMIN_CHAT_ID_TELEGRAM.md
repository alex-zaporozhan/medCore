# DEV_PROMPTS: ID чата админа для Telegram — итог и команды для @DEV

> Контекст для @DEV: зачем поле «ID чата админа», что уже сделано, что при необходимости доработать.

---

## 1. Задача (от продукта)

При настройке Telegram-бота нужно указать:
- **API key (токен бота)** — чтобы бот мог работать.
- **Личный ID в Telegram** (или ID чата/группы) — куда бот будет присылать **оповещения админу лично**: запрос оператора в едином чате, черновики AI, при расширении — новая запись, отмена и т.д.

То есть **один чат администратора**: одно место, куда уходят все оповещения владельцу/админу. Не несколько разных чатов, а один получатель на клинику (или на бота).

---

## 2. Что уже сделано (не трогать без задачи)

- **Фронт** (`AdminOmniChannelsPage.tsx`): в модалке «Настройка ключей: TELEGRAM_BOT» добавлено поле **«ID чата админа (для оповещений)»** (`admin_chat_id`). Сохраняется в credentials канала (JSON: `bot_token`, `webhook_secret`, `admin_chat_id`).
- **Бэкенд:**
  - `OmnichannelOutboundDispatcher._dispatch_telegram`: парсит JSON credentials, для отправки сообщения **клиенту** использует `bot_token`; получатель сообщения — контакт (telegram_user_id).
  - `OmnichannelAIOrchestrator._get_telegram_admin_chat_id(chat)`: для уведомлений **админу** (запрос оператора, черновик AI) читает credentials канала чата; если в JSON есть `admin_chat_id` — использует его, иначе `settings.telegram_admin_chat_id`.
- **Fallback:** если в настройках канала не задан `admin_chat_id`, используется глобальный `TELEGRAM_ADMIN_CHAT_ID` из env.

Итог: оповещения из единого чата (запрос оператора, черновики AI) уже уходят в чат админа — из настроек канала или из env.

---

## 3. Команды для @DEV (что делать дальше)

### 3.1. Проверка текущего поведения (обязательно)

1. В админке: Настройки → Омниканальные каналы → создать/открыть канал TELEGRAM_BOT → в настройках ключей указать **Bot token** и **ID чата админа** (личный ID или ID группы; можно получить через @userinfobot).
2. Сохранить. Убедиться, что при событии «клиент запросил оператора» или «новый черновик AI» в едином чате приходит уведомление в указанный чат.
3. Если `admin_chat_id` не задан в форме — уведомления должны уходить в чат из env `TELEGRAM_ADMIN_CHAT_ID` (если он задан).

### 3.2. Унификация оповещений о записи/отмене (опционально)

Сейчас уведомления **пациенту** о создании/отмене записи идут в личный канал пациента (SMS/Telegram/email). Отдельной отправки «админу о новой записи/отмене» в этом проекте может не быть.

Если продукт захочет добавить **оповещение админу в Telegram** при событии «новая запись» / «отмена записи»:

1. В месте, где формируется такое уведомление (например, задача или сервис после создания/отмены записи), вызывать `send_with_fallback(..., preferred_channel="telegram", chat_id=admin_chat_id)`.
2. `admin_chat_id` для клиники брать так же, как в омниканале: по `clinic_id` найти канал TELEGRAM_BOT этой клиники → прочитать credentials → из JSON взять `admin_chat_id`; если нет — использовать `settings.telegram_admin_chat_id`. То есть вынести в общий хелпер «получить admin_chat_id для клиники» (по clinic_id из credentials канала TELEGRAM_BOT или из env) и использовать его и в оркестраторе, и при уведомлениях о записи/отмене.

Чек-лист для этой доработки:
- Добавить метод/сервис: `get_telegram_admin_chat_id_for_clinic(clinic_id: UUID) -> str | None` (читать канал TELEGRAM_BOT для clinic_id, парсить credentials, вернуть `admin_chat_id` или settings.telegram_admin_chat_id).
- В задаче/сервисе уведомления о новой записи (и при отмене, если нужно) вызывать этот метод и передавать `chat_id` в `send_with_fallback`.
- Не ломать текущее поведение: если ни в канале, ни в env нет admin_chat_id — не падать, просто не слать в Telegram (или логировать).

### 3.3. Документация для пользователя

В справке или в подсказке на странице «Омниканальные каналы» можно кратко описать: «ID чата админа — личный чат или группа в Telegram, куда бот будет присылать вам оповещения (запрос оператора, черновики AI и при включении — уведомления о записях). Узнать свой ID: напишите боту @userinfobot в нужный чат.»
