## На потом (@QA_ARCH — предложения)

Рубрика для **следующих итераций** после v1 core multi‑clinic; не дублирует дословно §5–6, а фиксирует **качество, безопасность и эксплуатацию**.

1. **Единый контракт 403/404** — для всех админских эндпоинтов с `clinic_id` в path/query сверить с `BookingCompletionService` и прочими фасадами: везде ли **403** `clinic_forbidden` при «сущность в другой клинике», а **404** только при отсутствии строки; при необходимости расширить `ClinicForbiddenError` на completion/checkout.
2. **Owner / multi‑clinic JWT** — сейчас админ привязан к одной клинике в токене; при появлении роли «несколько клиник» понадобится **явный API смены контекста** или **owner‑токен**, иначе селектор останется визуальным только для owner‑дашборда.
3. **Полные структурированные логи** — поля `initiator`, `waitlist_entry_id`, тип операции для cancel/reschedule/prepayment как в §5.1.1; склейка с `trace_id` в ленте логов.
4. **Фронт: observability** — дешёвые UI‑события (смена клиники в wizard, старт записи с `clinic_id`) в `logUiEvent` / аналитику, если продукт заведёт дашборд.
5. **Автотесты PWA** — RTL/Playwright: >1 клиника → первый шаг; смена клиники инвалидирует query schedule; опционально snapshot контракта query `clinic_id`.
