## Ось A — Макро UI/UX

- Понятна ли **цель экрана** одним заголовком и контекстом?
- Выделено ли **одно первичное действие** (где уместно)?
- Согласована ли иерархия с каноном: фон → карточка → действия?
- Нет ли смешения зон продукта (маркетинг vs операционный UI)?

## Ось B — Микро UI/UX

- Состояния: загрузка, пусто (с подсказкой), ошибка (следующий шаг).
- Таблицы: фильтры связаны с запросом; пагинация/виртуализация при больших объёмах (если применимо).
- Кнопки и карточки: без «кустарных» отступов и смешения вариантов вне `theme.ts`.
- Селекты и списки: источник опций — **справочный API**, а не производные от запроса, который сам блокируется без выбора (см. §8 рубрики фронта).

## Ось C — Сквозная цепочка UI ↔ API

- Маршрут → хук(и) → HTTP-пути → мутации → инвалидация кэша (React Query).
- Для каждого типичного действия на экране: есть ли реальный запрос и обработка ошибки?
- Пометки **as-built** vs **gap** (заглушка, пустой `onClick`, нет инвалидации).

## Ось D — RBAC, entitlements, edition

- Какие `require_permissions` на бэкенде для ключевых API (если известно из кода роутера).
- `adminShellSegmentEntitlementKey`, `isAdminSegmentBlockedByEntitlements`, `isAdminSegmentBlockedInBox` — что режет UI.

## Ось E — Копирайт и доверие

- Соответствие [`COPY_STYLE_POLICY_RU.md`](../COPY_STYLE_POLICY_RU.md): нет следов «черновика ИИ», внутренних кодов задач в пользовательских строках.

## Ось F — Безопасность (UI-поверхность)

- Нет ли вывода сырого stack trace или внутренних идентификаторов там, где ожидается человекочитаемый текст?
- Чувствительные действия: подтверждение, понятные последствия.

## Ось G — Критика tech lead / покупателя (санитарная)

- Что разрушит скидку на сделке: пустые селекты, кнопки без эффекта, расхождение витрины и данных, UUID вместо имён?
- Краткий вердикт: **готово к демо** / **только внутреннее** / **блокер**.

## Ось H — Поверхности UI (инвентарь as-built)

Для **v1** паспорта обязательна секция **«Инвентарь поверхностей UI»** в файле страницы, если на экране есть хотя бы одно из ниже; если нет ни одного — явно написать **«модалок/drawer нет»**.

Перечислить по таблице или списку (минимум: тип, триггер, связь с данными):

| Тип | Примеры в коде | Что указать в паспорте |
|-----|----------------|-------------------------|
| Drawer (админ) | `AdminDrawer` | Режимы (`income` / …), открытие из `Menu` или кнопки, мутация, `onClose`, инвалидация |
| Modal | `GlassModal`, Mantine `Modal` | `opened` state, содержимое (форма/подтверждение), мутации |
| Menu | `Menu.Target` / `Menu.Dropdown` | Действия пунктов, открытие drawer/modal или навигация |
| Stepper | `Stepper.Step` | Имена шагов, условие пропуска шага (например мультиклиника), валидация перехода |
| Alert | критичные `Alert` | Условие показа (ошибка API, query-параметр) |
| Popover / picker | `EmojiMartPopoverPicker`, `Popover` | Назначение, влияние на сохранение |

Для каждой строки: **loading/error** обработаны или пометка **gap**.

## Версии паспорта

- **v1:** факт маршрута, компонент, основные хуки/API, скелет UI, **инвентарь поверхностей (ось H)** или явное «overlay нет», явные gap.
- **v2:** целевой премиум-слой (target), второй проход «Gap scan», связь с e2e/vitest.
