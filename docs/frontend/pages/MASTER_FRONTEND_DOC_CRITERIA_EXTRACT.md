## A. Документация репозитория (глобально)

Проверяемые входы фазы 3 мастер-плана фронта: [`RAG_CANON.md`](../../RAG_CANON.md), [`DOC_TOPOLOGY.md`](../../DOC_TOPOLOGY.md), [`DOCUMENTATION_POLICY.md`](../../../DOCUMENTATION_POLICY.md).

| ID | Критерий |
|----|----------|
| A1 | `docs/architecture` и смежные корни отражают **текущий код**; логическая цепочка «общая → деталь»; пригодность для RAG и чтения человеком. |
| A2 | Нет дублирующих/противоречивых описаний; слабые места усилены схемами и точными ссылками на пути в репозитории. |
| A3 | Единое место для канона фронта/дизайна; нет рассыпанного «фронт в трёх папках» без перекрёстных ссылок. |

## B. Паспорт экрана (per page) — пересечение с runbook v2

| ID | Критерий |
|----|----------|
| B1 | Логика UI, связь с **реально вызываемыми** API из хуков/клиента (не выдуманные маршруты). |
| B2 | As-built структура: layout, ключевые блоки, таблицы, модалки/drawer (ось H). |
| B3 | RBAC / entitlements / edition по коду. |
| B4 | Вторая редакция: gap scan, целевой UX vs as-built (документ, не обязательно реализация в коде). |
| B5 | Согласованность с единым стилем: ссылка на канон токенов/компонентов (`docs/design/`, `UI_THEME`, техпаспорт). |

## C. Продукт и код (вне узкого runbook паспортов)

| ID | Критерий |
|----|----------|
| C1 | Сверка **используемых** эндпоинтов UI с контрактом бэкенда; отсутствие «мертвых» кнопок и пустых селектов там, где должен быть выбор (**живой прогон**). |
| C2 | Точечные правки бэкенда/фронта, если обнаружен функциональный дефект (пример: пустой список врачей в Finance). |
| C3 | Копирайт: орфография, тон, отсутствие «следов ИИ» и внутренних меток разработки в пользовательском UI. |
| C4 | Визуальная целостность: кнопки, карточки, отступы — без «кустарности» (требует аудита UI в браузере или скрин-регрессии, не только .md). **Артефакт:** [`../PHASE_6_VISUAL_INTEGRITY_CHECKLIST.md`](../PHASE_6_VISUAL_INTEGRITY_CHECKLIST.md). |
| C5 | PWA/публичные сценарии (цены, врачи, связка админка → публичная витрина) — отдельный сквозной аудит. **Артефакт:** [`../PHASE_7_PWA_PUBLIC_SCENARIO_REPORT.md`](../PHASE_7_PWA_PUBLIC_SCENARIO_REPORT.md). |

## D. Приёмка «покупатель / техлид»

| ID | Критерий |
|----|----------|
| D1 | Нет логических дыр в ключевых сценариях; состояния loading/empty/error осмысленны. **Чеклист:** [`../PHASE_8_LEAD_ACCEPTANCE_CHECKLIST.md`](../PHASE_8_LEAD_ACCEPTANCE_CHECKLIST.md) §D1. |
| D2 | Безопасность периметра и данных — по регламентам проекта (не заменяется паспортом страницы). **Чеклист:** тот же файл §D2. |
| D3 | Несколько **итераций** рубрики Enterprise SaaS (макро/микро), сужение gap со временем. **Чеклист:** тот же файл §D3 + [`../architecture/ENTERPRISE_SAAS_FRONTEND_RUBRIC_AND_ITERATIONS.md`](../architecture/ENTERPRISE_SAAS_FRONTEND_RUBRIC_AND_ITERATIONS.md) §7. |
