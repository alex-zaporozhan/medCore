# Автоматизация паспортов страниц (SPA)

## Зачем это нужно

Паспорта в `docs/frontend/pages/*.md` должны оставаться **согласованными с кодом** (`frontend/src`). Ручные скриншоты и копипаста не масштабируются на десятки экранов; при этом **полностью автоматический «скриншот всех 71 страниц»** в репозитории без отдельного контура (поднятый фронт, тестовые учётки, сиды БД, headless-браузер, обход авторизации) **не задаётся** этим документом как обязательный артефакт CI.

## Что уже автоматизировано

| Команда | Назначение |
|---------|------------|
| `python scripts/gen_frontend_page_passport_stubs.py verify` | Регресс-охранитель: у каждого статического маршрута из `routePaths.ts` / `App.tsx` есть файл паспорта. |
| `python scripts/gen_frontend_page_passport_stubs.py generate` | Создать **только отсутствующие** заглушки `.md`. |
| `python scripts/enrich_page_passport_manifest.py` | Вставить/обновить блок **`AUTO_MANIFEST`** в каждом паспорте: эвристики по исходникам страницы (+ один уровень импортов `@/...`), пути `/v1/...`, счётчики overlay-компонентов. |

Блок `AUTO_MANIFEST` помечен как **автоинвентарь**: он **не отменяет** ручной проход по [`pages/PAGE_PASSPORT_V2_AGENT_RUNBOOK.md`](./pages/PAGE_PASSPORT_V2_AGENT_RUNBOOK.md) и не заменяет секции «Evidence / QA».

## Ограничения статического анализа

- Не следует за динамическими `import()`, не разбирает TSX через AST — возможны **пропуски и ложные срабатывания**.
- Импорты подтягиваются **один уровень** от корневого файла страницы (через `from "@/..."`).
- Скриншоты UI в PR **не генерируются** этим скриптом; для визуальной приёмки нужен отдельный e2e/Storybook/ручной прогон.

## Скриншоты (если понадобятся позже)

Реалистичный pipeline: Playwright (или аналог) + `npm run dev` + фикстурный логин + сохранение PNG в артефакт CI или в `docs/product_state/generated/` **только** после согласования секретов и политики git-lfs. До появления такого контура источником правды для маршрутов остаётся код, а для текста паспорта — runbook v2 + при необходимости блок `AUTO_MANIFEST`.
