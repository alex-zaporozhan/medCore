# Политика продуктовых текстов (русский интерфейс)

> **Версия:** 2026-04-08  
> **Аудитория:** авторы UI-копирайта, разработчики строк в `frontend/src/`, ревьюеры PR.

## Цель

Тексты в приложении должны восприниматься как **готовый коммерческий продукт**: уважительно, ясно, без следов внутренней переписки или черновиков ИИ.

## Обязательные принципы

1. **Грамотность** — орфография и пунктуация по нормам русского языка; единые термины (не смешивать «запись» и «бронь» в одном экране без причины).
2. **Официально-деловой тон** — на «Вы» в пользовательских подсказках и сообщениях об ошибках (где уместно по контексту продукта); избегать фамильярности.
3. **Объяснение без шума** — одна короткая строка-подсказка там, где действие неочевидно (аналитика, воронка, канбан, лиды). Без полотен текста и без дублирования заголовка.
4. **Имена в духе зрелых SaaS** — «Сохранить», «Отмена», «Фильтр», «Экспорт», «Подключить», «Архивировать»; не выдумывать нестандартные синонимы для стандартных действий.
5. **Запрещённые маркеры «черновика»** — не использовать во фронте формулировки вроде:
   - «по-человечески», «как для человека», «объяснение для пользователя»;
   - отсылки к «разработчику», «ИИ», «промпту», «MVP», «заглушка» в пользовательском тексте;
   - внутренние коды задач и аббревиатуры процесса (`QA_ARCH`, имена веток) в подсказках для конечного пользователя.

## Микрокопирайт по зонам

| Зона | Норма |
|------|--------|
| Ошибки API | Коротко: что не удалось и что сделать дальше; при необходимости «Повторите позже» / «Обратитесь к администратору». |
| Пустые списки | Заголовок пустого состояния + одна строка «что сделать» (добавить данные, изменить фильтр). |
| Аналитика | Подпись к оси или периоду на языке бизнеса («Выручка за период»), не «данные за range». |
